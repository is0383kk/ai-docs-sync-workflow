`/btw`（别名 `/side`）用于提出一个关于**当前会话**的简短附带问题，而不会将其添加到对话历史中。它以 Claude Code 的 `/btw` 为原型，并针对 OpenClaw 的 Gateway 网关和多渠道架构进行了适配。

```text
/btw 有什么变化？
/side 这个错误是什么意思？
```

## 功能

1. 将当前会话快照用作背景上下文（包括任何正在进行的主运行提示）。
2. 运行一次独立的单次附带查询，要求模型仅回答附带问题，不要恢复或引导主任务。
3. 以实时附带结果的形式传递答案，而不是作为普通助手消息。
4. 绝不会将问题或答案写入会话历史或 `chat.history`。

如果主运行处于活动状态，它不会受到任何影响。

对于 Codex harness 会话，BTW 会将活动的 Codex app-server 线程派生为一个临时子线程，而不是单独调用提供商。这样可保持 Codex OAuth 以及原生工具和线程行为不变，并且派生线程会保留父线程当前的审批策略、沙箱和原生工具界面。派生线程会收到一个边界提示，告知模型边界之前的所有内容都是继承的参考上下文，而不是当前有效的指令，只有边界之后的消息才是实时消息。`/btw` 需要已有的 Codex 线程；请先发送一条普通消息。

对于 CLI 运行时别名，BTW 会以单次附带问题模式调用其所属的 CLI 后端：它会将经过净化的对话上下文植入一次全新的 CLI 调用，同时禁用工具捆绑和可复用会话状态，并添加后端支持的任何禁止恢复或禁止使用工具的标志。直接（非 CLI）运行时则改为直接执行一次单次提供商调用。

## 不会执行的操作

`/btw` 不会创建持久会话、继续未完成的主任务、将问题或答案数据持久化到对话记录历史，也无法在重新加载后保留。

## 传递模型

普通助手聊天使用 Gateway 网关的 `chat` 事件。BTW 使用独立的 `chat.side_result` 事件，因此客户端不会将其误认为常规对话历史。由于它不会从 `chat.history` 重放，因此会在重新加载后消失。

## 界面行为

| 界面              | 行为                                                                                                                                                                                                                                                                               |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TUI               | 在聊天日志中内联呈现，与普通回复有明显区别，可使用 `Enter` 或 `Esc` 将其关闭。                                                                                                                                                                               |
| 外部渠道          | 作为带有明确标签的一次性回复传递（Telegram、WhatsApp、Discord 没有本地临时浮层）。                                                                                                                                                                                                  |
| Control UI / Web  | 呈现为固定在线程上的浮动“附带聊天”面板。答案会逐轮累积，“继续提问”输入框用于提出下一个附带问题。关闭（`Esc` 或 X）会保留对话，并在收到下一个答案时重新打开；垃圾桶按钮会将其丢弃并停止待处理的运行。 |

## 选择弹窗（Control UI）

在 Control UI 的聊天消息中高亮文本时，会打开一个包含两个操作的小型选择弹窗：

- **更多详情**会立即发送一个隐式 `/btw` 问题，要求模型结合当前会话的上下文解释高亮文本。答案会显示在浮动的附带聊天面板中。
- **在附带聊天中提问**会在输入框中预填一个引用高亮文本的 `/btw` 草稿，以便你输入自己的相关问题。

这两个操作都遵循普通的 `/btw` 语义：问题和答案不会进入会话历史，主运行也不会受到影响。

## 使用场景

使用 `/btw` 可快速请求澄清、在长时间运行仍在进行时获取事实性附带答案，或获得不应进入未来会话上下文的临时答案。

```text
/btw 我们正在编辑哪个文件？
/btw 用一句话概括当前任务
/btw 17 * 19 等于多少？
```

对于任何需要成为会话未来工作上下文一部分的内容，请改为在主会话中正常提问。
