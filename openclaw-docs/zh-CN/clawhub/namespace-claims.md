# 组织和命名空间认领

ClawHub 使用所有者句柄、组织句柄、技能短名、插件包名称和
包作用域作为公共命名空间。如果某个命名空间看起来属于
现实中的项目、品牌、包生态系统或组织，但在 ClawHub 上已被
认领、保留、冒用或存在争议，请通过
[组织/命名空间认领议题表单](https://github.com/openclaw/clawhub/issues/new?template=org-namespace-claim.yml)
请求工作人员审查。

此途径用于公开、非敏感的所有权审查。请勿使用产品内
举报或账户申诉表单提出命名空间认领。

## 何时提出认领

如果你认为 ClawHub 工作人员应根据现实中的所有权，审查是否应
保留、转让、重命名、隐藏、隔离某个命名空间，或为其添加别名
或以其他方式进行更改，请提出命名空间认领。

示例包括：

- 与你的 GitHub 组织、项目、公司或社区相匹配的组织句柄
- 类似 `@example-org/*` 的包作用域，该作用域应仅由
  匹配的 ClawHub 所有者发布
- 看起来在冒充某个项目的技能短名或插件包名称
- 涉及品牌、商标、项目重命名或包历史的争议
- 已删除、不活跃或无法联系的所有者，阻碍了正当的命名空间
  所有者

如果相关条目除了所有权争议外还存在不安全、恶意或误导性问题，
还应遵循相关的审核或安全指南。命名空间认领表单用于所有权审查，
而非紧急漏洞披露。

## 提交之前

首先确认你正使用与命名空间相匹配的所有者进行发布。
对于插件包，类似 `@example-org/example-plugin` 的作用域名称必须以
匹配的 `example-org` 所有者身份发布。

如果你可以管理当前所有者，请通过发布、重命名、转让、隐藏或
删除受影响的资源，直接修复命名空间。当你无法管理当前所有者，
或需要工作人员解决争议时，再提出认领。

## 应包含的证据

请使用公开、非敏感的证据。有用的证明包括：

- GitHub 组织、仓库、发布或维护者历史记录
- 明确提及该命名空间的官方项目文档
- 域名或官方电子邮件域名证明
- 对 npm、PyPI、crates.io 或其他包注册表作用域的控制权
- 可公开讨论的商标、品牌或项目所有权证据
- 源代码仓库历史、包历史或公开的重命名通知
- 存在争议的 ClawHub 所有者、技能、插件、包或议题的链接

请说明每个链接可以证明什么。工作人员应能在不需要私密凭据或
密钥的情况下理解其中的关系。

## 不应包含的内容

请勿在公开的 GitHub 议题中提供密钥或非公开证明。请勿包含：

- API 令牌、签名密钥或凭据
- DNS 质询令牌
- 非公开的法律文件或合同
- 个人身份证明文件
- 非公开电子邮件、非公开安全报告或机密客户数据

认领表单会询问敏感证据是否需要通过工作人员的私密渠道提供。
请使用该选项，而不要公开发布敏感材料。

## 可能的处理结果

根据证据和风险，ClawHub 工作人员可能会保留命名空间、
转让所有权、重命名资源、隐藏或隔离现有条目、添加别名或重定向、
要求提供更多证明，或拒绝请求。

命名空间审查并不保证所有匹配的名称都会被转让。
工作人员会权衡公开证据、现有使用情况、安全风险和用户影响。
