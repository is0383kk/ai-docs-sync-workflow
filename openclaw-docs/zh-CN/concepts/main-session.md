OpenClaw 首先是一个个人智能体。开箱即用时，你发送给它的每条私信——无论来自 Telegram、WhatsApp、iMessage、Slack 私信、Web 应用还是任何其他地方——都会进入**同一个滚动对话**：主会话。你可以在手机上提出问题，再用笔记本电脑继续追问，智能体在两处都拥有相同的上下文。它只有一个大脑，而这里就是它思考的地方。

在底层，主会话是一个键为
`agent:<agentId>:main`（例如 `agent:main:main`）的普通会话。它的特殊之处
在于，默认私信作用域会将所有私信归并到该会话中，而系统的其他部分
会将其视为智能体的根会话：Heartbeat 会唤醒它，后台工作会向它报告结果，
其他地方的活动也会汇集到这里。

## 主页

在 Web 应用中，主会话就是**主页**页面——侧边栏中的第一项。顶部的身份行代表你的智能体（点击可打开智能体菜单）；主页是你与它交谈的地方。从主对话分叉出的会话显示在**话题串**下，群聊显示在**群组**下，编码/CLI 会话显示在**编码**下。

## 汇入主会话的内容

主会话不只是一份聊天记录；它是智能体所处世界的汇聚之处：

- **群组活动。** 群组和房间会话会保持隔离（见下文），但在默认私信作用域下，主会话会自动关注它们。活动会以紧凑通知的形式排队——按对话合并，绝不会每条消息都唤醒一次——智能体会在下次运行时看到这些通知：可能是在你发送下一条消息时，也可能是在计划的 Heartbeat 触发时。智能体还可以读取它所关注的会话，因此可以回答“家庭群里有什么我错过的消息？”。
- **后台工作。** 子智能体和派生会话会将结果报告回启动它们的会话，因此智能体从主页发起的工作会将结果报告回主页。
- **Heartbeat。** 计划的 Heartbeat 以主会话为目标，即使你尚未发送任何内容，也能让智能体感知排队的通知。

## 重置和跨对话记忆

滚动对话受模型上下文窗口的限制，因此连续性来自其周围的多个层次：

- `MEMORY.md` 是智能体精心整理的长期记忆，会加载到每个新会话中。每日笔记（`memory/YYYY-MM-DD.md`）可按需搜索，最近的笔记会在 `/new` 或 `/reset` 后重新注入上下文。在压缩前，智能体会将持久性事实写入每日笔记，因此长对话不会悄无声息地丢失这些事实。
- **跨对话记忆回忆**允许智能体回忆其其他私有会话中的内容。在个人设置中——全局 `session.dmScope` 解析为 `main`，且没有按绑定配置的私信覆盖——该功能默认启用；配置任何私信隔离都会将其关闭，除非你明确选择启用。请参阅[记忆配置](/zh-CN/reference/memory-config)。

## 具有持久历史记录的滚动会话

主会话通过重置和压缩持续向前滚动，而不是让模型一次性携带其全部历史记录：

- 默认情况下不会自动重置；压缩会在保留滚动会话的同时限制活动上下文的大小。每日重置和空闲重置均为可选功能（请参阅[会话管理](/zh-CN/concepts/session)）。执行 `/new` 和 `/reset` 时，即将结束的对话尾部会保存到每日记忆笔记中，下一个会话则会重新注入最近的笔记。重置会分配新的实时会话 ID，但仍可通过同一主会话键搜索此前的 SQLite 对话记录。
- 当对话接近上下文窗口上限时，压缩会进行总结并在原会话中继续——对话记录历史仍保留在会话存储中。
- 会话列表显示当前的实时对话，而不会显示其背后的每个历史会话 ID。
- 当每个智能体存储的物理数据库、WAL 和会话工件超过磁盘预算（默认 10 GB）时，OpenClaw 会先将最早且未被引用的历史记录提取到经过验证的压缩归档中，然后再删除相应的数据库行。实时、已路由和进行中的会话绝不会因磁盘预算而被清除。

## 需要隔离时

对于只有你与之交谈的智能体，共享主会话是合适的默认设置。如果有多人可以向你的智能体发送消息，请隔离私信：

```json5
{
  session: {
    dmScope: "per-channel-peer",
  },
}
```

使用隔离作用域后，每个发送者都会获得自己的会话，主会话的群组关注功能会被禁用，跨对话记忆回忆也默认关闭。`openclaw security audit` 在检测到多个私信发送者时会建议启用隔离。完整的作用域矩阵、身份关联和按路由覆盖设置，请参阅[会话管理](/zh-CN/concepts/session)和[频道路由](/zh-CN/channels/channel-routing)。
