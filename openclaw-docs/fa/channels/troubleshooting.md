هنگامی که یک کانال متصل می‌شود اما رفتارش نادرست است، از این صفحه استفاده کنید.

## ترتیب فرمان‌ها

ابتدا این فرمان‌ها را به‌ترتیب اجرا کنید:

```bash
openclaw status
openclaw gateway status
openclaw logs --follow
openclaw doctor
openclaw channels status --probe
```

خط مبنای سالم:

- `Runtime: running`
- `Connectivity probe: ok`
- `Capability: read-only`، `write-capable` یا `admin-capable`
- کاوش کانال نشان می‌دهد که انتقال متصل است و در موارد پشتیبانی‌شده، `works` یا `audit ok`

## پس از به‌روزرسانی

هنگامی که Telegram، iMessage، پیکربندی‌های دورهٔ BlueBubbles یا کانال Plugin دیگری پس از به‌روزرسانی ناپدید می‌شود، از این روش استفاده کنید.

```bash
openclaw status --all
openclaw doctor --fix
openclaw gateway restart
openclaw status --all
```

در `openclaw
status --all` به‌دنبال `plugin load failed: dependency tree corrupted; run openclaw doctor --fix` بگردید. این یعنی کانال پیکربندی شده است، اما راه‌اندازی یا بارگذاری Plugin به‌جای ثبت کانال با درخت وابستگی خراب مواجه شده است. `openclaw doctor --fix` پیوندهای نمادین منسوخ وابستگی‌های زمان اجرای Plugin و سایه‌های منسوخ احراز هویت را پاک می‌کند، سپس `openclaw gateway restart` وضعیت پاک را دوباره بارگذاری می‌کند.

| پاسخ‌ها با چند ثانیه/دقیقه تأخیر می‌رسند | `openclaw doctor --fix`                             | doctor کلاینت‌های محلی TUI منسوخ و تأییدشده را هنگامی که حلقهٔ رویداد Gateway را مختل می‌کنند، متوقف می‌کند.                                    |

| نظرسنجی متوقف می‌شود یا اتصال مجدد کند است  | `openclaw logs --follow` برای تشخیص نظرسنجی | ارتقا دهید؛ توقف‌های مداوم معمولاً به پراکسی/DNS/IPv6 اشاره دارند.                                                            |

| پس از ارتقا، فهرست مجاز شما را مسدود می‌کند    | `openclaw security audit` و فهرست‌های مجاز پیکربندی  | `openclaw doctor --fix` را اجرا کنید یا `@username` را با شناسه‌های عددی فرستنده جایگزین کنید.                                            |
