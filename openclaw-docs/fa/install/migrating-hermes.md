ارائه‌دهندهٔ مهاجرت Hermes که همراه برنامه ارائه می‌شود، از `HERMES_HOME` و پروفایل فعال Hermes پیروی می‌کند و در صورت نبود آن‌ها، در macOS/Linux به `~/.hermes` یا در Windows به `%LOCALAPPDATA%\hermes` برمی‌گردد. این ارائه‌دهنده پیش از اعمال، همهٔ تغییرات را پیش‌نمایش می‌کند و رازها را در طرح‌ها و گزارش‌ها می‌پوشاند. اجرای مستقل `openclaw migrate` یک نسخهٔ پشتیبان تأییدشده می‌نویسد؛ مسیر راه‌اندازی اولیهٔ تازه، پیکربندی، اعتبارنامه‌ها و فایل‌ها را مرحله‌بندی می‌کند و فقط پس از تأیید استنتاج واردشده، آن‌ها را منتشر می‌کند. مسیر صریح `--from` همیشه اولویت دارد.

<Note>
واردکردن به راه‌اندازی تازهٔ OpenClaw نیاز دارد. اگر از قبل وضعیت محلی OpenClaw دارید، ابتدا پیکربندی، اعتبارنامه‌ها، نشست‌ها و فضای کاری را بازنشانی کنید، یا پس از بازبینی طرح، مستقیماً از `openclaw migrate apply hermes` همراه با `--overwrite` استفاده کنید.
</Note>

## دو روش برای واردکردن

<Tabs>
  <Tab title="جادوگر راه‌اندازی اولیه">
    خانه/پروفایل فعال Hermes را شناسایی می‌کند و پیش از اعمال، پیش‌نمایشی نشان می‌دهد.

    ```bash
    openclaw onboard --flow import
    ```

    یا یک منبع مشخص را تعیین کنید:

    ```bash
    openclaw onboard --import-from hermes --import-source ~/.hermes
    ```

  </Tab>
  <Tab title="CLI">
    برای اجراهای اسکریپتی یا تکرارپذیر از `openclaw migrate` استفاده کنید. برای مرجع کامل، [`openclaw migrate`](/fa/cli/migrate) را ببینید.

    ```bash
    openclaw migrate hermes --dry-run    # فقط پیش‌نمایش
    openclaw migrate apply hermes --yes  # اعمال با ردکردن تأیید
    ```

    برای نادیده‌گرفتن شناسایی خانه/پروفایل Hermes، `--from <path>` را اضافه کنید.

  </Tab>
</Tabs>

## چه چیزهایی وارد می‌شوند

<AccordionGroup>
  <Accordion title="پیکربندی مدل">

    - ارائه‌دهندگان مدل پیکربندی‌شده و نقاط پایانی سفارشی از `model`، `providers` و `custom_providers`، شامل انتقال‌های کنونی Chat Completions، Codex Responses و Anthropic Messages در Hermes.

  </Accordion>
  <Accordion title="سرورهای MCP">

  </Accordion>
  <Accordion title="فایل‌های فضای کاری">

  </Accordion>
  <Accordion title="پیکربندی حافظه">

  </Accordion>

  </Accordion>
</AccordionGroup>

## چه چیزهایی فقط در بایگانی باقی می‌مانند

ارائه‌دهنده موارد زیر را برای بازبینی دستی در پوشهٔ گزارش مهاجرت کپی می‌کند، اما آن‌ها را در پیکربندی یا اعتبارنامه‌های فعال OpenClaw بارگذاری **نمی‌کند**:

- `plugins/`
- `sessions/`
- `logs/`
- `cron/`
- `mcp-tokens/`
- `plans/`، `workspace/`، `skins/` و `kanban/`
- ذخیره‌های `pairing/` و `platforms/`، به‌همراه وضعیت مسیریابی/فرایند Gateway
- `state.db`، `hermes_state.db`، `projects.db`، `response_store.db`، `memory_store.db`، `verification_evidence.db`، `kanban.db` و `retaindb_queue.db`

OpenClaw از اجرای خودکار یا اعتماد خودکار به این وضعیت خودداری می‌کند، زیرا قالب‌ها و فرض‌های اعتماد ممکن است میان سامانه‌ها تغییر کنند. پس از بازبینی بایگانی، موارد موردنیاز را به‌صورت دستی منتقل کنید.

## روند پیشنهادی

<Steps>
  <Step title="پیش‌نمایش طرح">
    ```bash
    openclaw migrate hermes --dry-run
    ```

    طرح همهٔ مواردی را که تغییر خواهند کرد، از جمله تعارض‌ها، موارد ردشده و موارد حساس، فهرست می‌کند. کلیدهای تودرتویی که شبیه راز هستند در خروجی پوشانده می‌شوند.

  </Step>
  <Step title="اعمال همراه با نسخهٔ پشتیبان">
    ```bash
    openclaw migrate apply hermes --yes
    ```

    OpenClaw پیش از اعمال، یک نسخهٔ پشتیبان ایجاد و تأیید می‌کند. این نمونهٔ غیرتعاملی فقط وضعیت غیرمحرمانه را وارد می‌کند. برای پاسخ تعاملی به پرسش اعتبارنامه، بدون `--yes` اجرا کنید، یا برای افزودن اعتبارنامه‌های پشتیبانی‌شده در اجرای بدون نظارت، `--include-secrets` را اضافه کنید.

  </Step>
  <Step title="اجرای Doctor">
    ```bash
    openclaw doctor
    ```

    [Doctor](/fa/gateway/doctor) همهٔ مهاجرت‌های معلق پیکربندی را دوباره اعمال می‌کند و مشکلات ایجادشده هنگام واردکردن را بررسی می‌کند.

  </Step>
  <Step title="راه‌اندازی مجدد و تأیید">
    ```bash
    openclaw gateway restart
    openclaw status
    ```

    تأیید کنید Gateway سالم است و مدل، حافظه و Skills واردشدهٔ شما بارگذاری شده‌اند.

  </Step>
</Steps>

## مدیریت تعارض

وقتی طرح تعارض‌هایی را گزارش می‌کند (یک فایل یا مقدار پیکربندی از قبل در مقصد وجود دارد)، عملیات اعمال از ادامه خودداری می‌کند.

<Warning>
فقط زمانی با `--overwrite` دوباره اجرا کنید که جایگزینی مقصد موجود عمدی باشد. ارائه‌دهندگان ممکن است همچنان برای فایل‌های بازنویسی‌شده در پوشهٔ گزارش مهاجرت نسخه‌های پشتیبان در سطح مورد بنویسند.
</Warning>

تعارض‌ها در نصب تازه نامعمول‌اند. معمولاً زمانی ظاهر می‌شوند که واردکردن را دوباره روی راه‌اندازی‌ای اجرا کنید که از قبل ویرایش‌های کاربر را دارد.

اگر در میانهٔ اعمال تعارضی رخ دهد (برای مثال، رقابت غیرمنتظره روی یک فایل پیکربندی)، آن مورد به‌عنوان تعارض گزارش می‌شود و فایل‌ها، Skills، اعتبارنامه‌ها، بایگانی‌ها و ورودی‌های پیکربندی مستقل به کار ادامه می‌دهند. مورد متعارض را رفع کنید و واردکردن را دوباره اجرا کنید؛ واردکردن حافظه‌های یکسان idempotent است.

## رازها

اجرای تعاملی `openclaw migrate` می‌پرسد آیا اعتبارنامه‌های احراز هویت شناسایی‌شده وارد شوند یا نه و گزینهٔ بله به‌طور پیش‌فرض انتخاب شده است.

- پذیرش، ورودی‌های فعلی OpenAI Codex OAuth در Hermes، ورودی‌های OpenAI OAuth و GitHub Copilot در OpenCode و [کلیدهای پشتیبانی‌شدهٔ `.env`](/fa/cli/migrate#supported-env-keys) را وارد می‌کند.
- برای واردکردن فقط وضعیت غیرمحرمانه، از `--no-auth-credentials` استفاده کنید یا در پرسش پاسخ منفی دهید.
- برای واردکردن اعتبارنامه‌ها در اجرای بدون نظارت `--yes`، از `--include-secrets` استفاده کنید.
- برای واردکردن اعتبارنامه‌ها از جادوگر، از پرچم `--import-secrets` جادوگر راه‌اندازی اولیه استفاده کنید.

## خروجی JSON برای خودکارسازی

```bash
openclaw migrate hermes --dry-run --json
openclaw migrate apply hermes --json --yes
```

با `--json` و بدون `--yes`، عملیات اعمال طرح را چاپ می‌کند و وضعیت را تغییر نمی‌دهد — امن‌ترین حالت برای CI و اسکریپت‌های مشترک.
