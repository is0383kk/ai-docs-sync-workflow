`llm-task` یک **ابزار اختیاری Plugin** همراه است که یک فراخوانی منفرد LLM صرفاً با خروجی JSON اجرا می‌کند و خروجی ساخت‌یافته برمی‌گرداند که در صورت تمایل، در برابر یک JSON Schema اعتبارسنجی می‌شود. این ابزار، بدون نیاز به کد سفارشی OpenClaw برای هر گردش‌کار، یک مرحله LLM در اختیار موتورهای گردش‌کاری مانند Lobster قرار می‌دهد.

## فعال‌سازی

1. Plugin را فعال کنید:

```json
{
  "plugins": {
    "entries": {
      "llm-task": { "enabled": true }
    }
  }
}
```

2. ابزار را مجاز کنید:

```json
{
  "tools": {
    "alsoAllow": ["llm-task"]
  }
}
```

`alsoAllow`، `llm-task` را بدون محدودکردن سایر ابزارهای اصلی به نمایه ابزار فعال اضافه می‌کند. تنها در صورتی به‌جای آن از `tools.allow` استفاده کنید که حالت فهرست مجاز محدودکننده می‌خواهید.

## پیکربندی (اختیاری)

```json
{
  "plugins": {
    "entries": {
      "llm-task": {
        "enabled": true,
        "config": {
          "defaultProvider": "openai",
          "defaultModel": "gpt-5.6-sol",
          "defaultAuthProfileId": "main",
          "allowedModels": ["openai/gpt-5.6-sol"],
          "maxTokens": 800,
          "timeoutMs": 30000
        }
      }
    }
  }
}
```

`allowedModels` فهرست مجازی از رشته‌های `provider/model` است؛ درخواست هر مدل دیگری رد می‌شود. همه کلیدهای دیگر، مقادیر جایگزین هر فراخوانی هستند که وقتی فراخوانی ابزار آن پارامتر را حذف کند، استفاده می‌شوند.

## پارامترهای ابزار

| پارامتر       | نوع   | توضیحات                                                                                                                                         |
| --------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`        | رشته | الزامی. دستورالعمل وظیفه برای LLM.                                                                                                       |
| `input`         | هر نوع    | بار داده اختیاری؛ به JSON سریال‌سازی و به پرامپت افزوده می‌شود.                                                                              |
| `schema`        | شیء | JSON Schema اختیاری که خروجی تجزیه‌شده باید در برابر آن اعتبارسنجی شود.                                                                                 |
| `provider`      | رشته | `defaultProvider` / ارائه‌دهنده پیش‌فرض عامل را بازنویسی می‌کند.                                                                                   |
| `model`         | رشته | `defaultModel` را بازنویسی می‌کند؛ شناسه‌های خام مدل، نام‌های مستعار یا ارجاع `provider/model` را می‌پذیرد (پیشوند تکراری ارائه‌دهنده به‌طور خودکار حذف می‌شود). |
| `thinking`      | رشته | سطح استدلال (برای مثال `low`، `medium`)؛ باید یکی از سطوح پشتیبانی‌شده توسط مدل حل‌شده باشد.                                                          |
| `authProfileId` | رشته | `defaultAuthProfileId` را بازنویسی می‌کند.                                                                                                             |
| `temperature`   | عدد | در حد توان؛ همه ارائه‌دهندگان آن را رعایت نمی‌کنند.                                                                                                      |
| `maxTokens`     | عدد | سقف در حد توان برای توکن‌های خروجی.                                                                                                             |
| `timeoutMs`     | عدد | مهلت اجرای عملیات؛ مقدار پیش‌فرض `30000`.                                                                                                                 |

## خروجی

`details.json` (JSON تجزیه‌شده و اعتبارسنجی‌شده در برابر طرح‌واره) را همراه با `details.provider`
و `details.model` برمی‌گرداند که مشخص می‌کنند در عمل چه چیزی اجرا شده است.

## نمونه: مرحله گردش‌کار Lobster

### محدودیت مهم

نمونه زیر فرض می‌کند **CLI مستقل Lobster** در محیطی اجرا می‌شود که
`openclaw.invoke` از قبل URL و زمینه احراز هویت صحیح Gateway را دارد.

برای اجراکننده Lobster **تعبیه‌شده** همراه در OpenClaw، این الگوی CLI تو‌در‌تو
**در حال حاضر قابل‌اعتماد نیست**:

```lobster
openclaw.invoke --tool llm-task --action json --args-json '{ ... }'
```

تا زمانی که Lobster تعبیه‌شده پلی پشتیبانی‌شده برای این جریان داشته باشد، یکی از این موارد را ترجیح دهید:

- فراخوانی‌های مستقیم ابزار `llm-task` خارج از Lobster، یا
- مراحل Lobster که به فراخوانی‌های تو‌در‌توی `openclaw.invoke` وابسته نیستند.

نمونه CLI مستقل Lobster:

```lobster
openclaw.invoke --tool llm-task --action json --args-json '{
  "prompt": "با توجه به ایمیل ورودی، هدف و پیش‌نویس را برگردان.",
  "thinking": "low",
  "input": {
    "subject": "سلام",
    "body": "می‌توانید کمک کنید؟"
  },
  "schema": {
    "type": "object",
    "properties": {
      "intent": { "type": "string" },
      "draft": { "type": "string" }
    },
    "required": ["intent", "draft"],
    "additionalProperties": false
  }
}'
```

## نکات ایمنی

- **فقط JSON**: به مدل دستور داده می‌شود فقط یک مقدار JSON، بدون حصار کد و بدون توضیح، برگرداند.
- **بدون ابزار**: ابزارها در اجرای زیربنایی غیرفعال‌اند، بنابراین مدل نمی‌تواند در میانه وظیفه فراخوانی خارجی انجام دهد.
- خروجی را نامطمئن در نظر بگیرید، مگر اینکه آن را با `schema` اعتبارسنجی کنید.
- تأییدها را پیش از هر مرحله دارای اثر جانبی (ارسال، انتشار، اجرا) که این خروجی را مصرف می‌کند، قرار دهید.
