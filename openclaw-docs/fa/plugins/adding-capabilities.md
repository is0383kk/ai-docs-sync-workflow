<Info>
  این یک **راهنمای مشارکت‌کنندگان** برای توسعه‌دهندگان هستهٔ OpenClaw است. اگر در حال
  ساخت یک Plugin خارجی هستید، به‌جای این صفحه [ساخت Pluginها](/fa/plugins/building-plugins)
  را ببینید. برای مرجع عمیق معماری (مدل قابلیت، مالکیت،
  پایپ‌لاین بارگذاری، کمک‌کننده‌های زمان اجرا)، [جزئیات داخلی Plugin](/fa/plugins/architecture) را ببینید.
</Info>

هنگامی از این الگو استفاده کنید که OpenClaw به یک دامنهٔ مشترک جدید، مانند تعبیه‌ها، تولید
تصویر، تولید ویدئو یا حوزه‌ای برای قابلیت‌های آینده با پشتیبانی فروشندگان نیاز دارد.

قاعده:

- **Plugin** = مرز مالکیت
- **قابلیت** = قرارداد مشترک هسته

یک فروشنده را مستقیماً به کانال یا ابزار متصل نکنید. ابتدا قابلیت را تعریف کنید.

## چه زمانی یک قابلیت ایجاد شود

فقط زمانی یک قابلیت جدید ایجاد کنید که **همهٔ** موارد زیر برقرار باشند:

1. بیش از یک فروشنده بتواند به‌طور معقول آن را پیاده‌سازی کند.
2. کانال‌ها، ابزارها یا Pluginهای قابلیت باید بدون اهمیت‌دادن به فروشنده از آن استفاده کنند.
3. هسته باید مالک رفتار جایگزینی، خط‌مشی، پیکربندی یا تحویل باشد.

اگر کار فقط مختص یک فروشنده است و هنوز قرارداد مشترکی وجود ندارد، ابتدا قرارداد را تعریف کنید.

## توالی استاندارد

1. قرارداد نوع‌دار هسته را تعریف کنید.
2. ثبت Plugin را برای آن قرارداد اضافه کنید.
3. یک کمک‌کنندهٔ مشترک زمان اجرا اضافه کنید.
4. یک Plugin واقعی فروشنده را به‌عنوان اثبات متصل کنید.
5. مصرف‌کنندگان قابلیت/کانال را به کمک‌کنندهٔ زمان اجرا منتقل کنید.
6. آزمون‌های قرارداد را اضافه کنید.
7. پیکربندی قابل‌مشاهده برای اپراتور و مدل مالکیت را مستند کنید.

## هر بخش متعلق به کجاست

| لایه                      | مالک                                                                                                                                                                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **هسته**                   | نوع‌های درخواست/پاسخ؛ رجیستری ارائه‌دهنده و تفکیک آن؛ رفتار جایگزینی؛ طرح‌وارهٔ پیکربندی با فرادادهٔ مستندات `title`/`description` که در گره‌های شیء تو‌در‌تو، نویسهٔ عام، عضو آرایه و ترکیب انتشار می‌یابد؛ سطح کمک‌کنندهٔ زمان اجرا. |
| **Plugin فروشنده**          | فراخوانی‌های API فروشنده، مدیریت احراز هویت فروشنده، نرمال‌سازی درخواست مختص فروشنده و ثبت پیاده‌سازی قابلیت.                                                                                                     |
| **Plugin قابلیت/کانال** | `api.runtime.*` یا کمک‌کنندهٔ متناظر `plugin-sdk/*-runtime` را فراخوانی می‌کند. هرگز پیاده‌سازی فروشنده را مستقیماً فراخوانی نمی‌کند.                                                                                                                    |

## درزهای ارائه‌دهنده و چارچوب اجرا

هنگامی از **قلاب‌های ارائه‌دهنده** استفاده کنید که رفتار به قرارداد ارائه‌دهندهٔ مدل تعلق دارد، نه حلقهٔ عمومی عامل. نمونه‌ها شامل پارامترهای درخواست مختص ارائه‌دهنده پس از انتخاب انتقال، ترجیح نمایهٔ احراز هویت، لایه‌های افزودهٔ پرامپت و مسیریابی جایگزین پیگیری پس از جایگزینی مدل/نمایه هستند.

هنگامی از **قلاب‌های چارچوب اجرای عامل** استفاده کنید که رفتار به زمان اجرایی تعلق دارد که یک نوبت را اجرا می‌کند. چارچوب‌های اجرا می‌توانند نتایج صریح پروتکل، مانند خروجی خالی، استدلال بدون خروجی قابل‌مشاهده یا یک برنامهٔ ساختاریافته بدون پاسخ نهایی را طبقه‌بندی کنند تا خط‌مشی جایگزینی مدل بیرونی بتواند دربارهٔ تلاش مجدد تصمیم بگیرد.

هر دو درز را محدود نگه دارید:

- هسته مالک خط‌مشی تلاش مجدد/جایگزینی است.
- Pluginهای ارائه‌دهنده مالک راهنمایی‌های مختص ارائه‌دهنده برای درخواست/احراز هویت/مسیریابی هستند.
- Pluginهای چارچوب اجرا مالک طبقه‌بندی تلاش مختص زمان اجرا هستند.
- Pluginهای شخص ثالث به‌جای تغییر مستقیم وضعیت هسته، راهنمایی بازمی‌گردانند.

## فهرست بررسی فایل‌ها

برای یک قابلیت جدید، انتظار می‌رود این بخش‌ها تغییر کنند:

- `src/<capability>/types.ts`
- `src/<capability>/...registry/runtime.ts`
- `src/plugins/types.ts`
- `src/plugins/registry.ts`
- `src/plugins/captured-registration.ts`
- `src/plugins/contracts/registry.ts`
- `src/plugins/runtime/types-core.ts`
- `src/plugins/runtime/index.ts`
- `src/plugin-sdk/<capability>.ts`
- `src/plugin-sdk/<capability>-runtime.ts`
- یک یا چند بستهٔ Plugin همراه.
- پیکربندی، مستندات، آزمون‌ها.

## نمونهٔ عملی: تولید تصویر

تولید تصویر از ساختار استاندارد پیروی می‌کند:

1. هسته `ImageGenerationProvider` را تعریف می‌کند.
2. هسته `registerImageGenerationProvider(...)` را ارائه می‌کند.
3. هسته `api.runtime.imageGeneration.generate(...)` و `.listProviders(...)` را ارائه می‌کند.
4. Pluginهای فروشنده (`comfy`، `deepinfra`، `fal`، `google`، `litellm`، `microsoft-foundry`، `minimax`، `openai`، `openrouter`، `vydra`، `xai`) پیاده‌سازی‌های با پشتیبانی فروشنده را ثبت می‌کنند.
5. فروشندگان آینده همان قرارداد را بدون تغییر کانال‌ها/ابزارها ثبت می‌کنند.

کلید پیکربندی عمداً از مسیریابی تحلیل بینایی جدا است:

- `agents.defaults.imageModel` تصاویر را تحلیل می‌کند.
- `agents.defaults.mediaModels.image` تصاویر را تولید می‌کند.

این موارد را جدا نگه دارید تا جایگزینی و خط‌مشی صریح باقی بمانند.

## ارائه‌دهندگان تعبیه

برای ارائه‌دهندگان قابل‌استفادهٔ مجدد تعبیهٔ برداری، از `registerEmbeddingProvider(...)` / قرارداد `embeddingProviders`
استفاده کنید. این قرارداد عمداً گسترده‌تر
از حافظه است: ابزارها، جست‌وجو، بازیابی، واردکننده‌ها یا Pluginهای قابلیت آینده
می‌توانند بدون وابستگی به موتور حافظه، تعبیه‌ها را مصرف کنند. جست‌وجوی حافظه
نیز `embeddingProviders` عمومی را مصرف می‌کند.

API قدیمی ثبت مختص حافظه و قرارداد `memoryEmbeddingProviders`
منسوخ شده‌اند. برای همهٔ ارائه‌دهندگان جدید تعبیه، از `registerEmbeddingProvider` و
`embeddingProviders` استفاده کنید.

## فهرست بررسی بازبینی

پیش از انتشار یک قابلیت جدید، بررسی کنید:

- هیچ کانال/ابزاری کد فروشنده را مستقیماً وارد نمی‌کند.
- کمک‌کنندهٔ زمان اجرا مسیر مشترک است.
- حداقل یک آزمون قرارداد، مالکیت همراه را بررسی می‌کند.
- مستندات پیکربندی، مدل/کلید پیکربندی جدید را نام می‌برند.
- مستندات Plugin مرز مالکیت را توضیح می‌دهند.

اگر یک PR از لایهٔ قابلیت عبور کند و رفتار فروشنده را در یک کانال/ابزار کدنویسی ثابت کند، آن را بازگردانید و ابتدا قرارداد را تعریف کنید.
