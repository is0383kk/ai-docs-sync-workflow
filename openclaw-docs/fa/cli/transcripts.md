# `openclaw transcripts`

فرمان بازرسی و برون‌بری برای رونوشت‌های ماندگار جلسه. شرکت‌کنندگان مرورگری Google Meet،
Microsoft Teams و Zoom یادداشت‌ها را به‌طور خودکار ثبت می‌کنند؛
ابزار عامل `transcripts` نیز از ثبت توسط ارائه‌دهنده و درون‌ریزی دستی پشتیبانی می‌کند.

وضعیت مرجع رونوشت در پایگاه داده مشترک SQLite در
`$OPENCLAW_STATE_DIR/state/openclaw.sqlite` نگهداری می‌شود. `show` و `path` به‌صراحت
مصنوعات قابل‌مشاهده برای کاربر را در پوشه وضعیت ایجاد می‌کنند:

```text
$OPENCLAW_STATE_DIR/transcripts/YYYY-MM-DD/<session>/
  metadata.json
  transcript.jsonl
  summary.json
  summary.md
```

این فایل‌ها برون‌بری هستند، نه یک مخزن زمان‌اجرای دوم. OpenClaw هنگام ثبت،
خلاصه‌سازی یا فهرست‌کردن، آن‌ها را دوباره نمی‌خواند. پوشه وضعیت پیش‌فرض
`~/.openclaw` است؛ با `OPENCLAW_STATE_DIR` آن را بازنویسی کنید. پوشه تاریخ از
زمان شروع نشست گرفته می‌شود؛ پوشه نشست یک نامک امن برای سیستم فایل است که
از شناسه نشست ساخته می‌شود.

## فرمان‌ها

```bash
openclaw transcripts list
openclaw transcripts show <session>
openclaw transcripts show YYYY-MM-DD/<session>
openclaw transcripts path <session>
openclaw transcripts path YYYY-MM-DD/<session>
openclaw transcripts path <session> --dir
openclaw transcripts path <session> --metadata
openclaw transcripts path <session> --transcript
openclaw transcripts list --json
openclaw transcripts show <session> --json
openclaw transcripts path <session> --json
```

| فرمان                       | توضیحات                                          |
| ----------------------------- | ---------------------------------------------------- |
| `list`                        | نشست‌های ذخیره‌شده را فهرست می‌کند.                                |
| `show <session>`              | `summary.md` را چاپ و ایجاد می‌کند.                  |
| `path <session>`              | مسیر `summary.md` را ایجاد و چاپ می‌کند.         |
| `path <session> --dir`        | همه مصنوعات را ایجاد و پوشه آن‌ها را چاپ می‌کند. |
| `path <session> --metadata`   | `metadata.json` را ایجاد و چاپ می‌کند.               |
| `path <session> --transcript` | `transcript.jsonl` را ایجاد و چاپ می‌کند.            |
| `--json`                      | خروجی ماشین‌خوان را چاپ می‌کند (برای هر زیرفرمان).      |

`<session>` یک شناسه نشست ساده یا گزینشگر دارای تاریخ
(`YYYY-MM-DD/<session>`) را می‌پذیرد. وقتی یک شناسه نشست در بیش از یک روز
وجود دارد، از شکل دارای تاریخ استفاده کنید؛ برای مثال `openclaw transcripts show
2026-05-22/standup`. شناسه‌های پیش‌فرض نشست شامل مُهر زمانی و پسوندی
تصادفی هستند؛ تنها زمانی شناسه ثابتی به نشست بدهید که آن شناسه در همان روز یکتا باشد.

## خروجی

`list` برای هر نشست یک خط جداشده با تب چاپ می‌کند: گزینشگر، زمان شروع، عنوان،
مسیر خلاصه.

```text
2026-05-22/standup  2026-05-22T09:00:00.000Z  جلسه هماهنگی هفتگی  /Users/user/.openclaw/transcripts/2026-05-22/standup/summary.md
```

گزینشگر امن‌ترین مقداری است که می‌توان دوباره به `show` یا `path` داد.

`list --json` اشیایی با `sessionId`، `selector`، `date`، `title`،
`startedAt`، `stoppedAt`، `source`، `path`، `summaryPath` و `hasSummary` برمی‌گرداند.
نشانی‌های URL منبع جلسه ذخیره‌شده فقط شامل مبدأ و مسیر هستند؛ رشته‌های پرس‌وجو،
قطعه‌ها و اطلاعات احراز هویت تعبیه‌شده پیش از ماندگارشدن حذف می‌شوند.

`show --json` فراداده ذخیره‌شده نشست، گزینشگر، پوشه نشست،
مسیر خلاصه و متن Markdown خلاصه را برمی‌گرداند.

`path --json` مسیر انتخاب‌شده و اینکه آیا آن مصنوع قابل ایجاد بوده است یا نه را
برمی‌گرداند. برون‌بری‌های فراداده و رونوشت همیشه برای نشست ذخیره‌شده وجود دارند؛
مسیر خلاصه تا زمانی که نشست خلاصه‌ای داشته باشد، `exists: false` را گزارش می‌کند.

## چندین نشست در هر روز

نشست‌ها ابتدا بر اساس تاریخ و سپس شناسه نشست گروه‌بندی می‌شوند. ده جلسه در یک روز به
ده پوشه هم‌سطح تبدیل می‌شوند:

```text
~/.openclaw/transcripts/2026-05-22/
  transcript-2026-05-22T09-00-00-000Z-a1b2c3d4/
  transcript-2026-05-22T10-30-00-000Z-b2c3d4e5/
  standup/
```

برای خودکارسازی از شناسه‌های پیش‌فرض تولیدشده استفاده کنید. تنها زمانی از شناسه ثابتی مانند `standup` استفاده کنید
که در همان تاریخ تکرار نشود.

## خلاصه‌های مفقود

نشست‌های زنده هنگام توقف نشست، `summary.md` را ذخیره و ایجاد می‌کنند؛
رونوشت‌های درون‌ریزی‌شده نیز بلافاصله پس از درون‌ریزی همین کار را انجام می‌دهند. ممکن است یک نشست بدون خلاصه در
`list` ظاهر شود، اگر ثبت همچنان فعال باشد، ارائه‌دهنده‌ای هنگام توقف
ناموفق شده باشد، یا فراداده پیش از رسیدن هرگونه گفتار ذخیره شده باشد.

برای بازرسی رونوشت خام و فقط‌افزودنی از `path <session> --transcript` استفاده کنید،
یا کنش `summarize` ابزار `transcripts` را اجرا کنید تا خلاصه Markdown
دوباره تولید شود.

## ارتقای مخزن فایل قدیمی

نسخه‌های OpenClaw پیش از مخزن SQLite، وضعیت مرجع زمان اجرا را
مستقیماً زیر `$OPENCLAW_STATE_DIR/transcripts/` می‌نوشتند. اجرا کنید:

```bash
openclaw doctor --fix
```

Doctor کل درخت قدیمی را به SQLite درون‌ریزی می‌کند، تعداد و ترتیب ردیف‌ها را
تأیید می‌کند، رسیدهای مهاجرت را ثبت می‌کند و درخت منبع تأییدشده را به یک بایگانی
`transcripts.migrated-*` دارای مُهر زمانی منتقل می‌کند. فرمان‌های زمان اجرا به فایل‌های
قدیمی برنمی‌گردند. بایگانی را تا زمانی نگه دارید که نشست‌های درون‌ریزی‌شده و
هر برون‌بری مورد اتکای خود را تأیید کرده باشید.

## پیکربندی

ثبت رونوشت جلسه به‌طور پیش‌فرض فعال است. برای غیرفعال‌کردن آن در سراسر سامانه:

```json
{
  "transcripts": {
    "enabled": false
  }
}
```

- `enabled` (پیش‌فرض `true`): یادداشت‌برداری خودکار جلسه، ابزار رونوشت‌ها
  و منابع شروع خودکار پیکربندی‌شده را فعال می‌کند. وقتی یادداشت‌های جلسه نباید روی میزبان
  ماندگار شوند، آن را روی `false` تنظیم کنید. حالت `transcribe` جلسه که به‌صراحت درخواست شده باشد،
  دنباله محدود زیرنویس زنده موجود خود را حفظ می‌کند، اما وقتی این تنظیم false است،
  ردیف‌های ماندگار نمی‌نویسد.
  منابع شروع خودکار را با `transcripts.autoStart` پیکربندی کنید. هر ورودی با وجودداشتن
  فعال می‌شود؛ برای غیرفعال‌کردن آن منبع، ورودی را حذف کنید. `discord-voice`
  منبع همراهِ دارای قابلیت شروع خودکار است و به `guildId` و
  `channelId` نیاز دارد:

```json
{
  "transcripts": {
    "enabled": true,
    "autoStart": [
      {
        "providerId": "discord-voice",
        "guildId": "1234567890",
        "channelId": "2345678901"
      }
    ]
  }
}
```

شناسه‌های ارائه‌دهندگان جلسه `google-meet`، `teams` و `zoom` هستند. نام‌های مستعار آن‌ها
به‌ترتیب `googlemeet`/`meet`، `teams-meetings`/`microsoft-teams`/`msteams` و
`zoom-meetings` هستند. ارائه‌دهندگان جلسه به نشست ازپیش‌فعال ربات جلسه متصل می‌شوند؛
پیوستن عادی به جلسه به ورودی `autoStart` نیاز ندارد.
