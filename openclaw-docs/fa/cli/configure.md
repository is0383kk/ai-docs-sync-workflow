# `openclaw configure`

پرسش‌های تعاملی برای تغییرات هدفمند در یک راه‌اندازی موجود: اعتبارنامه‌ها، دستگاه‌ها، پیش‌فرض‌های عامل، Gateway، کانال‌ها، Pluginها، Skills و بررسی‌های سلامت.

برای فرایند کامل و هدایت‌شدهٔ نخستین اجرا از `openclaw onboard` یا `openclaw setup`، فقط برای پیکربندی پایه/فضای کاری از `openclaw setup --baseline` و زمانی که فقط به راه‌اندازی حساب کانال نیاز دارید از `openclaw channels add` استفاده کنید.

<Tip>
`openclaw config` بدون زیرفرمان، همان راهنما را باز می‌کند. برای ویرایش‌های غیرتعاملی از `openclaw config get|set|unset` استفاده کنید.
</Tip>

## گزینه‌ها

`--section <section>`: فیلتر تکرارپذیر بخش‌ها. بخش‌های موجود:

`workspace`, `model`, `web`, `gateway`, `daemon`, `channels`, `plugins`, `skills`, `health`

```bash
openclaw configure
openclaw configure --section web
openclaw configure --section model --section channels
openclaw configure --section gateway --section daemon
```

انتخاب `gateway`، `daemon` یا `health` (یا اجرای راهنمای کامل بدون `--section`) دربارهٔ محل اجرای Gateway پرسش می‌کند و `gateway.mode` را به‌روزرسانی می‌کند. فیلترهای بخشی که از هر سه مورد عبور کنند، بدون پرسش دربارهٔ حالت Gateway مستقیماً به راه‌اندازی درخواستی می‌روند. انتخاب حالت Gateway راه‌دور، پیکربندی راه‌دور را می‌نویسد و بلافاصله خارج می‌شود؛ مراحل صرفاً محلی مانند نصب Pluginها را اجرا نمی‌کند.

<Note>
`openclaw configure` به یک ترمینال تعاملی نیاز دارد (هم stdin و هم stdout باید TTY باشند). بدون آن، فرمان‌های غیرتعاملی معادل `openclaw config get|set|patch|validate` را چاپ می‌کند و به‌جای اجرای ناقص، با خطا خارج می‌شود.
</Note>

## بخش مدل

<Note>
**مدل** شامل انتخاب چندگانه برای فهرست صریح `agents.defaults.modelPolicy.allow` است (مواردی که در `/model` و انتخاب‌گر مدل نمایش داده می‌شوند). گزینه‌های راه‌اندازی مختص ارائه‌دهنده، مدل‌های انتخاب‌شدهٔ خود را با فهرست موجود ادغام می‌کنند و جایگزین ارائه‌دهندگان نامرتبطی که از قبل در پیکربندی هستند نمی‌شوند. نام‌های مستعار و پارامترهای هر مدل همچنان زیر `agents.defaults.models` باقی می‌مانند؛ این ورودی‌ها به‌تنهایی بازنویسی مدل‌ها را محدود نمی‌کنند.

اجرای دوبارهٔ احراز هویت ارائه‌دهنده از طریق configure، `agents.defaults.model.primary` موجود را حفظ می‌کند؛ حتی وقتی مرحلهٔ احراز هویت ارائه‌دهنده یک وصلهٔ پیکربندی با مدل پیش‌فرض پیشنهادی خودش برمی‌گرداند. افزودن یا احراز هویت دوبارهٔ یک ارائه‌دهنده، مدل‌های آن را بدون تصاحب مدل اصلی فعلی شما در دسترس قرار می‌دهد. برای تغییر عمدی مدل پیش‌فرض از `openclaw models auth login --provider <id> --set-default` یا `openclaw models set <model>` استفاده کنید.
</Note>

وقتی configure از یک گزینهٔ احراز هویت ارائه‌دهنده آغاز می‌شود، انتخاب‌گرهای مدل پیش‌فرض و خط‌مشی مدل به‌طور خودکار آن ارائه‌دهنده را ترجیح می‌دهند. برای ارائه‌دهندگان جفت‌شده مانند Volcengine و BytePlus، همین ترجیح گونه‌های طرح کدنویسی آن‌ها (`volcengine-plan/*`، `byteplus-plan/*`) را نیز تطبیق می‌دهد. اگر فیلتر ارائه‌دهندهٔ ترجیحی فهرستی خالی ایجاد کند، configure به‌جای نمایش انتخاب‌گر خالی به کاتالوگ بدون فیلتر بازمی‌گردد.

## بخش وب

`openclaw configure --section web` یک ارائه‌دهندهٔ جست‌وجوی وب را انتخاب و اعتبارنامه‌های آن را پیکربندی می‌کند. برخی ارائه‌دهندگان مراحل تکمیلی مختص خود را نمایش می‌دهند:

- **Grok** می‌تواند راه‌اندازی اختیاری `x_search` را با همان پروفایل OAuth متعلق به xAI یا کلید API ارائه دهد و امکان انتخاب یک مدل `x_search` را فراهم کند.
- **Kimi** می‌تواند منطقهٔ API متعلق به Moonshot (`api.moonshot.ai` در برابر `api.moonshot.cn`) و مدل پیش‌فرض جست‌وجوی وب Kimi را بپرسد.

## نکات دیگر

- پس از نوشتن پیکربندی محلی، هنگامی که مسیر راه‌اندازی انتخاب‌شده به Pluginهای قابل‌بارگیری نیاز داشته باشد، configure آن‌ها را نصب می‌کند. پیکربندی Gateway راه‌دور، بسته‌های Plugin محلی را نصب نمی‌کند.
- سرویس‌های کانال‌محور (Slack/Discord/Matrix/Microsoft Teams) هنگام راه‌اندازی فهرست‌های مجاز کانال/اتاق را درخواست می‌کنند. می‌توانید نام یا شناسه وارد کنید؛ راهنما در صورت امکان نام‌ها را به شناسه تبدیل می‌کند.
- اگر مرحلهٔ نصب daemon را اجرا کنید، احراز هویت با توکن به یک توکن نیاز دارد. اگر `gateway.auth.token` توسط SecretRef مدیریت شود، configure اعتبار SecretRef را بررسی می‌کند، اما مقادیر متن سادهٔ توکنِ استخراج‌شده را در فرادادهٔ محیط سرویس ناظر ذخیره نمی‌کند؛ اگر SecretRef قابل‌حل نباشد، configure نصب daemon را با راهنمای عملی رفع مشکل مسدود می‌کند.
- اگر هر دو `gateway.auth.token` و `gateway.auth.password` پیکربندی شده باشند و `gateway.auth.mode` تنظیم نشده باشد، configure نصب daemon را تا زمانی که حالت را صریحاً تنظیم کنید مسدود می‌کند.
