# `openclaw pairing`

درخواست‌های جفت‌سازی پیام مستقیم را برای کانال‌هایی که از جفت‌سازی پشتیبانی می‌کنند تأیید یا بررسی کنید (فقط پیام‌های مستقیم چت — برای جفت‌سازی Node/دستگاه از `openclaw devices` استفاده می‌شود).

مرتبط: [جریان جفت‌سازی](/fa/channels/pairing)

همین درخواست‌های در انتظار را می‌توان در رابط کنترل، در مسیر **تنظیمات ←
کانال‌ها ← درخواست‌های دسترسی پیام مستقیم** بررسی کرد. رابط کنترل از تأیید، اعلان اختیاری
به درخواست‌کننده و رد کردن پشتیبانی می‌کند. رد کردن، درخواست فعلی را حذف می‌کند اما
فرستنده را برای همیشه مسدود نمی‌کند.

## فرمان‌ها

```bash
openclaw pairing list telegram
openclaw pairing list --channel telegram --account work
openclaw pairing list telegram --json

openclaw pairing approve <code>
openclaw pairing approve telegram <code>
openclaw pairing approve --channel telegram --account work <code> --notify
```

## `pairing list`

درخواست‌های جفت‌سازی در انتظار برای یک کانال را فهرست می‌کند.

| گزینه                  | توضیحات                           |
| ----------------------- | ------------------------------------- |
| `[channel]`             | شناسهٔ کانال به‌صورت آرگومان موقعیتی                 |
| `--channel <channel>`   | شناسهٔ صریح کانال                   |
| `--account <accountId>` | شناسهٔ حساب برای کانال‌های چندحسابی |
| `--json`                | خروجی قابل‌خواندن برای ماشین               |

اگر چند کانال با قابلیت جفت‌سازی پیکربندی شده‌اند، کانال را به‌صورت آرگومان موقعیتی یا با `--channel` مشخص کنید. کانال‌های افزونه تا زمانی که شناسهٔ کانال معتبر باشد کار می‌کنند.

## `pairing approve`

یک کد جفت‌سازی در انتظار را تأیید کنید و به آن فرستنده اجازهٔ دسترسی دهید.

نحوهٔ استفاده:

- `openclaw pairing approve <channel> <code>`
- `openclaw pairing approve --channel <channel> <code>`
- `openclaw pairing approve <code>` هنگامی که دقیقاً یک کانال با قابلیت جفت‌سازی پیکربندی شده است

گزینه‌ها: `--channel <channel>`، `--account <accountId>`، `--notify` (ارسال تأییدیه برای درخواست‌کننده در همان کانال).

### راه‌اندازی اولیهٔ مالک

اگر هنگام تأیید یک کد جفت‌سازی، `commands.ownerAllowFrom` خالی باشد، CLI فرستندهٔ تأییدشده را نیز با استفاده از یک ورودی محدود به کانال، مانند `telegram:123456789`، به‌عنوان مالک فرمان ثبت می‌کند. این کار فقط نخستین مالک را راه‌اندازی می‌کند — تأییدهای بعدی جفت‌سازی هرگز `commands.ownerAllowFrom` را جایگزین یا گسترش نمی‌دهند. رابط کنترل این ارتقای سطح دسترسی را به‌صورت یک کادر انتخاب جداگانهٔ محافظت‌شده با `operator.admin` نمایش می‌دهد، نه اینکه آن را به‌طور خودکار اعمال کند.

مالک فرمان، حساب اپراتور انسانی است که اجازه دارد فرمان‌های مختص مالک را اجرا و اقدام‌های خطرناکی مانند `/diagnostics`، `/export-session`، `/export-trajectory`، `/config` و تأییدهای اجرای فرمان را تأیید کند. جفت‌سازی فقط به فرستنده اجازه می‌دهد با عامل گفتگو کند؛ به‌خودی‌خود و به‌جز این راه‌اندازی یک‌باره، امتیازات مالک را اعطا نمی‌کند.

اگر پیش از ایجاد این راه‌اندازی اولیه، فرستنده‌ای را تأیید کرده‌اید، `openclaw doctor` را اجرا کنید؛ اگر هیچ مالک فرمانی پیکربندی نشده باشد، هشدار می‌دهد و فرمان دقیق `openclaw config set commands.ownerAllowFrom ...` را برای رفع آن نمایش می‌دهد.
