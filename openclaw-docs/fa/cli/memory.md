# `openclaw memory`

نمایه‌سازی، جست‌وجو و ارتقای حافظه معنایی به `MEMORY.md` را مدیریت کنید.
این قابلیت توسط Plugin همراه `memory-core` ارائه می‌شود و هنگامی در دسترس است که
`plugins.slots.memory` مقدار `memory-core` (پیش‌فرض) را انتخاب کند. سایر Pluginهای حافظه
فضاهای نام CLI مختص خود را ارائه می‌کنند.

مرتبط: مفهوم [حافظه](/fa/concepts/memory)، [Dreaming](/fa/concepts/dreaming)،
[مرجع پیکربندی حافظه](/fa/reference/memory-config)، [ویکی حافظه](/fa/plugins/memory-wiki)،
[ویکی](/fa/cli/wiki)، [Pluginها](/fa/tools/plugin).

## `memory status`

```bash
openclaw memory status [--agent <id>] [--deep] [--index] [--fix] [--json] [--verbose]
```

بدون `--agent`، برای همه عامل‌های موجود در `agents.entries` اجرا می‌شود؛ اگر فهرست عاملی
پیکربندی نشده باشد، از عامل پیش‌فرض استفاده می‌کند.

| پرچم        | اثر                                                                                                                                                                                                                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--deep`    | آمادگی مخزن برداری، ارائه‌دهنده تعبیه‌سازی و جست‌وجوی معنایی را بررسی می‌کند (مستلزم فراخوانی‌های اضافی ارائه‌دهنده است). `memory status` ساده سریع باقی می‌ماند و از این کار صرف‌نظر می‌کند؛ وضعیت برداری/معنایی ناشناخته یعنی بررسی نشده است. `searchMode: "search"` واژگانی QMD همیشه از بررسی‌های بردار معنایی صرف‌نظر می‌کند، حتی با `--deep`. |
| `--index`   | اگر مخزن کثیف باشد، دوباره نمایه‌سازی می‌کند. متضمن `--deep` است.                                                                                                                                                                                                                                                          |
| `--fix`     | قفل‌های یادآوری منقضی را ترمیم و فراداده ارتقا را نرمال‌سازی می‌کند.                                                                                                                                                                                                                                               |
| `--json`    | JSON را چاپ می‌کند.                                                                                                                                                                                                                                                                                               |
| `--verbose` | گزارش‌های تفصیلی هر مرحله را منتشر می‌کند.                                                                                                                                                                                                                                                                             |

اگر خط `Dreaming` حتی با `dreaming.enabled: true` همچنان `off` باقی می‌ماند، یا
به نظر می‌رسد پیمایش‌های زمان‌بندی‌شده هرگز اجرا نمی‌شوند، Cron مدیریت‌شده Dreaming برای
راه‌اندازی تطبیق به فعال‌شدن Heartbeat عامل پیش‌فرض وابسته است. برای جزئیات
زمان‌بندی به [Dreaming](/fa/concepts/dreaming) مراجعه کنید.

وضعیت همچنین مسیرهای جست‌وجوی اضافی از `memory.search.extraPaths` را فهرست می‌کند.

## `memory index`

```bash
openclaw memory index [--agent <id>] [--force] [--verbose]
```

دامنه‌بندی هر عامل همانند `status` است. `--force` به‌جای نمایه‌سازی
افزایشی، نمایه‌سازی مجدد کامل را اجرا می‌کند. `--verbose` پیش از نمایش پیشرفت نمایه‌سازی،
جزئیات ارائه‌دهنده، مدل، منابع و مسیرهای اضافی هر عامل را چاپ می‌کند.

## `memory search`

```bash
openclaw memory search [query] [--query <text>] [--agent <id>] [--max-results <n>] [--min-score <n>] [--json]
```

- پرس‌وجو: `[query]` موقعیتی یا `--query <text>`. اگر هر دو تنظیم شده باشند، `--query`
  اولویت دارد. اگر هیچ‌کدام تنظیم نشده باشند، فرمان خطا می‌دهد.
- `--agent <id>`: به‌طور پیش‌فرض از عامل پیش‌فرض استفاده می‌کند (نه فهرست کامل عامل‌ها).
- `--max-results <n>`: تعداد نتایج را محدود می‌کند (عدد صحیح مثبت).
- `--min-score <n>`: تطبیق‌های پایین‌تر از این امتیاز را فیلتر می‌کند.

## `memory promote`

نامزدهای کوتاه‌مدت را از `memory/YYYY-MM-DD.md` رتبه‌بندی کنید و در صورت تمایل
ورودی‌های برتر را به `MEMORY.md` بیفزایید.

```bash
openclaw memory promote [--agent <id>] [--limit <n>] [--min-score <n>] \
  [--min-recall-count <n>] [--min-unique-queries <n>] [--apply] [--include-promoted] [--json]
```

| پرچم                       | پیش‌فرض      | اثر                                                            |
| -------------------------- | ------------ | ----------------------------------------------------------------- |
| `--limit <n>`              |              | حداکثر تعداد نامزدها برای بازگردانی/اعمال.                                   |
| `--min-score <n>`          | `0.75`       | حداقل امتیاز وزنی ارتقا.                                 |
| `--min-recall-count <n>`   | `3`          | حداقل تعداد یادآوری لازم.                                    |
| `--min-unique-queries <n>` | `2`          | حداقل تعداد پرس‌وجوهای متمایز لازم.                            |
| `--apply`                  | فقط پیش‌نمایش | نامزدهای انتخاب‌شده را به `MEMORY.md` می‌افزاید و آن‌ها را ارتقایافته علامت‌گذاری می‌کند. |
| `--include-promoted`       |              | نامزدهایی را که در چرخه‌های پیشین ارتقا یافته‌اند نیز شامل می‌شود.           |
| `--json`                   |              | JSON را چاپ می‌کند.                                                       |

این پیش‌فرض‌های CLI با آستانه‌های مرحله عمیق پیمایش زمان‌بندی‌شده Dreaming
متفاوت‌اند (به [Dreaming](#dreaming) در ادامه مراجعه کنید)؛ برای مطابقت رفتار
پیمایش در یک اجرای دستی موردی، پرچم‌ها را صریحاً ارسال کنید.

سیگنال‌های رتبه‌بندی: بسامد یادآوری، ارتباط بازیابی، تنوع پرس‌وجو،
تازگی زمانی، تثبیت میان‌روزی و غنای مفهومی مشتق‌شده که
هم از یادآوری‌های حافظه و هم از گذرهای دریافت روزانه به دست می‌آیند، به‌علاوه
تقویت اندک مرحله سبک/REM برای بازدیدهای مکرر Dreaming. پیش از نوشتن، فرایند ارتقا
یادداشت روزانه زنده را دوباره می‌خواند تا ویرایش یا حذف قطعه‌های کوتاه‌مدت
پس از رتبه‌بندی رعایت شود و ارتقا از یک عکس فوری منقضی انجام نشود.

## `memory promote-explain`

تفکیک امتیاز یک نامزد ارتقا را توضیح می‌دهد.

```bash
openclaw memory promote-explain <selector> [--agent <id>] [--include-promoted] [--json]
```

`<selector>` با کلید نامزد (به‌صورت دقیق یا زیررشته)، مسیر یا متن قطعه
مطابقت می‌کند.

## `memory rem-harness`

بازتاب‌های REM، حقیقت‌های نامزد و خروجی ارتقای مرحله عمیق را
بدون نوشتن هیچ‌چیز پیش‌نمایش می‌کند.

```bash
openclaw memory rem-harness [--agent <id>] [--path <file-or-dir>] [--grounded] [--include-promoted] [--json]
```

- `--path <file-or-dir>`: به‌جای فضای کاری زنده، ابزار آزمون را از فایل‌های روزانه
  تاریخی `YYYY-MM-DD.md` مقداردهی اولیه می‌کند.
- `--grounded`: همچنین یک پیش‌نمایش مستند `What Happened` / `Reflections` /
  `Possible Lasting Updates` را از یادداشت‌های تاریخی رندر می‌کند.

## `memory rem-backfill`

خلاصه‌های تاریخی مستند REM را برای بازبینی در رابط کاربری در `DREAMS.md` می‌نویسد.
برگشت‌پذیر است.

```bash
openclaw memory rem-backfill --path <file-or-dir> [--agent <id>] [--stage-short-term] [--json]
openclaw memory rem-backfill --rollback [--rollback-short-term] [--json]
```

- `--path <file-or-dir>`: الزامی است، مگر اینکه `--rollback`/`--rollback-short-term`
  تنظیم شده باشد. فایل(های) حافظه روزانه تاریخی یا پوشه‌ای که پُرکردن گذشته‌نگر از آن انجام می‌شود.
- `--stage-short-term`: همچنین نامزدهای ماندگار مستند را در مخزن زنده
  ارتقای کوتاه‌مدت قرار می‌دهد تا مرحله عمیق عادی بتواند آن‌ها را رتبه‌بندی کند.
- `--rollback`: ورودی‌های مستند دفترچه خاطرات را که پیش‌تر در
  `DREAMS.md` نوشته شده‌اند، حذف می‌کند.
- `--rollback-short-term`: نامزدهای کوتاه‌مدت مستندی را که پیش‌تر
  آماده شده‌اند، حذف می‌کند.

## Dreaming

Dreaming سامانه تثبیت حافظه در پس‌زمینه با سه مرحله همکار است
که به‌ترتیب و طبق یک زمان‌بندی اجرا می‌شوند: **سبک** (مرتب‌سازی/آماده‌سازی مطالب
کوتاه‌مدت)، **REM** (بازاندیشی و آشکارسازی درون‌مایه‌ها)، **عمیق** (ارتقای حقایق
ماندگار به `MEMORY.md`). فقط مرحله عمیق در `MEMORY.md` می‌نویسد.

- با `plugins.entries.memory-core.config.dreaming.enabled: true` فعال کنید
  (پیش‌فرض `false`)؛ `memory-core` کار Cron پیمایش را خودکار مدیریت می‌کند و نیازی به
  `openclaw cron add` دستی نیست.
- از چت با `/dreaming on|off` تغییر وضعیت دهید؛ با `/dreaming status`
  (یا `/dreaming`/`/dreaming help`) بررسی کنید. `on`/`off` به وضعیت مالک کانال
  یا `operator.admin` در Gateway نیاز دارد؛ `status` و راهنما برای هر کسی که
  بتواند فرمان را فراخوانی کند، در دسترس می‌مانند.
- خروجی خوانای هر مرحله برای انسان در `DREAMS.md` (یا یک `dreams.md` موجود) قرار می‌گیرد.
  به‌طور پیش‌فرض (`dreaming.storage.mode: "separate"`) هر مرحله همچنین یک
  گزارش مستقل در `memory/dreaming/<phase>/YYYY-MM-DD.md` می‌نویسد؛ `mode:
"inline"` را تنظیم کنید تا گزارش‌ها در فایل حافظه روزانه ادغام شوند، یا `"both"`
  را برای هر دو تنظیم کنید.
- اجراهای زمان‌بندی‌شده و دستی `memory promote` سیگنال‌های رتبه‌بندی
  مرحله عمیق یکسانی دارند؛ فقط آستانه‌های پیش‌فرض متفاوت‌اند (جدول بالا را با
  پیش‌فرض‌های زمان‌بندی‌شده زیر مقایسه کنید).
- اجراهای زمان‌بندی‌شده در فضای کاری حافظه همه عامل‌های پیکربندی‌شده توزیع می‌شوند.

پیش‌فرض‌های زمان‌بندی‌شده (`plugins.entries.memory-core.config.dreaming`):

| کلید                                    | پیش‌فرض     |
| -------------------------------------- | ----------- |
| `frequency`                            | `0 3 * * *` |
| `phases.deep.minScore`                 | `0.8`       |
| `phases.deep.minRecallCount`           | `3`         |
| `phases.deep.minUniqueQueries`         | `3`         |
| `phases.deep.recencyHalfLifeDays`      | `14`        |
| `phases.deep.maxAgeDays`               | `30`        |
| `phases.deep.maxPromotedSnippetTokens` | `160`       |

```json
{
  "plugins": {
    "entries": {
      "memory-core": {
        "config": {
          "dreaming": {
            "enabled": true
          }
        }
      }
    }
  }
}
```

فهرست کامل کلیدها و جزئیات مراحل: [Dreaming](/fa/concepts/dreaming)،
[مرجع پیکربندی حافظه](/fa/reference/memory-config#dreaming).

## وابستگی SecretRef به Gateway

اگر فیلدهای کلید API راه‌دور Active Memory به‌صورت SecretRef پیکربندی شده باشند، فرمان‌های `memory`
آن‌ها را از عکس فوری فعال Gateway حل می‌کنند؛ اگر Gateway
در دسترس نباشد، فرمان به‌سرعت شکست می‌خورد. این کار به Gatewayای نیاز دارد که از
متد `secrets.resolve` پشتیبانی کند؛ Gatewayهای قدیمی‌تر خطای متد ناشناخته برمی‌گردانند.
