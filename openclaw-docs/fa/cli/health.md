# `openclaw health`

یک نمای فوری از سلامت Gateway در حال اجرا از طریق WebSocket RPC دریافت می‌کند (بدون سوکت‌های مستقیم کانال از CLI).

## گزینه‌ها

| پرچم             | پیش‌فرض | توضیحات                                                                       |
| ---------------- | ------- | --------------------------------------------------------------------------------- |
| `--json`         | `false` | به‌جای متن، JSON قابل‌خواندن توسط ماشین را چاپ می‌کند.                                      |
| `--timeout <ms>` | `10000` | مهلت زمانی اتصال برحسب میلی‌ثانیه.                                               |
| `--verbose`      | `false` | یک وارسی زنده را اجباری می‌کند و خروجی را برای همه حساب‌ها و عامل‌های پیکربندی‌شده گسترش می‌دهد. |
| `--debug`        | `false` | نام مستعار برای `--verbose`.                                                            |

مثال‌ها:

```bash
openclaw health
openclaw health --json
openclaw health --timeout 2500
openclaw health --verbose
openclaw health --debug
```

## رفتار

- بدون `--verbose`، Gateway می‌تواند یک نمای فوری ذخیره‌شده در حافظه نهان را بازگرداند (تا 60 ثانیه تازه و بدون تفاوت با وضعیت زنده زمان اجرای کانال) و آن را در پس‌زمینه برای فراخواننده بعدی تازه‌سازی کند.
- `--verbose` یک وارسی زنده (وارسی حساب‌ها به‌ازای هر کانال) را اجباری می‌کند، جزئیات اتصال Gateway را چاپ می‌کند و به‌جای فقط عامل پیش‌فرض، خروجی خوانا برای انسان را برای همه حساب‌ها و عامل‌های پیکربندی‌شده گسترش می‌دهد.
- `--json` همیشه نمای فوری کامل را بازمی‌گرداند: کانال‌ها، وارسی‌های هر حساب، وضعیت بارگذاری Plugin، وضعیت قرنطینه موتور زمینه، وضعیت حافظه نهان قیمت‌گذاری مدل، سلامت حلقه رویداد، نامه‌های مرده صف تحویل و مخزن‌های نشست هر عامل.
- هنگامی که تحویل‌های خروجی یا رویدادهای ورودی کانال به صف نامه‌های مرده منتقل شوند، خروجی متنی تعداد آن‌ها و قدمت قدیمی‌ترین خرابی را گزارش می‌کند. تعداد ورودی‌ها بر اساس حساب کانال گروه‌بندی می‌شود؛ رویدادهای منفرد را با [`openclaw channels dead-letters`](/fa/cli/channels#inbound-dead-letters) بررسی یا بازیابی کنید.
