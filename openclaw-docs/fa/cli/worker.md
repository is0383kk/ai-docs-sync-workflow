# `openclaw worker`

`openclaw worker` نقطهٔ ورود محدود زمان اجرا برای راه‌اندازی توسط یک هماهنگ‌کنندهٔ worker ابری
درون یک محیط worker آماده‌شده است. این یک فرمان همه‌منظوره برای ثبت دستی worker
نیست.

Gateway بستهٔ منطبق OpenClaw را نصب و تونل SSH معکوسِ سنجاق‌شده به کلید میزبان را
باز می‌کند. راه‌انداز worker این فرمان را با یک تخصیص آماده‌شده آغاز می‌کند.
فرمان از طریق سوکت محلی هدایت‌شده در تونل متصل می‌شود و با نقش اختصاصی
`worker` پذیرش می‌شود.

## قرارداد راه‌اندازی

فرمان دقیقاً یک پوش JSON محدود راه‌اندازی را از ورودی استاندارد می‌خواند.
این پوش شامل محل سوکت محلی، اعتبارنامهٔ صادرشدهٔ worker، هویت بسته
و پروتکل، دورهٔ مالک، تنها نشست و نوبت تخصیص‌یافته، و نام دقیق ابزارهای محلی worker
است که برای آن نوبت مجازند. Gateway این مجموعه‌ابزار نهایی را پیش از تحویل، بر اساس
سیاست جاری تعیین می‌کند؛ پیکربندی خام و هویت مالک زمان‌بندی‌شده هرگز وارد پوش
worker نمی‌شوند.
اعتبارنامه هرگز از طریق آرگومان‌های خط فرمان پذیرفته نمی‌شود و این صفحه
عمداً هیچ نمونه‌ای از اعتبارنامه یا پوش دست‌نویس ارائه نمی‌کند.

اگر پوش نامعتبر باشد، اعتبارنامه رد شود، ویژگی‌های بسته یا پروتکل مطابقت
نداشته باشند، یا نشست و دورهٔ مالک دیگر جاری نباشند، پذیرش به‌صورت بسته شکست
می‌خورد. نام‌های ابزار مفقود، تکراری یا ناشناخته نیز پوش را نامعتبر می‌کنند.
اپراتورها باید workerها را از طریق هماهنگ‌کنندهٔ worker ابری راه‌اندازی کنند،
نه اینکه این نقطهٔ ورود را مستقیماً فراخوانی کنند.

## مرز زمان اجرا

فرایند حلقهٔ عادی عامل تعبیه‌شده را با یک بک‌اند محدود اجرا می‌کند:

- ابزارهای کدنویسی `read`، `write`، `edit`، `apply_patch`، `exec` و `process`
  هنگامی‌که در اختیار نوبت صادرشده توسط Gateway وجود داشته باشند، به‌صورت محلی
  در فضای کاری worker اجرا می‌شوند. اختیار خالی، مدل را بدون ابزار اجرا می‌کند.
- فراخوانی‌های مدل از پراکسی استنتاج Gateway استفاده می‌کنند. هیچ نمایهٔ احراز هویت
  محلی مدل بارگذاری نمی‌شود.
- نوشتن رونوشت‌ها از RPC ثبت رونوشت Gateway استفاده می‌کند.
- به‌روزرسانی‌های جریان و چرخهٔ عمر ابزار از RPC رویداد زندهٔ Gateway استفاده می‌کنند.
- فقط نشست و نوبت تخصیص‌یافته پذیرفته می‌شوند.

حالت worker کانال‌ها، سطوح HTTP متعلق به Gateway یا شروع خودکار Pluginها
فراتر از مجموعه‌ابزار نشست تخصیص‌یافته را راه‌اندازی نمی‌کند. این حالت از یک
دایرکتوری وضعیت یک‌بارمصرف استفاده می‌کند و هیچ اعتبارنامهٔ دائمی ارائه‌دهنده
یا forge ندارد.

ارسال نشست از یک worker به worker دیگر در این حالت ارائه نمی‌شود. جای‌دهی و
ارسال همچنان تحت مالکیت Gateway باقی می‌مانند: اپراتور می‌تواند یک نشست محلی
موجود با worktree مدیریت‌شده را از طریق Gateway ارسال کند، اما فرایند worker
نمی‌تواند خود یا worker دیگری را ارسال کند.

تخصیص آماده‌شده شامل زمینهٔ رونوشت، برگ پایهٔ پذیرفته‌شده، توالی ثبت و مکان‌نمای
رویداد زنده است. هنگام اتصال مجدد تونل، فرایند با همان اعتبارنامه و دورهٔ مالک
دوباره پذیرش می‌شود، پایهٔ پذیرفته‌شدهٔ رونوشت را حفظ می‌کند، دنبالهٔ تأییدنشدهٔ
رویداد زندهٔ خود را بازپخش می‌کند و نوبت استنتاج در حال اجرای دارای همان هویت را
دوباره متصل می‌کند. اگر دلتاهای جریانی از دست رفته باشند، پیام نهایی استنتاج
مرجع قطعی است. دورهٔ مالک جایگزین، فرایند را محصور می‌کند و موجب خروج پاک می‌شود.

رد رونوشت `stale-base-leaf` اجرای جاری را فوراً متوقف می‌کند. حالت worker
توالی ردشده را در برابر برگی متفاوت دوباره امتحان نمی‌کند؛ بنابراین هیچ ثبت
تکراری تولید نمی‌شود و هر دنبالهٔ درون‌حافظه‌ای هنوز ثبت‌نشده از آن اجرا از دست
می‌رود. راه‌اندازی مجدد بر عهدهٔ مالک جای‌دهی milestone-3 است که باید تخصیصی تازه
بر اساس رونوشت مرجع و دفتر ثبت Gateway ایجاد کند. همچنین، راه‌اندازی مجدد فرایند
Gateway یک نوبت استنتاج معلق را با خطای ارائه‌دهنده خاتمه می‌دهد؛ فقط اتصال مجدد
تونل یا WebSocket متعلق به worker می‌تواند دوباره به جریان استنتاج فعال همان
فرایند متصل شود.

برای سطح بستهٔ RPC مربوط به worker به [پروتکل Gateway](/fa/gateway/protocol#worker-role-and-closed-protocol)
و برای معماری و مدل امنیتی به [طرح workerهای ابری](/fa/plan/cloud-workers)
مراجعه کنید.
