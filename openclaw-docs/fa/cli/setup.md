# `openclaw setup`

`openclaw setup` نقطهٔ ورود عامل سیستم است. در یک سیستم پیکربندی‌شده، اجرای صرف
`openclaw setup` یک گفت‌وگوی تعاملی OpenClaw را باز می‌کند. در یک سیستم تازه، به
راه‌اندازی اولیهٔ هدایت‌شده منتقل می‌شود. برای یک درخواست از `-m`/`--message` یا
برای مقداردهی اولیهٔ پوشه‌های پیکربندی/فضای کاری بدون جادوگر از `--baseline` استفاده کنید.

ترتیب مسیریابی:

1. هر گزینهٔ راه‌اندازی اولیه (`--wizard`، `--baseline`، فضای کاری، بازنشانی،
   غیرتعاملی، جریان، حالت، Gateway، دیمن، رد کردن، درون‌ریزی، راه دور یا گزینه‌های
   احراز هویت) راه‌اندازی اولیه را دقیقاً مانند `openclaw onboard` اجرا می‌کند.
2. `-m`/`--message` یا `--yes` عامل سیستم را اجرا می‌کند.
3. بدون گزینهٔ مسیریابی، یک سیستم تعاملی پیکربندی‌شده OpenClaw را باز می‌کند. یک
   سیستم تازه راه‌اندازی اولیه را اجرا می‌کند. در یک سیستم پیکربندی‌شده، `--json` حتی بدون TTY
   نمای کلی سیستم را چاپ می‌کند؛ یک گزینهٔ راه‌اندازی اولیه، خلاصهٔ JSON
   راه‌اندازی اولیه را حفظ می‌کند.

در حالت هدایت‌شده، `--workspace <dir>` فضای کاری پیشنهادی به OpenClaw است؛
این مقدار تنها پس از تأیید پیشنهاد شما ماندگار می‌شود. راه‌اندازی پایه، کلاسیک و
غیرتعاملی در نصب تازه، فضای کاری ارائه‌شده را از طریق جریان عادی خود ماندگار
می‌کنند. هنگامی که فهرست عامل‌های موجود نیازمند نگاشت مجدد باشد،
جادوگر کلاسیک به تأیید صریح نیاز دارد؛ راه‌اندازی غیرتعاملی فضای کاری ناوگان
فعلی را حفظ می‌کند و هشداری چاپ می‌کند.

تشخیص استنتاج هدایت‌شده روی میزبان Gateway در macOS یا Linux اجرا می‌شود. CLI
و برنامهٔ macOS همان آشکارساز متعلق به Gateway را فراخوانی می‌کنند که مدل‌های
پیکربندی‌شده، ورودهای CLI پشتیبانی‌شده، متغیرهای محیطی کلید API و مدل‌های
ازپیش‌نصب‌شدهٔ Ollama یا LM Studio را بررسی می‌کند. مدل‌های محلی هرگز در این
مرحلهٔ خودکار بارگیری نمی‌شوند. زمان‌اجراهای محلی شناسایی‌شده پس از گزینه‌های
CLI و کلید API به‌طور خودکار آزمایش می‌شوند؛ هنگامی که چند مدل محلی در دسترس
باشد، OpenClaw قوی‌ترین خانوادهٔ دستوری با قابلیت فراخوانی ابزار را ترجیح
می‌دهد. گزینهٔ انتخاب‌شده باید پیش از ذخیره‌شدن پیکربندی ارائه‌دهنده و مدل آن،
به یک تکمیل واقعی پاسخ دهد.
CLIهای نصب‌شدهٔ Gemini، Antigravity، Pi و OpenCode نیز هنگامی گزارش می‌شوند که
نتوانند به‌عنوان مسیر استنتاج قابل‌استفادهٔ مجدد برای راه‌اندازی هدایت‌شده عمل کنند.

`setup` همان پرچم‌های راه‌اندازی اولیهٔ `openclaw onboard` را می‌پذیرد، از جمله
احراز هویت (`--auth-choice`، `--token`، پرچم‌های کلید ارائه‌دهنده)، Gateway
(`--gateway-port`، `--gateway-bind`، `--gateway-auth`، `--install-daemon`)،
Tailscale (`--tailscale`)، بازنشانی (`--reset`، `--reset-scope`)، جریان
(`--flow quickstart|advanced|manual|import`) و پرچم‌های رد کردن
(`--skip-channels`، `--skip-skills`، `--skip-bootstrap`، `--skip-search`،
`--skip-health`، `--skip-ui`، `--skip-hooks`). برای استفاده از همان
راه خروج ترمینال `openclaw onboard --tui`، مقدار `--tui` را ارسال کنید. برای مرجع کامل پرچم‌ها و
نمونه‌های غیرتعاملی، به [راه‌اندازی اولیه](/fa/cli/onboard) و
[خودکارسازی CLI](/fa/start/wizard-cli-automation) مراجعه کنید. `openclaw onboard --modern` همچنان یک ورودی سازگاری
برای همان دستیار OpenClaw وابسته به استنتاج است.

<Note>
`openclaw setup` برای نصب‌هایی با پیکربندی قابل‌تغییر است. در حالت Nix (`OPENCLAW_NIX_MODE=1`)، OpenClaw نوشتن تنظیمات راه‌اندازی را رد می‌کند، زیرا فایل پیکربندی توسط Nix مدیریت می‌شود. از [شروع سریع nix-openclaw](https://github.com/openclaw/nix-openclaw#quick-start) متعلق به سازنده یا پیکربندی منبع معادل برای بستهٔ Nix دیگری استفاده کنید.
</Note>

## گزینه‌ها

| پرچم                       | توضیحات                                                                                          |
| -------------------------- | ---------------------------------------------------------------------------------------------------- |
| `-m, --message <text>`     | اجرای یک درخواست OpenClaw.                                                                            |
| `--yes`                    | تأیید نوشتن ماندگار پیکربندی برای یک درخواست `--message`.                                        |
| `--workspace <dir>`        | پیشنهاد فضای کاری؛ ناوگان‌های موجود به تأیید کلاسیک نیاز دارند و در حالت غیرتعاملی حفظ می‌شوند. |
| `--baseline`               | ایجاد پوشه‌های پیکربندی/فضای کاری/نشست پایه بدون راه‌اندازی اولیه.                                 |
| `--wizard`                 | اجبار راه‌اندازی اولیهٔ تعاملی.                                                                        |
| `--tui`                    | استفاده از راه خروج ترمینال به‌جای تحویل به مرورگر.                                               |
| `--non-interactive`        | اجرای راه‌اندازی اولیه بدون اعلان.                                                                      |
| `--accept-risk`            | پذیرش خطر دسترسی عامل به کل سیستم؛ همراه `--non-interactive` الزامی است.                        |
| `--mode <mode>`            | حالت راه‌اندازی اولیه: `local` یا `remote`.                                                                |
| `--flow <flow>`            | جریان راه‌اندازی اولیه: `quickstart`، `advanced`، `manual` یا `import`.                                       |
| `--reset`                  | بازنشانی پیکربندی + اعتبارنامه‌ها + نشست‌ها پیش از راه‌اندازی اولیه (فضای کاری فقط با `--reset-scope full`).  |
| `--reset-scope <scope>`    | دامنهٔ بازنشانی: `config`، `config+creds+sessions` یا `full`.                                           |
| `--import-from <provider>` | ارائه‌دهندهٔ مهاجرت برای اجرا هنگام راه‌اندازی اولیه.                                                         |
| `--import-source <path>`   | خانهٔ عامل مبدأ برای `--import-from`.                                                               |
| `--import-secrets`         | درون‌ریزی رازهای پشتیبانی‌شده هنگام مهاجرت راه‌اندازی اولیه.                                                |
| `--remote-url <url>`       | نشانی WebSocket راه دور Gateway.                                                                        |
| `--remote-token <token>`   | توکن Gateway راه دور (اختیاری).                                                                     |
| `--json`                   | سیستم پیکربندی‌شده: نمای کلی OpenClaw. مسیر راه‌اندازی اولیه: خلاصهٔ راه‌اندازی اولیه.                          |

`--classic` و `--non-interactive` متقابلاً انحصاری‌اند: حالت کلاسیک
جادوگر دارای اعلان را باز می‌کند، درحالی‌که راه‌اندازی غیرتعاملی از مسیر خودکارسازی استفاده می‌کند.
در راه‌اندازی اولیهٔ تعاملی، `--remote-url` و `--remote-token`
مرحلهٔ Gateway راه دور را از پیش پر می‌کنند و برای آن اجرا بر مقادیر راه دور ذخیره‌شده اولویت دارند.
تغییر نشانی URL باعث استفادهٔ مجدد از اعتبارنامه‌های ذخیره‌شده نمی‌شود، مگر اینکه توکنی نیز ارسال کنید.
توکن پوشیده باقی می‌ماند و از حالت ذخیره‌سازی متن ساده یا SecretRef انتخاب‌شده توسط
جادوگر استفاده می‌کند.

### حالت پایه

`openclaw setup --baseline` رفتار قدیمی‌ترِ محدود به حالت پایه را حفظ می‌کند:
پوشه‌های پیکربندی، فضای کاری و نشست را ایجاد می‌کند و سپس بدون
اجرای راه‌اندازی اولیه خارج می‌شود. `--workspace` و کنترل‌های بی‌ضرر خروجی را می‌پذیرد، اما
گزینه‌های صریح راه‌اندازی اولیه، Gateway، احراز هویت، بازنشانی یا دیمن را به‌جای
نادیده‌گرفتن بی‌سروصدای آن‌ها رد می‌کند. اگر پیکربندی موجود نامعتبر باشد، راه‌اندازی پایه
آن را حفظ می‌کند و از شما می‌خواهد پیش از تلاش دوباره `openclaw doctor` را اجرا کنید.

## نمونه‌ها

```bash
openclaw setup
openclaw setup -m "status"
openclaw setup -m "restart gateway" --yes
openclaw setup --json
openclaw setup --wizard
openclaw setup --baseline
openclaw setup --workspace ~/.openclaw/workspace
openclaw setup --import-from hermes --import-source ~/.hermes
openclaw setup --non-interactive --accept-risk --mode remote --remote-url wss://gateway-host:18789 --remote-token <token>
```

## نکات

- پس از راه‌اندازی پایه، برای طی‌کردن کامل مسیر هدایت‌شده `openclaw onboard`، برای تغییرات هدفمند `openclaw configure` یا برای افزودن حساب‌های کانال `openclaw channels add` را اجرا کنید.
- اگر وضعیت Hermes شناسایی شود، راه‌اندازی اولیهٔ تعاملی می‌تواند مهاجرت را به‌طور خودکار پیشنهاد دهد. راه‌اندازی اولیهٔ درون‌ریزی به یک راه‌اندازی تازه نیاز دارد؛ برای طرح‌های اجرای آزمایشی، پشتیبان‌گیری و حالت بازنویسی خارج از راه‌اندازی اولیه از [مهاجرت](/fa/cli/migrate) استفاده کنید.
