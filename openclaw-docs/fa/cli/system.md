# `openclaw system`

ابزارهای کمکی سطح سیستم برای Gateway: قراردادن رویدادهای سیستمی در صف، کنترل
Heartbeatها و مشاهدهٔ وضعیت حضور.

همهٔ زیرفرمان‌های `system` از RPC در Gateway استفاده می‌کنند و پرچم‌های مشترک کلاینت را می‌پذیرند:

| پرچم              | پیش‌فرض                              | توضیحات                                                                                                                                                                                            |
| ----------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--url <url>`     | `gateway.remote.url` در صورت پیکربندی | نشانی WebSocket مربوط به Gateway.                                                                                                                                                                                 |
| `--token <token>` | هیچ‌کدام                                 | توکن Gateway (در صورت نیاز).                                                                                                                                                                           |
| `--timeout <ms>`  | `30000`                              | مهلت زمانی RPC برحسب میلی‌ثانیه.                                                                                                                                                                           |
| `--expect-final`  | خاموش                                  | انتظار برای پاسخ نهایی (عامل).                                                                                                                                                                       |
| `--json`          | خاموش                                  | خروجی JSON. گزینه‌های `heartbeat last/enable/disable` و `system presence` بدون توجه به این پرچم، همیشه محتوای خام JSON مربوط به RPC را چاپ می‌کنند؛ `system event` از آن برای جابه‌جایی بین JSON و یک خط سادهٔ `ok` استفاده می‌کند. |

## فرمان‌های متداول

```bash
openclaw system event --text "Check for urgent follow-ups" --mode now
openclaw system event --text "Check for urgent follow-ups" --url ws://127.0.0.1:18789 --token "$OPENCLAW_GATEWAY_TOKEN"
openclaw system heartbeat enable
openclaw system heartbeat last
openclaw system presence
```

## `system event`

به‌طور پیش‌فرض، یک رویداد سیستمی را در صف نشست **اصلی** قرار می‌دهد. Heartbeat بعدی
آن را به‌شکل یک خط `System:` در اعلان وارد می‌کند. برای
فعال‌کردن فوری Heartbeat از `--mode now` استفاده کنید؛ `next-heartbeat` (پیش‌فرض) تا
تیک زمان‌بندی‌شدهٔ بعدی منتظر می‌ماند.

برای هدف‌گرفتن یک نشست مشخص، `--session-key` را ارسال کنید؛ برای نمونه، جهت بازگرداندن
تکمیل یک وظیفهٔ ناهمگام به کانالی که آن را آغاز کرده است.

<Note>
**استثنای زمان‌بندی با `--session-key`:** وقتی `--session-key` ارائه شود،
`--mode next-heartbeat` به‌جای انتظار برای تیک زمان‌بندی‌شدهٔ بعدی، به یک
بیدارباش هدفمند و فوری تبدیل می‌شود. بیدارباش‌های هدفمند از هدف Heartbeat
با مقدار `immediate` استفاده می‌کنند تا از دروازهٔ «هنوز موعد نرسیده» اجراکننده عبور کنند؛ در غیر این صورت،
این دروازه یک بیدارباش با هدف `event` را به تعویق می‌اندازد (و عملاً حذف می‌کند). اگر تحویل با تأخیر
می‌خواهید، `--session-key` را حذف کنید تا رویداد در نشست اصلی قرار گیرد و
همراه Heartbeat عادی بعدی ارسال شود.
</Note>

پرچم‌ها:

- `--text <text>`: متن الزامی رویداد سیستمی.
- `--mode <mode>`: `now` یا `next-heartbeat` (پیش‌فرض).
- `--session-key <sessionKey>`: اختیاری؛ به‌جای نشست اصلی عامل، یک نشست مشخص عامل را
  هدف می‌گیرد. کلیدهایی که به عامل
  حل‌شده تعلق ندارند، به نشست اصلی عامل بازمی‌گردند.

## `system heartbeat last|enable|disable`

- `last`: آخرین رویداد Heartbeat را نمایش می‌دهد.
- `enable`: Heartbeatها را دوباره روشن می‌کند (اگر غیرفعال شده‌اند، از این گزینه استفاده کنید).
- `disable`: Heartbeatها را متوقف می‌کند.

## `system presence`

فهرست ورودی‌های فعلی حضور در سیستم را که Gateway از آن‌ها آگاه است نمایش می‌دهد (Nodeها،
نمونه‌ها و خطوط وضعیت مشابه).

## نکات

- به یک Gateway در حال اجرا نیاز دارد که از طریق پیکربندی فعلی شما (محلی یا
  راه دور) قابل دسترسی باشد.
- رویدادهای سیستمی موقتی‌اند و پس از راه‌اندازی مجدد نگه‌داری نمی‌شوند.
