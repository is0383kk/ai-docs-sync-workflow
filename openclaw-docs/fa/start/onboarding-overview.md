OpenClaw فرایند راه‌اندازی اولیه در ترمینال و برنامه macOS را ارائه می‌دهد. هر دو ابتدا استنتاج را برقرار می‌کنند:
دسترسی موجود به هوش مصنوعی را شناسایی می‌کنند، تکمیل زنده را الزامی می‌دانند و تنها پس از آن
OpenClaw را برای پیکربندی ادامه راه‌اندازی اجرا می‌کنند. یک Gateway در دسترس و پیکربندی‌شده
که عامل پیش‌فرض آن از قبل مدل پیکربندی‌شده‌ای دارد، راه‌اندازی اولیه را رد می‌کند و
رابط کاربری عادی عامل را باز می‌کند. جریان ترمینال همچنین برای
راه‌اندازی دقیق، جادوگر کلاسیک کامل را ارائه می‌دهد.

## از کدام مسیر باید استفاده کنم؟

|                | راه‌اندازی اولیه CLI                         | راه‌اندازی اولیه برنامه macOS           |
| -------------- | -------------------------------------- | ------------------------------ |
| **پلتفرم‌ها**  | macOS، Linux، Windows (بومی یا WSL2) | فقط macOS                     |
| **رابط**  | راه‌اندازی استنتاج، سپس OpenClaw         | راه‌اندازی استنتاج، سپس OpenClaw |
| **مناسب برای**   | سرورها، محیط‌های بدون رابط گرافیکی، کنترل کامل        | رایانه رومیزی Mac، راه‌اندازی بصری      |
| **خودکارسازی** | `--non-interactive` برای اسکریپت‌ها        | فقط دستی                    |
| **فرمان**    | `openclaw onboard`                     | اجرای برنامه                 |

بیشتر کاربران باید با **راه‌اندازی اولیه CLI** شروع کنند — این روش همه‌جا کار می‌کند و
بیشترین کنترل را در اختیارتان می‌گذارد.

## مواردی که راه‌اندازی اولیه پیکربندی می‌کند

مرحله هدایت‌شده استنتاج فقط موارد زیر را برقرار می‌کند:

1. **ارائه‌دهنده مدل و احراز هویت** — دسترسی شناسایی‌شده یا ورود تأییدشده به ارائه‌دهنده،
   کلید API یا توکن
2. **استنتاج تأییدشده** — یک تکمیل واقعی روی مدل مؤثر
   عامل پیش‌فرض

پس از موفقیت آن تکمیل، OpenClaw می‌تواند فضای کاری، Gateway،
سرویس Gateway، کانال‌ها، عامل‌ها، Pluginها و دیگر قابلیت‌های اختیاری را پیکربندی کند.

جادوگر کلاسیک CLI می‌تواند موارد زیر را نیز پیکربندی کند:

1. **کانال‌ها** (اختیاری) — کانال‌های گفت‌وگوی داخلی و همراه، مانند
   Discord، Feishu، Google Chat، iMessage، Mattermost، Microsoft Teams،
   Telegram، WhatsApp و موارد دیگر
2. **کنترل‌های پیشرفته Gateway** — حالت راه دور، تنظیمات شبکه و گزینه‌های دیمن

## راه‌اندازی اولیه CLI

در هر ترمینالی اجرا کنید:

```bash
openclaw onboard
```

جریان هدایت‌شده دسترسی موجود به هوش مصنوعی را شناسایی می‌کند، گزینه‌ها را به‌ترتیب به‌صورت زنده
آزمایش می‌کند و در صورت شکست به گزینه بعدی می‌رود. اگر همه گزینه‌های شناسایی‌شده تمام شوند، ابتدا OpenAI،
Anthropic، xAI (Grok)، Google و OpenRouter را نمایش می‌دهد. **More…** شامل
سایر ارائه‌دهندگان در گروه‌های ارائه‌دهنده است و مناطق، طرح‌ها و روش‌های پشتیبانی‌شده
مرورگر، دستگاه، کلید API یا توکن را در منوی دوم نشان می‌دهد. مدل
و اعتبارنامه را تنها پس از موفقیت یک تکمیل ذخیره می‌کند، سپس OpenClaw را برای
پیکربندی فضای کاری، Gateway، کانال‌ها، عامل‌ها، Pluginها و دیگر قابلیت‌های اختیاری
اجرا می‌کند. **Skip for now** بدون اجرای OpenClaw خارج می‌شود. انتقال درون‌جریانی
به حالت کلاسیک وجود ندارد؛ اگر به‌جای آن جادوگر کلاسیک را می‌خواهید، خارج شوید و
`openclaw onboard --classic` را اجرا کنید.

پس از موفقیت استنتاج، OpenClaw می‌تواند راه‌اندازی کانال را به یک جادوگر ترمینالی
با ورودی پوشیده واگذار کند. این جادوگر راه‌اندازی هدایت‌شده یا کلاسیک ارائه‌دهنده را باز نمی‌کند؛ برای
تغییر ارائه‌دهنده مدل یا احراز هویت آن، از OpenClaw خارج شوید و
`openclaw onboard` را اجرا کنید.

برای راه‌اندازی دقیق مدل/احراز هویت، کانال، Skill،
Gateway راه دور یا واردسازی، از `openclaw onboard --classic` استفاده کنید. افزودن `--install-daemon` همچنین
جریان کلاسیک را انتخاب می‌کند و سرویس پس‌زمینه را در یک مرحله نصب می‌کند. برای راه‌اندازی مکالمه‌ای و ترمیم موارد غیرمرتبط با استنتاج، از `openclaw
openclaw` استفاده کنید. `openclaw
onboard --modern` یک نام مستعار سازگاری است که از همان
دروازه استنتاج زنده استفاده می‌کند.

## راه‌اندازی اولیه برنامه macOS

برنامه OpenClaw را باز کنید. اگر Gateway محلی یا راه دور پیکربندی‌شده آن در دسترس باشد
و عامل پیش‌فرض از قبل مدل پیکربندی‌شده‌ای داشته باشد، برنامه راه‌اندازی اولیه
و OpenClaw را رد می‌کند و بلافاصله رابط کاربری عادی عامل را باز می‌کند.

برای یک Gateway تازه یا ناقص، جریان اجرای نخست دسترسی موجود به هوش مصنوعی
(Claude Code، Codex یا کلیدهای API) را شناسایی می‌کند، بهترین
گزینه را به‌صورت زنده آزمایش می‌کند و تنها پس از دریافت پاسخی واقعی آن را ذخیره می‌کند — در صورت نیاز به‌طور خودکار
به گزینه جایگزین می‌رود و وقتی چیزی پیدا نشود، مرحله دستی تأییدشده‌ای برای کلید API
ارائه می‌دهد. برای اعتبارنامه‌های حساس از ورودی پوشیده استفاده می‌شود. پس از موفقیت استنتاج،
OpenClaw اجرا می‌شود و به پیکربندی سایر موارد کمک می‌کند.

Gemini CLI پس از راه‌اندازی برای عامل‌های عادی همچنان در دسترس است، اما برای این
دروازه استنتاج ارائه نمی‌شود، زیرا نمی‌تواند کاوش بدون ابزار را اجباری کند.

مرجع کامل: [راه‌اندازی اولیه (برنامه macOS)](/fa/start/onboarding)

## ارائه‌دهندگان سفارشی یا فهرست‌نشده

اگر ارائه‌دهنده شما در فهرست نیست، `openclaw onboard --classic` را اجرا کنید، گزینه
**Custom Provider** را انتخاب کنید و موارد زیر را وارد کنید:

- سازگاری نقطه پایانی: سازگار با OpenAI ‏(`/chat/completions`)، سازگار با OpenAI Responses ‏(`/responses`)، سازگار با Anthropic ‏(`/messages`) یا ناشناخته (هر سه را کاوش و به‌طور خودکار شناسایی می‌کند)
- نشانی پایه و کلید API (اگر نقطه پایانی به کلید نیاز نداشته باشد، کلید API اختیاری است)
- شناسه مدل و نام مستعار اختیاری مدل

چند نقطه پایانی سفارشی می‌توانند هم‌زمان وجود داشته باشند — هرکدام شناسه نقطه پایانی مخصوص خود را دریافت می‌کند.
