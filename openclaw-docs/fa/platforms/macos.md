برنامهٔ macOS، **همراه نوار منوی** OpenClaw است: رابط کاربری بومی نوار وضعیت، درخواست‌های مجوز macOS، اعلان‌ها، WebChat، ورودی صوتی، Canvas و
ابزارهای Node میزبانی‌شده روی Mac مانند `system.run`.

برای نوشتن پیام در نشست اصلی به سبک Spotlight، بدون باز کردن یک پنجرهٔ کامل، از **گفت‌وگوی سریع** استفاده کنید. به‌طور پیش‌فرض Option-Space (⌥Space) را فشار دهید، آن را از منوی نوار منو انتخاب کنید، یا میان‌بر دیگری را در **تنظیمات ← عمومی** ثبت کنید.

فقط به CLI و Gateway نیاز دارید؟ از [شروع به کار](/fa/start/getting-started) آغاز کنید.

## دانلود

ساخت‌های برنامهٔ macOS را از [انتشارهای GitHub مربوط به OpenClaw](https://github.com/openclaw/openclaw/releases) دریافت کنید.
وقتی یک انتشار شامل فایل‌های برنامهٔ macOS است، به‌دنبال این موارد بگردید:

- `OpenClaw-<version>.dmg` (ترجیحی)
- `OpenClaw-<version>.zip`

برخی انتشارها فقط شامل CLI، شواهد یا فایل‌های Windows هستند. اگر جدیدترین انتشار
فایل برنامهٔ macOS ندارد، از جدیدترین انتشاری که آن را دارد استفاده کنید، یا با
[راه‌اندازی محیط توسعهٔ macOS](/fa/platforms/mac/dev-setup) از کد منبع بسازید.

## نخستین اجرا

1. **OpenClaw.app** را نصب و اجرا کنید.
2. برای یک Gateway محلی، **این Mac** را انتخاب کنید یا به یک Gateway راه دور متصل شوید.
3. منتظر بمانید تا برنامه محیط اجرایی CLI منطبق را نصب کند. در حالت محلی، برنامه همچنین
   Gateway را نصب و راه‌اندازی می‌کند.
4. با بررسی زندهٔ یک مدل، استنتاج را برقرار کنید. پس از موفقیت بررسی، OpenClaw
   ادامهٔ راه‌اندازی را انجام می‌دهد.
5. چک‌لیست مجوزهای macOS را تکمیل و پیام آزمایشی آغاز به کار را ارسال کنید.

اگر برنامه به یک Gateway موجود برسد که عامل پیش‌فرض آن دارای مدل
پیکربندی‌شده است، آن Gateway را از پیش راه‌اندازی‌شده در نظر می‌گیرد، از آغاز به کار ارائه‌دهنده و
OpenClaw عبور می‌کند و داشبورد را باز می‌کند. اگر اتصال به Gateway ممکن نباشد یا
عامل پیش‌فرض آن مدلی نداشته باشد، آغاز به کار استنتاج برای
بازیابی همچنان در دسترس می‌ماند.

برای مسیر راه‌اندازی CLI/Gateway، از [شروع به کار](/fa/start/getting-started) استفاده کنید.
برای بازیابی مجوزها، از [مجوزهای macOS](/fa/platforms/mac/permissions) استفاده کنید.

## به‌روزرسانی‌ها

کارت به‌روزرسانی داشبورد مشخص می‌کند برنامه چه چیزی را به‌روزرسانی خواهد کرد:

- **به‌روزرسانی برنامهٔ Mac و Gateway** یعنی برنامهٔ امضاشده مالک Gateway محلی
  مبتنی بر launchd است. Sparkle ابتدا برنامه را به‌روزرسانی می‌کند؛ پس از اجرای مجدد، برنامه به‌طور خودکار
  Gateway خود را به نسخهٔ منطبق به‌روزرسانی و مجدداً راه‌اندازی می‌کند و سپس
  اتصال را تأیید می‌کند.
- **به‌روزرسانی Gateway** یعنی برنامه به یک Gateway راه دور، یک Gateway محلی با
  مدیریت دستی یا نصب دیگری که برنامه مالک آن نیست متصل است. این دکمه
  به‌جای تغییر برنامهٔ Mac، جریان معمول به‌روزرسانی آن Gateway را اجرا می‌کند.

به‌روزرسانی هماهنگ ناموفق در پنجرهٔ راه‌اندازی‌مانند خود باقی می‌ماند و گزینه‌های تلاش مجدد،
[راهنمای به‌روزرسانی](/fa/install/updating) و Discord را ارائه می‌دهد. تعمیر خودکار هرگز
نسخهٔ یک Gateway جدیدتر را کاهش نمی‌دهد یا پین کانال `extended-stable` را لغو نمی‌کند.

پس از به‌روزرسانی موفق، برنامه جدیدترین نشست مستقیم سطح‌بالا را که اخیراً یک انسان از آن استفاده کرده است
پیدا می‌کند و یک رویداد یک‌بارهٔ به‌روزرسانی به آن عامل می‌دهد. فعالیت Heartbeat
و cron بر این انتخاب تأثیری ندارد. سپس عامل می‌تواند از همان گفت‌وگویی که به‌احتمال زیاد
استفاده می‌کردید، به شما خوشامد بگوید. در حالت راه دور، برنامه
فقط محیط اجرایی Node محلی Mac را به‌روزرسانی می‌کند و اگر
Gateway راه دور قدیمی‌تر از برنامه باشد، اعلان را نادیده می‌گیرد.

Sparkle از تنظیم `update.channel` در Gateway پیروی می‌کند. `beta` و `dev` استفاده
از ساخت‌های بتای برنامه را فعال می‌کنند؛ `stable`، `extended-stable` و مقادیر ناموجود یا ناشناخته
روی ساخت‌های پایدار برنامه باقی می‌مانند.

## باز کردن پیوندهای داشبورد

در داشبورد تعبیه‌شدهٔ برنامهٔ macOS، کلیک روی یک پیوند وب خارجی، آن را در نوار کناری مرورگری با اندازهٔ قابل تغییر و نصف عرض پنجره باز می‌کند و پیمایش داشبورد را قابل مشاهده نگه می‌دارد. برای انتخاب عرضی دیگر، جداکننده را بکشید؛ برنامه آن را به خاطر می‌سپارد. هر پیوند در زبانهٔ خودش باز می‌شود، نوار زبانه‌ها هنگام باز بودن چند صفحه ظاهر می‌شود و کلیک دوباره روی همان پیوند از زبانهٔ موجود آن استفاده می‌کند. برای تغییر ترتیب زبانه‌ها آن‌ها را بکشید، با دکمهٔ بستن زبانه یا کلیک میانی ببندید و برای گزینه‌های **باز کردن در مرورگر پیش‌فرض**، **کپی پیوند**، **بارگذاری مجدد**، **بستن زبانه** و **بستن سایر زبانه‌ها** روی زبانه راست‌کلیک کنید. کنترل‌های عقب/جلو در نوار عنوان پنجره و کشیدن انگشت روی ترک‌پد در تاریخچهٔ داشبورد پیمایش می‌کنند؛ کنترل‌های عقب/جلوی خود نوار کناری در تاریخچهٔ زبانهٔ فعال پیمایش می‌کنند. نوار کناری همچنین کنترل‌های بارگذاری مجدد، باز کردن در مرورگر پیش‌فرض و بستن را دارد.

کنترل‌های نوار عنوان از نوار کناری برنامه پیروی می‌کنند: وقتی باز است، کنترل‌های عقب/جلو در لبهٔ راست آن و کنار دکمهٔ تغییر وضعیت نوار کناری قرار می‌گیرند؛ وقتی جمع شده است، جای خود را به یک دکمهٔ جست‌وجو (که پالت فرمان را باز می‌کند) و یک دکمهٔ نشست جدید می‌دهند.

برای انتخاب **باز کردن در نوار کناری**، **باز کردن در مرورگر پیش‌فرض** یا **کپی پیوند** روی یک پیوند خارجی راست‌کلیک کنید. کلیک‌های تغییریافته و پیوندهای پنجرهٔ جدید فعال‌شده توسط کاربر در داشبورد همچنان در مرورگر پیش‌فرض باز می‌شوند؛ پیوندهای پنجرهٔ جدید درون نوار کناری به‌صورت زبانه‌های جدید نوار کناری باز می‌شوند. صفحات معمول رابط کاربری کنترل که در مرورگر میزبانی می‌شوند، رفتار عادی مرورگر برای پیوندها و منوی زمینه را حفظ می‌کنند.

## وارد کردن ورودهای مرورگر

نخستین بار که نوار کناری مرورگر هنگام اجرای برنامه با یک Gateway محلی باز می‌شود، اگر نمایه‌ای از خانوادهٔ Chrome دارای کوکی روی Mac وجود داشته باشد، داشبورد یک بنر قابل بستن نمایش می‌دهد. این بنر امکان کپی‌کردن آن کوکی‌ها را به یک نمایهٔ مدیریت‌شده و ایزوله که عامل‌ها برای مرور استفاده می‌کنند فراهم می‌کند. یک نمایه را از کنترل **وارد کردن** آن انتخاب کنید (ممکن است Touch ID لازم باشد)؛ پیشرفت و تعداد کوکی‌های واردشده در همان‌جا ظاهر می‌شوند و فقط کوکی‌ها کپی می‌شوند — گذرواژه‌ها هرگز مرورگر مبدأ را ترک نمی‌کنند. بستن بنر این انتخاب را ثبت می‌کند؛ **تنظیمات ← عمومی ← ورود مرورگر ← وارد کردن…** در هر زمان دوباره آن را ارائه می‌دهد. برای جریان زیربنایی وارد کردن و دروازهٔ `browser.allowSystemProfileImport`، به [مرورگر](/fa/cli/browser) مراجعه کنید.

| ------ | ------------------------------------------------------------------------------ | -------------------------------------------------- |
| محلی  | این Mac باید Gateway را اجرا کند و با launchd فعال نگه دارد.                | [Gateway در macOS](/fa/platforms/mac/bundled-gateway) |
| راه دور | میزبان دیگری Gateway را اجرا می‌کند؛ این Mac آن را از طریق SSH، شبکهٔ محلی یا Tailnet کنترل می‌کند. | [کنترل از راه دور](/fa/platforms/mac/remote)            |

هر دو حالت به یک CLI نصب‌شدهٔ `openclaw` نیاز دارند، زیرا برنامه از محیط اجرایی
میزبان Node آن دوباره استفاده می‌کند. روی یک Mac تازه، برنامه CLI منطبق را به‌طور خودکار نصب می‌کند؛ سپس حالت
محلی جادوگر Gateway را راه‌اندازی می‌کند، درحالی‌که حالت راه دور بدون راه‌اندازی
یک Gateway محلی دوم به Gateway انتخاب‌شده متصل می‌شود.
برای بازیابی دستی، به [Gateway در macOS](/fa/platforms/mac/bundled-gateway) مراجعه کنید.

## آنچه برنامه مدیریت می‌کند

- وضعیت نوار منو، اعلان‌ها، سلامت، WebChat و نوار شناور گفت‌وگوی سریع.
- درخواست‌های مجوز macOS برای صفحه‌نمایش، میکروفون، گفتار، خودکارسازی و دسترس‌پذیری.
- یک Node مک که Canvas بومی، ثبت دوربین/صفحه‌نمایش، اعلان‌ها،
  موقعیت مکانی و کنترل رایانه را با فرمان‌های سیستم، مرورگر،
  Plugin، Skills و MCP میزبان Node مربوط به CLI ترکیب می‌کند.
- درخواست‌های تأیید اجرا برای فرمان‌های میزبانی‌شده روی Mac.
- اجرای فرمان‌های پوستهٔ تأییدشده در زمینهٔ برنامه، با حفظ انتساب مجوزهای macOS
  به برنامه، درحالی‌که محیط اجرایی CLI مالک خط‌مشی مشترک Node است.
- تونل‌های SSH در حالت راه دور یا اتصال‌های مستقیم Gateway.

در رابط کاربری کنترل تعبیه‌شده، **تنظیمات ← اعلان‌ها** به‌جای اعلان‌های فشاری مرورگر،
مجوز بومی اعلان برنامه را نشان می‌دهد، زیرا برنامه اعلان‌ها را به‌صورت بومی تحویل می‌دهد.

برنامه جایگزین مستندات Gateway یا CLI عمومی **نمی‌شود**. پیکربندی Gateway،
ارائه‌دهندگان، Pluginها، کانال‌ها، ابزارها و امنیت در مستندات
مختص خودشان قرار دارند.
