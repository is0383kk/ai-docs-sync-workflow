# 組織與命名空間權利主張

ClawHub 將擁有者代號、組織代號、Skill slug、外掛套件名稱和
套件 scope 作為公開命名空間。如果命名空間看似屬於現實世界中的
專案、品牌、套件生態系統或組織，但已在 ClawHub 上遭到
占用、保留、誤導性使用或產生爭議，請透過
[組織／命名空間權利主張議題表單](https://github.com/openclaw/clawhub/issues/new?template=org-namespace-claim.yml)
要求工作人員審查。

此管道適用於公開且不涉及敏感資訊的所有權審查。請勿使用產品內
檢舉功能或帳號申訴表單提出命名空間權利主張。

## 何時提出權利主張

如果你認為 ClawHub 工作人員應根據現實世界中的所有權，審查某個
命名空間是否應予保留、移轉、重新命名、隱藏、隔離、設定別名或
進行其他變更，請提出命名空間權利主張。

例如：

- 與你的 GitHub 組織、專案、公司或社群相符的組織代號
- 像是 `@example-org/*` 這類應僅能由相符 ClawHub 擁有者發布的套件 scope
- 看似冒充某個專案的 Skill slug 或外掛套件名稱
- 品牌、商標、專案重新命名或套件歷史爭議
- 已刪除、停用或無法聯絡，因而阻礙合法命名空間擁有者的擁有者

如果該項目除了所有權爭議外，還有不安全、惡意或誤導的情況，
也請遵循相關的內容審核或安全性指引。命名空間權利主張表單用於
所有權審查，而非緊急漏洞揭露。

## 提交前準備

請先確認你用於發布的擁有者與命名空間相符。
對於外掛套件，像是 `@example-org/example-plugin` 這類帶 scope 的名稱，必須
以相符的 `example-org` 擁有者發布。

如果你可以管理目前的擁有者，請透過發布、重新命名、移轉、隱藏
或刪除受影響的資源，直接修正命名空間。如果你無法管理目前的
擁有者，或需要工作人員解決爭議，請提出權利主張。

## 應附上的證據

請使用公開且不涉及敏感資訊的證據。實用的證明包括：

- GitHub 組織、儲存庫、版本發布或維護者歷史
- 明確提及該命名空間的官方專案文件
- 網域或官方電子郵件網域的證明
- 對 npm、PyPI、crates.io 或其他套件註冊表 scope 的控制權
- 可安全公開討論的商標、品牌或專案所有權證據
- 原始碼儲存庫歷史、套件歷史或公開的重新命名公告
- 爭議所涉及的 ClawHub 擁有者、Skill、外掛、套件或議題連結

請說明每個連結能證明什麼。工作人員應能在不需要私密認證資訊或
密鑰的情況下理解其中的關聯。

## 不應包含的內容

請勿在公開的 GitHub 議題中放入密鑰或私密證明。請勿包含：

- API 權杖、簽署金鑰或認證資訊
- DNS 驗證權杖
- 非公開的法律文件或合約
- 個人身分證明文件
- 私人電子郵件、非公開的安全性報告或機密客戶資料

權利主張表單會詢問敏感證據是否需要透過工作人員的私密管道提交。
請選擇該選項，而不要公開發布敏感資料。

## 可能的處理結果

ClawHub 工作人員可能會根據證據和風險，保留命名空間、移轉所有權、
重新命名資源、隱藏或隔離現有項目、新增別名或重新導向、要求提供
更多證明，或拒絕申請。

命名空間審查不保證每個相符名稱都會移轉。工作人員會衡量公開證據、
現有使用情況、安全風險和使用者影響。
