# `openclaw worker`

`openclaw worker` 是供雲端工作程序協調器在已準備的工作程序環境中啟動的受限執行階段進入點。它並非用於手動註冊工作程序的通用命令。

閘道會安裝相符的 OpenClaw 套件，並開啟固定主機金鑰的反向 SSH 通道。工作程序啟動器會使用已準備的指派啟動此命令。此命令會透過由通道轉送的本機通訊端連線，並以專用的 `worker` 角色准入。

## 啟動合約

此命令會從標準輸入讀取恰好一個有大小限制的 JSON 啟動封套。封套包含本機通訊端位置、簽發的工作程序認證資訊、套件與通訊協定識別資訊、擁有者 epoch、唯一指派的工作階段與輪次，以及該輪次獲授權的確切工作程序本機工具名稱。閘道會在交接前依據目前政策解析這個最終工具集；原始設定與排程擁有者的身分絕不會進入工作程序封套。
認證資訊絕不接受透過命令列引數傳入，而本頁刻意不提供認證資訊或手動撰寫的封套範例。

如果封套無效、認證資訊遭拒、套件或通訊協定功能不相符，或工作階段與擁有者 epoch 已不再是最新狀態，准入便會以封閉方式失敗。缺少、重複或未知的工具名稱也會使封套失效。操作人員應透過雲端工作程序協調器啟動工作程序，而非直接叫用此進入點。

## 執行階段邊界

此程序會使用受限後端執行一般的嵌入式代理程式迴圈：

- `read`、`write`、`edit`、`apply_patch`、`exec` 和 `process` 程式設計工具
  若存在於閘道簽發的輪次權限中，便會在工作程序工作區中於本機執行。權限為空時，模型不會使用任何工具。
- 模型呼叫會使用閘道推論代理。不會載入本機模型驗證設定檔。
- 逐字稿寫入會使用閘道逐字稿提交 RPC。
- 串流與工具生命週期更新會使用閘道即時事件 RPC。
- 僅接受已指派的工作階段與輪次。

除了已指派工作階段的工具集之外，工作程序模式不會啟動頻道、閘道 HTTP 介面或外掛自動啟動功能。它會使用拋棄式狀態目錄，且不持有任何常駐的供應商或程式碼託管平台認證資訊。

此模式不會公開工作程序對工作程序的工作階段分派。配置與分派仍由閘道擁有：操作人員可以透過閘道分派既有的本機受管理工作樹工作階段，但工作程序程序無法分派自身或其他工作程序。

已準備的指派包含逐字稿內容、已接受的基礎葉節點、提交序列與即時事件游標。通道重新連線時，程序會使用相同的認證資訊與擁有者 epoch 重新准入、保留已接受的逐字稿基礎、重播其尚未確認的即時事件尾端，並使用相同識別資訊重新附加正在進行的推論輪次。若遺漏了串流增量，則以終止推論訊息為準。取代現有擁有者的 epoch 會隔離此程序，並使其正常結束。

`stale-base-leaf` 逐字稿拒絕會使目前的執行立即停止。工作程序模式不會針對不同的葉節點重試遭拒的序列，因此不會產生重複提交；該次執行中仍未提交、僅存在記憶體內的任何尾端資料都會遺失。重新啟動由里程碑 3 的配置擁有者負責；該擁有者必須根據閘道的權威逐字稿與提交分類帳建立全新的指派。同樣地，閘道程序重新啟動會以供應商錯誤終止待處理的推論輪次；只有通道或工作程序 WebSocket 重新連線，才能重新附加至仍在同一程序中作用中的推論串流。

如需了解封閉式工作程序 RPC 介面，請參閱[閘道通訊協定](/zh-TW/gateway/protocol#worker-role-and-closed-protocol)；如需了解架構與安全模型，請參閱[雲端工作程序計畫](/zh-TW/plan/cloud-workers)。
