本頁記錄 2026 年 5 月 OpenClaw 效能、套件大小、相依性及 shrinkwrap 清理背後的證據。這是公開部落格文章的技術補充資料。

此處合併了兩項稽核：

- **發行版效能掃描：**從 `v2026.5.28` 往回至穩定版 `v2026.4.23` 的 GitHub Releases，使用 `OpenClaw Performance` 工作流程、`profile=smoke`、模擬提供者執行環境。大多數標籤列為單次樣本；`v2026.5.27` 與 `v2026.5.28` 列使用最新的重複 3 次發行分支成品。
- **較早的 4 月背景資料：**從 `v2026.4.1` 到 `v2026.5.2` 已發布的 `clawgrit-reports` 模擬提供者基準，僅用於避免將 4 月下旬損壞的發行版視為公開效能基準。
- **安裝佔用空間掃描：**將 `npm install --ignore-scripts` 全新安裝至暫存套件，使用 `du -sk node_modules` 計算大小，並以 `node_modules` 遍歷計算套件實例數量。
- **npm 套件大小掃描：**針對已發布的版本執行 `npm pack openclaw@<version> --dry-run --json`，記錄壓縮 tarball 大小、解壓縮後大小及檔案數量。

<Warning>
主要效能掃描對每個標籤使用一個冒煙測試樣本，但 `v2026.5.27` 與 `v2026.5.28` 列使用最新的重複 3 次發行分支成品。較早的 4 月背景資料使用 `clawgrit-reports` 已發布的重複 3 次中位數。請將這些數字視為趨勢證據及尋找迴歸的訊號，而非發行閘門統計資料。
</Warning>

### Shrinkwrap 分界點

`2026.5.20` 發布時沒有根層 shrinkwrap，也沒有大型巢狀 OpenClaw
相依套件樹。`2026.5.22` 導入根層 shrinkwrap，並在巢狀
`openclaw/node_modules` 下安裝了 911.8MB。`2026.5.28` 保留 shrinkwrap，且仍在
巢狀 `openclaw/node_modules` 下安裝 259.7MiB，但本機全新安裝稽核中已不再安裝
任何 `@napi-rs/canvas` 套件。

檢查已發布的 tarball 可驗證此分界點：

| 版本     | 已發布為穩定版？ | 根層 `npm-shrinkwrap.json` | 備註                                 |
| ----------- | ----------------- | -------------------------- | ------------------------------------- |
| `2026.5.20` | 是               | 否                         | 導入 shrinkwrap 前的最後一個穩定版本 |
| `2026.5.21` | 否                | 不適用                        | 沒有穩定的 npm 版本                 |
| `2026.5.22` | 是               | 是                        | 導入 shrinkwrap                 |
| `2026.5.23` | 否                | 不適用                        | 沒有穩定的 npm 版本                 |
| `2026.5.24` | 否                | 不適用                        | 沒有穩定的 npm 版本                 |
| `2026.5.25` | 否                | 不適用                        | 沒有穩定的 npm 版本                 |
| `2026.5.26` | 是               | 是                        | 巢狀相依套件樹仍然存在  |
| `2026.5.27` | 是               | 是                        | 巢狀相依套件樹仍然存在  |
| `2026.5.28` | 是               | 是                        | 巢狀相依套件樹已大幅縮小   |

重要區別是：**shrinkwrap 本身並不是問題**。
`v2026.5.28` 仍隨附根層 shrinkwrap。問題在於套件結構導致 npm 實體化
大型巢狀 OpenClaw 相依套件樹，以及全部 12 個 `@napi-rs/canvas` 平台套件。
`v2026.5.28` 中的巢狀樹較小，而 Canvas 平台的扇出套件也不再出現在
本機稽核中。

如需 shrinkwrap 的白話說明及維護者層級的套件檢查，請參閱
[npm shrinkwrap](/zh-TW/gateway/security/shrinkwrap)。

## 供應鏈解讀

相依套件數量是營運安全指標，不只是安裝大小指標。每個套件都會擴大
操作人員必須信任的維護者、tarball、遞移更新、選用原生二進位檔，以及
安裝時行為的範圍。

清理方向如下：

- 將大型及選用功能保留在預設核心安裝之外
- 讓外掛套件自行擁有其執行階段相依套件圖
- 避免在閘道啟動期間進行執行階段套件管理器修復
- 維持確定性安裝，同時避免實體化所有平台的原生套件
- 在套件驗收與測量流程中維持停用安裝指令碼
- 在發布前攔截巢狀相依套件樹與原生選用相依套件的爆增
