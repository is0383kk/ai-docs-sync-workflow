## 1. 範圍

| 元件                   | 納入範圍 | 備註                                             |
| ---------------------- | -------- | ------------------------------------------------ |
| OpenClaw 代理程式執行階段 | 是       | 核心代理程式執行、工具呼叫、工作階段             |
| 閘道                   | 是       | 驗證、路由、頻道整合                             |
| 頻道整合               | 是       | WhatsApp、Telegram、Discord、Signal、Slack 等    |
| ClawHub 市集           | 是       | 技能發布、審核、散布                             |
| MCP 伺服器             | 是       | 外部工具提供者                                   |
| 使用者裝置             | 部分     | 行動應用程式、桌面用戶端                         |

不在範圍內的回報與誤判模式（公開網際網路曝露、未繞過邊界且僅涉及提示注入的攻擊鏈、彼此不信任的操作者共用同一部閘道主機，以及其他情況）列於 [`SECURITY.md`](https://github.com/openclaw/openclaw/blob/main/SECURITY.md)；該檔案才是目前漏洞回報範圍的權威來源，而非本頁。

## 4. ClawHub 供應鏈分析

### 4.1 目前的安全性控制措施

| 控制措施                       | 實作方式                                                                                      | 有效性                                                       |
| ------------------------------ | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| GitHub 帳號年齡                | `requireGitHubAccountAge()`（至少 14 天）                                                              | 中等－提高新攻擊者的門檻                                     |
| 路徑清理                       | `sanitizePath()`                                                                            | 高－防止路徑遍歷                                             |
| 檔案類型驗證                   | `isTextFile()`                                                                            | 中等－僅掃描文字檔，但仍可能遭到利用                         |
| 大小限制                       | 套件組合總計 50MB（`MAX_PUBLISH_TOTAL_BYTES`）                                                       | 高－防止資源耗盡                                             |
| 必須提供 SKILL.md              | 發布時必須提供讀我檔案                                                                       | 安全價值低－僅供參考                                         |
| 靜態與 AST 相鄰掃描            | 模式引擎涵蓋執行、資料外洩、竊取認證資訊、混淆等行為                                         | 中高－涵蓋許多已知濫用模式，但仍以模式比對為基礎             |
| 基於 LLM 的代理式風險審查      | 發布時依安全提示詞做出判定                                                                   | 中高－可發現靜態模式未能識別的行為                           |
| VirusTotal 掃描                | 整合至 Skill 與套件版本的發布／重新掃描流程，並以操作者 API 金鑰為啟用條件                    | 啟用時為高－靜態引擎偵測                                     |
| 管理狀態                       | `moderationStatus` 欄位                                                                       | 中等－可進行人工審查                                         |

### 4.2 管理限制

ClawHub 的靜態掃描會直接檢查 Skill 程式碼內容（不僅是 slug／中繼資料／frontmatter），涵蓋危險的執行呼叫、動態程式碼執行、竊取認證資訊、資料外洩模式、混淆的酬載等。已知缺口：

- 以模式為基礎的偵測仍可能遭到足夠新穎的混淆技術規避。
- 基於 LLM 的審查與 VirusTotal 掃描，取決於是否已啟用操作者端的 API 金鑰／設定。
- Skill 安裝後，沒有執行階段沙箱能將其與代理程式本身的權限隔離。

### 4.3 徽章

Skills 與套件可獲得管理員指派的徽章：`highlighted`、`official`、`deprecated`、`redactionApproved`（僅限 Skills）。社群檢舉（`skillReports`）與稽核記錄（`auditLogs`）支援管理工作流程。
