`/btw`（別名 `/side`）可針對**目前的
工作階段**快速提出附帶問題，而不將其加入對話記錄。其設計參考
Claude Code 的 `/btw`，並針對 OpenClaw 的閘道與多頻道
架構進行調整。

```text
/btw 有哪些變更？
/side 這個錯誤是什麼意思？
```

## 功能

1. 將目前的工作階段建立快照，作為背景脈絡（包括任何
   執行中的主要執行提示）。
2. 執行獨立的一次性附帶查詢，指示模型僅回答附帶問題，
   不得繼續或引導主要任務。
3. 以即時附帶結果傳送答案，而非一般助理訊息。
4. 絕不將問題或答案寫入工作階段記錄或 `chat.history`。

如果主要執行正在進行，將不會受到任何影響。

對於 Codex 控制框架工作階段，BTW 會將作用中的 Codex app-server 執行緒
分叉成暫時的子執行緒，而不是另外發出供應商呼叫。這可保持 Codex OAuth
及原生工具／執行緒行為不變，而分叉的執行緒會保留父執行緒目前的核准
原則、沙箱及原生工具介面。分叉的執行緒會收到邊界提示，告知模型邊界
之前的所有內容都是繼承的參考脈絡，而非作用中的指示，且只有邊界之後
的訊息才是即時訊息。`/btw` 需要現有的 Codex 執行緒；請先傳送
一般訊息。

對於命令列介面執行階段別名，BTW 會以一次性附帶問題模式叫用其所屬的
命令列介面後端：將經過清理的對話脈絡植入全新的命令列介面叫用、停用
工具綑綁及可重複使用的工作階段狀態，並加入後端支援的任何禁止繼續／
禁止工具旗標。直接（非命令列介面）執行階段則改用直接的一次性供應商
呼叫。

## 不會執行的操作

`/btw` 不會建立持久工作階段、繼續未完成的主要任務、
將問題／答案資料保存至文字記錄，或在重新載入後繼續存在。

## 傳送模型

一般助理聊天使用閘道的 `chat` 事件。BTW 使用獨立的
`chat.side_result` 事件，因此用戶端不會將其誤認為一般
對話記錄。由於不會從 `chat.history` 重播，因此會在重新載入後
消失。

## 各介面行為

| 介面              | 行為                                                                                                                                                                                                                                                                                |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 終端介面          | 以行內方式顯示於聊天記錄中，外觀與一般回覆明顯不同，並可使用 `Enter` 或 `Esc` 關閉。                                                                                                                                                                         |
| 外部頻道          | 以清楚標示的一次性回覆傳送（Telegram、WhatsApp、Discord 沒有本機暫時浮層）。                                                                                                                                                                                                        |
| 控制介面／網頁    | 顯示為固定於執行緒的浮動「附帶聊天」面板。答案會逐輪累積，而「後續提問」輸入框可提出下一個附帶問題。關閉（`Esc` 或 X）會保留對話，並在下一個答案出現時重新開啟；垃圾桶按鈕會捨棄對話並停止待處理的執行。 |

## 選取快顯視窗（控制介面）

在控制介面的聊天訊息中反白文字時，會開啟包含兩個動作的小型
選取快顯視窗：

- **更多詳細資料**會立即傳送隱含的 `/btw` 問題，要求
  模型根據目前工作階段的脈絡解釋反白文字。答案會顯示於浮動的
  附帶聊天面板中。
- **在附帶聊天中提問**會在撰寫框中預先填入 `/btw` 草稿，
  引用反白文字，讓你可以輸入自己的相關問題。

這兩個動作都遵循一般的 `/btw` 語意：問題與答案不會進入
工作階段記錄，且主要執行不會受到影響。

## 適用時機

可使用 `/btw` 快速釐清事項、在長時間執行仍在進行時取得
事實性附帶答案，或取得不應進入未來工作階段脈絡的暫時答案。

```text
/btw 我們正在編輯哪個檔案？
/btw 用一句話摘要目前的任務
/btw 17 * 19 是多少？
```

對於任何希望成為工作階段未來工作脈絡一部分的內容，請改為在主要
工作階段中正常提問。
