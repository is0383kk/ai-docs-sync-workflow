# `openclaw configure`

मौजूदा सेटअप में लक्षित बदलावों के लिए इंटरैक्टिव प्रॉम्प्ट: क्रेडेंशियल, डिवाइस, एजेंट डिफ़ॉल्ट, Gateway, चैनल, plugins, Skills और स्वास्थ्य जाँच।

पूरी निर्देशित प्रथम-रन प्रक्रिया के लिए `openclaw onboard` या `openclaw setup`, केवल आधारभूत कॉन्फ़िगरेशन/वर्कस्पेस के लिए `openclaw setup --baseline`, और केवल चैनल अकाउंट सेटअप की आवश्यकता होने पर `openclaw channels add` का उपयोग करें।

<Tip>
बिना किसी उपकमांड के `openclaw config` वही विज़ार्ड खोलता है। गैर-इंटरैक्टिव संपादनों के लिए `openclaw config get|set|unset` का उपयोग करें।
</Tip>

## विकल्प

`--section <section>`: दोहराया जा सकने वाला सेक्शन फ़िल्टर। उपलब्ध सेक्शन:

`workspace`, `model`, `web`, `gateway`, `daemon`, `channels`, `plugins`, `skills`, `health`

```bash
openclaw configure
openclaw configure --section web
openclaw configure --section model --section channels
openclaw configure --section gateway --section daemon
```

`gateway`, `daemon`, या `health` चुनने पर (या बिना `--section` के पूरा विज़ार्ड चलाने पर) यह पूछा जाता है कि Gateway कहाँ चलता है और `gateway.mode` को अपडेट किया जाता है। जो सेक्शन फ़िल्टर इन तीनों को छोड़ देते हैं, वे Gateway मोड का प्रॉम्प्ट दिखाए बिना सीधे अनुरोधित सेटअप पर जाते हैं। रिमोट Gateway मोड चुनने पर रिमोट कॉन्फ़िगरेशन लिखा जाता है और प्रक्रिया तुरंत समाप्त हो जाती है; यह plugin इंस्टॉलेशन जैसे केवल-लोकल चरण नहीं चलाता।

<Note>
`openclaw configure` के लिए इंटरैक्टिव टर्मिनल आवश्यक है (stdin और stdout, दोनों TTY होने चाहिए)। इसके बिना, यह आंशिक रूप से चलने के बजाय समतुल्य गैर-इंटरैक्टिव `openclaw config get|set|patch|validate` कमांड प्रिंट करता है और त्रुटि के साथ बाहर निकल जाता है।
</Note>

## मॉडल सेक्शन

<Note>
**मॉडल** में स्पष्ट `agents.defaults.modelPolicy.allow` सूची के लिए बहु-चयन शामिल है (जो `/model` और मॉडल पिकर में दिखाई देता है)। प्रदाता-सीमित सेटअप विकल्प अपने चुने हुए मॉडलों को मौजूदा सूची में मर्ज करते हैं, न कि कॉन्फ़िगरेशन में पहले से मौजूद असंबंधित प्रदाताओं को प्रतिस्थापित करते हैं। प्रत्येक मॉडल के उपनाम और पैरामीटर `agents.defaults.models` के अंतर्गत बने रहते हैं; वे प्रविष्टियाँ अपने आप मॉडल ओवरराइड को सीमित नहीं करतीं।

configure से प्रदाता प्रमाणीकरण दोबारा चलाने पर मौजूदा `agents.defaults.model.primary` सुरक्षित रहता है, भले ही प्रदाता का प्रमाणीकरण चरण अपने अनुशंसित डिफ़ॉल्ट मॉडल वाला कॉन्फ़िगरेशन पैच लौटाए। किसी प्रदाता को जोड़ने या उसका पुनः प्रमाणीकरण करने पर उसके मॉडल उपलब्ध हो जाते हैं, लेकिन वे आपके वर्तमान प्राथमिक मॉडल का स्थान नहीं लेते। डिफ़ॉल्ट मॉडल जानबूझकर बदलने के लिए `openclaw models auth login --provider <id> --set-default` या `openclaw models set <model>` का उपयोग करें।
</Note>

जब configure किसी प्रदाता प्रमाणीकरण विकल्प से शुरू होता है, तो डिफ़ॉल्ट-मॉडल और मॉडल-नीति पिकर अपने आप उस प्रदाता को प्राथमिकता देते हैं। Volcengine और BytePlus जैसे युग्मित प्रदाताओं के लिए यही प्राथमिकता उनके कोडिंग-प्लान प्रकारों (`volcengine-plan/*`, `byteplus-plan/*`) से भी मेल खाती है। यदि पसंदीदा-प्रदाता फ़िल्टर से सूची खाली हो जाती, तो configure रिक्त पिकर दिखाने के बजाय बिना फ़िल्टर वाली कैटलॉग पर वापस लौटता है।

## वेब सेक्शन

`openclaw configure --section web` वेब-सर्च प्रदाता चुनता है और उसके क्रेडेंशियल कॉन्फ़िगर करता है। कुछ प्रदाता, प्रदाता-विशिष्ट अनुवर्ती विकल्प दिखाते हैं:

- **Grok** उसी xAI OAuth प्रोफ़ाइल या API कुंजी के साथ वैकल्पिक `x_search` सेटअप की पेशकश कर सकता है और आपको `x_search` मॉडल चुनने दे सकता है।
- **Kimi** Moonshot API क्षेत्र (`api.moonshot.ai` बनाम `api.moonshot.cn`) और डिफ़ॉल्ट Kimi वेब-सर्च मॉडल पूछ सकता है।

## अन्य टिप्पणियाँ

- लोकल कॉन्फ़िगरेशन लिखे जाने के बाद, चुने गए सेटअप पथ को आवश्यकता होने पर configure चयनित डाउनलोड किए जा सकने वाले plugins इंस्टॉल करता है। रिमोट Gateway कॉन्फ़िगरेशन लोकल plugin पैकेज इंस्टॉल नहीं करता।
- चैनल-केंद्रित सेवाएँ (Slack/Discord/Matrix/Microsoft Teams) सेटअप के दौरान चैनल/रूम अनुमति-सूचियों के लिए प्रॉम्प्ट करती हैं। आप नाम या ID दर्ज कर सकते हैं; संभव होने पर विज़ार्ड नामों को ID में हल करता है।
- यदि आप डेमन इंस्टॉलेशन चरण चलाते हैं, तो टोकन प्रमाणीकरण के लिए टोकन आवश्यक है। यदि `gateway.auth.token` को SecretRef द्वारा प्रबंधित किया जाता है, तो configure SecretRef को सत्यापित करता है, लेकिन हल किए गए प्लेनटेक्स्ट टोकन मानों को सुपरवाइज़र सेवा के एनवायरनमेंट मेटाडेटा में स्थायी रूप से संग्रहीत नहीं करता; यदि SecretRef अनसुलझा है, तो configure कार्रवाई योग्य समाधान मार्गदर्शन के साथ डेमन इंस्टॉलेशन रोक देता है।
- यदि `gateway.auth.token` और `gateway.auth.password`, दोनों कॉन्फ़िगर हैं और `gateway.auth.mode` सेट नहीं है, तो configure डेमन इंस्टॉलेशन तब तक रोकता है, जब तक आप मोड स्पष्ट रूप से सेट नहीं करते।
