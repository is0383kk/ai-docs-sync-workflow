# `openclaw system`

Gateway के लिए सिस्टम-स्तरीय सहायक: सिस्टम इवेंट को कतार में लगाना, Heartbeat नियंत्रित करना और उपस्थिति देखना।

सभी `system` उपकमांड Gateway RPC का उपयोग करते हैं और साझा क्लाइंट फ़्लैग स्वीकार करते हैं:

| फ़्लैग              | डिफ़ॉल्ट                              | विवरण                                                                                                                                                                                            |
| ----------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--url <url>`     | कॉन्फ़िगर होने पर `gateway.remote.url` | Gateway WebSocket URL।                                                                                                                                                                                 |
| `--token <token>` | कोई नहीं                                 | Gateway टोकन (यदि आवश्यक हो)।                                                                                                                                                                           |
| `--timeout <ms>`  | `30000`                              | मिलीसेकंड में RPC टाइमआउट।                                                                                                                                                                           |
| `--expect-final`  | बंद                                  | अंतिम प्रतिक्रिया (एजेंट) की प्रतीक्षा करें।                                                                                                                                                                       |
| `--json`          | बंद                                  | JSON आउटपुट करें। इस फ़्लैग से स्वतंत्र रूप से, `heartbeat last/enable/disable` और `system presence` हमेशा अपरिष्कृत RPC JSON पेलोड प्रिंट करते हैं; `system event` इसका उपयोग JSON और साधारण `ok` पंक्ति के बीच स्विच करने के लिए करता है। |

## सामान्य कमांड

```bash
openclaw system event --text "Check for urgent follow-ups" --mode now
openclaw system event --text "Check for urgent follow-ups" --url ws://127.0.0.1:18789 --token "$OPENCLAW_GATEWAY_TOKEN"
openclaw system heartbeat enable
openclaw system heartbeat last
openclaw system presence
```

## `system event`

डिफ़ॉल्ट रूप से **मुख्य** सत्र पर सिस्टम इवेंट को कतार में लगाएँ। अगला Heartbeat इसे प्रॉम्प्ट में `System:` पंक्ति के रूप में अंतःक्षेपित करता है। Heartbeat को तुरंत ट्रिगर करने के लिए `--mode now` का उपयोग करें; `next-heartbeat` (डिफ़ॉल्ट) अगले निर्धारित टिक की प्रतीक्षा करता है।

किसी विशिष्ट सत्र को लक्षित करने के लिए `--session-key` दें, उदाहरण के लिए किसी असिंक्रोनस कार्य की पूर्णता को उसे शुरू करने वाले चैनल पर वापस रिले करने हेतु।

<Note>
**`--session-key` के साथ समय-निर्धारण अपवाद:** जब `--session-key` दिया जाता है, तो `--mode next-heartbeat` अगले निर्धारित टिक की प्रतीक्षा करने के बजाय तत्काल लक्षित वेक में बदल जाता है। लक्षित वेक Heartbeat इंटेंट `immediate` का उपयोग करते हैं, इसलिए वे रनर के नॉट-ड्यू गेट को बायपास करते हैं, जो अन्यथा `event`-इंटेंट वेक को स्थगित कर देता (और प्रभावी रूप से छोड़ देता)। यदि आप विलंबित डिलीवरी चाहते हैं, तो `--session-key` को छोड़ दें, ताकि इवेंट मुख्य सत्र पर पहुँचे और अगले नियमित Heartbeat के साथ वितरित हो।
</Note>

फ़्लैग:

- `--text <text>`: आवश्यक सिस्टम इवेंट टेक्स्ट।
- `--mode <mode>`: `now` या `next-heartbeat` (डिफ़ॉल्ट)।
- `--session-key <sessionKey>`: वैकल्पिक; एजेंट के मुख्य सत्र के बजाय किसी विशिष्ट एजेंट सत्र को लक्षित करें। जो कुंजियाँ समाधान किए गए एजेंट की नहीं हैं, वे एजेंट के मुख्य सत्र पर वापस चली जाती हैं।

## `system heartbeat last|enable|disable`

- `last`: अंतिम Heartbeat इवेंट दिखाएँ।
- `enable`: Heartbeat को फिर से चालू करें (यदि उन्हें अक्षम किया गया था, तो इसका उपयोग करें)।
- `disable`: Heartbeat रोकें।

## `system presence`

Gateway को ज्ञात वर्तमान सिस्टम उपस्थिति प्रविष्टियाँ सूचीबद्ध करें (Node, इंस्टेंस और समान स्थिति पंक्तियाँ)।

## टिप्पणियाँ

- आपके वर्तमान कॉन्फ़िगरेशन से पहुँच योग्य एक चालू Gateway आवश्यक है (स्थानीय या रिमोट)।
- सिस्टम इवेंट क्षणिक होते हैं और रीस्टार्ट के बाद बने नहीं रहते।
