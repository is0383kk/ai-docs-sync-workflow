# `openclaw claws`

Claw एक नए OpenClaw एजेंट के लिए संस्करणित सेटअप है। यह एजेंट की
पोर्टेबल पहचान, वर्कस्पेस फ़ाइलों, Skills, plugins, MCP सर्वरों और
Cron जॉब का वर्णन कर सकता है। हार्नेस-विशिष्ट एजेंट सेटिंग्स को संदर्भित
पैकेज प्रोफ़ाइल में रखा जा सकता है। Claw किसी मौजूदा एजेंट को प्रतिस्थापित या संशोधित नहीं करता।

Claws प्रयोगात्मक हैं। उनका स्कीमा, कमांड आउटपुट और जीवनचक्र बदल सकते हैं।
कमांड सतह को स्पष्ट रूप से सक्षम करें:

```bash
export OPENCLAW_EXPERIMENTAL_CLAWS=1
```

वर्तमान CLI स्थानीय पैकेज डायरेक्टरी, `CLAW.md`, या समूहीकृत JSON मैनिफ़ेस्ट को पढ़ता है।
ClawHub के माध्यम से पूरे Claws को प्रकाशित करना, खोजना और इंस्टॉल करना एक
अलग रजिस्ट्री ट्रैक है और अभी इस कमांड सतह का भाग नहीं है।

## Claw पैकेज बनाएँ

पैकेज में `package.json`, एक `CLAW.md` मैनिफ़ेस्ट और उस मैनिफ़ेस्ट द्वारा संदर्भित कोई भी प्रोफ़ाइल या
वर्कस्पेस साइडकार होते हैं:

```json
{
  "name": "@acme/incident-triage-claw",
  "version": "1.0.0",
  "type": "module",
  "openclaw": { "claw": "CLAW.md" }
}
```

`CLAW.md` YAML फ्रंटमैटर से शुरू होता है। उसकी Markdown बॉडी लोगों के लिए Claw का वर्णन
करती है और एजेंट कॉन्फ़िगरेशन का भाग नहीं है:

```md
---
schemaVersion: 1
agent:
  id: incident-triage
  name: घटना ट्राइएज
metadata:
  openclaw.config: profiles/openclaw.yml
workspace:
  bootstrapFiles: {}
packages: []
mcpServers: {}
cronJobs: []
---

# घटना ट्राइएज

घटनाओं की समीक्षा और रूटिंग के लिए एक एजेंट बनाता है।
```

`metadata` पोर्टेबल उपभोक्ता संकेतों के लिए स्ट्रिंग-से-स्ट्रिंग मैप है। OpenClaw की
`openclaw.config` कुंजी एक वैकल्पिक, पैकेज-सापेक्ष YAML प्रोफ़ाइल की ओर संकेत करती है। निर्यातित
डिफ़ॉल्ट `profiles/openclaw.yml` है; पॉइंटर मानक है, इसलिए
पैकेज कोई अन्य सुरक्षित सापेक्ष `.yml` या `.yaml` पथ चुन सकता है।

```yaml
schemaVersion: 1
agent:
  tools:
    profile: coding
    alsoAllow: [cron]
    deny: [exec]
    fs:
      workspaceOnly: true
  memory:
    search:
      enabled: true
      rememberAcrossConversations: true
      sources: [memory, sessions]
```

यह प्रोफ़ाइल केवल Claw पैकेज के भीतर मौजूद रहती है। OpenClaw उस Claw का
निरीक्षण, जोड़ना, अपडेट और निर्यात करते समय इसे सत्यापित तथा उपयोग करता है; इसे
उपयोगकर्ता के सामान्य OpenClaw कॉन्फ़िगरेशन पथ पर कॉपी नहीं किया जाता।
अन्य हार्नेस नेमस्पेस वाली मेटाडेटा कुंजी को अनदेखा करके पोर्टेबल मैनिफ़ेस्ट फ़ील्ड का उपयोग कर सकते हैं।

यही सख्त संस्करण 1 स्कीमा समूहीकृत JSON मैनिफ़ेस्ट को स्वीकार करना जारी रखता है।
समूहीकृत JSON, OpenClaw प्रोफ़ाइल की दूसरी प्रति एम्बेड करने के बजाय उसी
`metadata.openclaw.config` पॉइंटर का उपयोग करता है। इस पृष्ठ के शेष स्कीमा अंश
JSON का उपयोग करते हैं, जिनकी समकक्ष कुंजियाँ `CLAW.md` फ्रंटमैटर में उपलब्ध हैं।

OpenClaw पैकेज प्रोफ़ाइल चल रहे OpenClaw संस्करण द्वारा पंजीकृत किसी भी अंतर्निहित टूल
प्रोफ़ाइल का चयन कर सकती है, फिर उसे `alsoAllow`, `deny` और
`tools.fs.workspaceOnly: true` से परिष्कृत कर सकती है। Claw उस फ़ील्ड को `false` पर सेट करके
होस्ट फ़ाइलसिस्टम सीमाबंदी को कमज़ोर नहीं कर सकता। `tools.allow` स्पष्ट
अनुमति-सूची के रूप में उपलब्ध रहता है, लेकिन इसे `alsoAllow` के साथ संयोजित नहीं किया जा सकता। Claw
`memory.search.enabled` भी सेट कर सकता है, पोर्टेबल `memory` और `sessions` स्रोत चुन सकता है,
और `rememberAcrossConversations` के साथ वार्तालापों के बीच मेमोरी के लिए ऑप्ट इन कर सकता है।
`sessions` स्रोत घोषित करने के लिए यह ऑप्ट-इन आवश्यक है।
होस्ट नीति फिर भी इन सेटिंग्स को सीमित करती है, और Claws कस्टम
प्रोफ़ाइल परिभाषाएँ, प्रदाता, क्रेडेंशियल, बाइंडिंग या स्थानीय मेमोरी पथ नहीं रखते।
संदर्भित प्रोफ़ाइल 256 KiB तक सीमित है, JSON-संगत YAML होनी चाहिए, इसमें
उपनाम, एंकर, टैग या मर्ज कुंजियाँ नहीं हो सकतीं, और यह पैकेज के भीतर एक नियमित,
गैर-सिमलिंक, गैर-हार्डलिंक फ़ाइल होनी चाहिए।

पैकेज और वर्कस्पेस पथ पैकेज रूट के भीतर ही रहने चाहिए। मैनिफ़ेस्ट
1 MiB तक, पैकेज मेटाडेटा 256 KiB तक सीमित हैं, और वर्कस्पेस स्रोतों पर
अलग-अलग प्रति-फ़ाइल तथा समग्र सीमाएँ लागू होती हैं। वर्कस्पेस स्रोत सिमलिंक वाले
पैरेंट को भी अस्वीकार करते हैं।

वर्कस्पेस फ़ाइलें पथ द्वारा घोषित की जाती हैं और पैकेज साइडकार से पढ़ी जाती हैं। `SOUL.md` जैसी बूटस्ट्रैप
फ़ाइलें नामित प्रविष्टियों का उपयोग करती हैं; अतिरिक्त फ़ाइलें पैकेज-सापेक्ष
स्रोत और वर्कस्पेस-सापेक्ष लक्ष्य उपयोग करती हैं:

```json
{
  "workspace": {
    "bootstrapFiles": {
      "SOUL.md": { "source": "workspace/SOUL.md" }
    },
    "files": [
      {
        "source": "workspace/reference/policy.md",
        "path": "reference/policy.md"
      }
    ]
  }
}
```

Skills और plugins सटीक ClawHub संस्करणों का उपयोग करते हैं:

```json
{
  "packages": [
    {
      "kind": "skill",
      "source": "clawhub",
      "ref": "incident-triage",
      "version": "1.0.0"
    },
    {
      "kind": "plugin",
      "source": "clawhub",
      "ref": "@acme/audit-plugin",
      "version": "2.0.0"
    }
  ]
}
```

ड्राई रन सहमति से पहले सटीक आर्टिफ़ैक्ट, अखंडता और किसी भी ClawHub विश्वास चेतावनी को
रिज़ॉल्व करने के लिए मौजूदा skill और plugin प्रीफ़्लाइट पथों का उपयोग करता है।
चेतावनी अखंडता-बद्ध योजना में दिखाई देती रहती है। लागू करने पर अनुपलब्ध आर्टिफ़ैक्ट
इंस्टॉल होते हैं या मेल खाने वाले आर्टिफ़ैक्ट पुनः उपयोग किए जाते हैं, और यह दर्ज होता है कि Claw ने
प्रत्येक संसाधन प्रस्तुत किया या संदर्भित किया। Plugins प्रति-एजेंट इंस्टॉलेशन के बजाय
पूरी प्रक्रिया में उपलब्ध OpenClaw क्षमताएँ बने रहते हैं।

Cron जॉब नए एजेंट के लिए निर्धारित कार्य घोषित करते हैं:

```json
{
  "cronJobs": [
    {
      "id": "daily-summary",
      "name": "दैनिक घटना सारांश",
      "schedule": { "cron": "0 9 * * *", "timezone": "UTC" },
      "session": "isolated",
      "message": "सक्रिय घटनाओं का सारांश दें।"
    }
  ]
}
```

Claws मौजूदा Gateway शेड्यूलर का उपयोग करते हैं और बनाए गए जॉब को नए
एजेंट से बाँधते हैं। पूर्वावलोकन, उद्गम, स्थिति और निष्कासन सामान्य Cron कमांड के
व्यवहार को बदले बिना उन जॉब को कवर करते हैं। निष्कासन Gateway के माध्यम से लाइव जॉब को
दोबारा पढ़ता है और योजना बनने के बाद उसकी स्वामित्व वाली परिभाषा बदल गई हो तो उसे सुरक्षित रखता है।

MCP घोषणाएँ मौजूदा `mcp.servers` कॉन्फ़िगरेशन मॉडल का उपयोग करती हैं:

```json
{
  "mcpServers": {
    "statuspage": {
      "command": "npx",
      "args": ["--yes", "@acme/statuspage-mcp@1.0.0"],
      "env": { "STATUSPAGE_TOKEN": "${STATUSPAGE_TOKEN}" }
    }
  }
}
```

पर्यावरण संदर्भ, संदर्भ ही बने रहते हैं; Claws रिज़ॉल्व किए गए सीक्रेट
मान एम्बेड नहीं करते। टकराव-रहित घोषणा प्रबंधित हो जाती है, जबकि बिल्कुल समान मौजूदा
या साझा घोषणा संदर्भित होती है। पूर्वावलोकन, उद्गम, स्थिति, निर्यात और
निष्कासन अन्य Claw संसाधनों जैसी ही स्वामित्व नीति का पालन करते हैं।

## निरीक्षण और पूर्वावलोकन

स्थानीय परिवर्तनों की योजना बनाए बिना स्रोत को सत्यापित करें:

```bash
openclaw claws inspect ./incident-triage.claw.json
```

सभी प्रस्तावित जीवनचक्र कार्रवाइयों का पूर्वावलोकन करें:

```bash
openclaw claws add ./incident-triage.claw.json --dry-run --json
```

योजना व्युत्पन्न एजेंट और वर्कस्पेस, प्रत्येक प्रस्तावित कार्रवाई,
पूर्वापेक्षाएँ, अवरोधक, अलग-अलग क्षमता वृद्धियाँ और एक `planIntegrity`
डाइजेस्ट रिपोर्ट करती है। क्षमता रिकॉर्ड सटीक पैकेज, MCP, निर्धारित कार्य, सैंडबॉक्स,
टूल या Heartbeat प्रभाव दिखाते हैं। एजेंट बनाने से पहले योजना की समीक्षा करें:

```bash
openclaw claws add ./incident-triage.claw.json \
  --yes \
  --plan-integrity <SHA256_FROM_DRY_RUN>
```

केवल `--yes` पर्याप्त नहीं है। पूर्वावलोकन के बाद स्रोत, गंतव्य या लाइव कॉन्फ़िगरेशन
बदलने पर OpenClaw योजना को दोबारा बनाता है और सहमति अस्वीकार कर देता है। पैकेज
डिफ़ॉल्ट का स्थानीय स्थिति से टकराव होने पर पूर्वावलोकन और लागू करने, दोनों के दौरान
`--agent-id` या `--workspace` का उपयोग करें। अस्थायी प्रोफ़ाइल और समानांतर सत्यापन के लिए
स्पष्ट `--workspace` दें; `OPENCLAW_STATE_DIR` रनटाइम स्थिति का स्थान बदलता है, लेकिन
डिफ़ॉल्ट वर्कस्पेस स्थान नहीं बदलता।

Claw जोड़ने से नया एजेंट और वर्कस्पेस कॉन्फ़िगरेशन बनता है, घोषित
वर्कस्पेस फ़ाइलें लिखी जाती हैं, घोषित skill और plugin आर्टिफ़ैक्ट इंस्टॉल या पुनः उपयोग होते हैं, और
पैकेज, MCP तथा Cron उद्गम दर्ज होता है। मौजूदा फ़ाइलों को अधिलेखित नहीं किया जाता,
और स्वामित्व वाली सामग्री में विचलन होने पर पुनः प्रयास सुरक्षित रूप से विफल होते हैं।

## इंस्टॉल की गई स्थिति का निरीक्षण करें

```bash
openclaw claws status
openclaw claws status incident-triage --json
openclaw doctor
```

`status` इंस्टॉल किए गए एजेंट और उसके दर्ज वर्कस्पेस, पैकेज, MCP तथा
Cron उद्गम की वर्तमान स्थिति से तुलना करता है। यह स्थानीय स्थिति बदले बिना अधूरे इंस्टॉल, अनुपलब्ध
संसाधन और विचलन रिपोर्ट करता है। `openclaw doctor` अधूरे स्वामित्व रिकॉर्ड, असुरक्षित प्रबंधित
फ़ाइलों और ऐसे Cron जॉब के लिए Claw-विशिष्ट निदान जोड़ता है जिनकी लाइव Gateway इन्वेंटरी से
पुष्टि नहीं की जा सकती।

Claw उद्गम दो संबंधों में अंतर करता है:

- **प्रबंधित:** Claw ने संसाधन प्रस्तुत किया और वर्तमान में उसका प्रबंधन करता है। अपरिवर्तित होने और कोई
  परस्पर-विरोधी स्वामी न रहने पर यह सफ़ाई का उम्मीदवार होता है।
- **संदर्भित:** संसाधन स्वतंत्र रूप से पहले से मौजूद था या साझा है। निष्कासन
  इस Claw का संदर्भ मुक्त करता है और डिफ़ॉल्ट रूप से संसाधन को बनाए रखता है।

यह संदर्भ गणना नहीं है। सामान्य plugin, skill और एजेंट कमांड अपना
मौजूदा व्यवहार बनाए रखते हैं; Claws उनके ऊपर उद्गम और संरक्षित जीवनचक्र संचालन
जोड़ते हैं।

## इंस्टॉल किए गए Claw को अपडेट करें

डिफ़ॉल्ट रूप से अपडेट उस स्रोत का उपयोग करता है जो Claw जोड़ते समय दर्ज किया गया था। स्रोत का
स्थान बदलने या किसी अन्य पैकेज डायरेक्टरी का परीक्षण करते समय `--from` का उपयोग करें:

```bash
openclaw claws update incident-triage --dry-run --json
openclaw claws update incident-triage \
  --from ./incident-triage-next \
  --dry-run --json
```

योजना वर्तमान उद्गम और लाइव स्थिति की लक्ष्य मैनिफ़ेस्ट से तुलना करती है।
यह एजेंट, वर्कस्पेस, पैकेज, MCP, Cron और स्वामित्व परिवर्तन रिपोर्ट करती है,
जिनमें क्षमता वृद्धियाँ और अवरोधक शामिल हैं। क्षमता वृद्धियों के लिए
अलग मशीन-पठनीय रिकॉर्ड और मानव आउटपुट में सटीक संशोधित प्रभाव वाली `!` पंक्तियाँ होती हैं।
रिज़ॉल्व की गई पैकेज अखंडता, इंस्टॉल पहचान और कोई भी विश्वास चेतावनी
शामिल होती है। पैकेज घोषणा हटाने पर अपडेट के दौरान आर्टिफ़ैक्ट को अनइंस्टॉल किए बिना इस Claw का किनारा
मुक्त हो जाता है। अंतिम सटीक `planIntegrity` पुष्टि उस प्रकट किए गए सेट के साथ-साथ सामान्य
सामग्री परिवर्तनों को भी बाँधती है। होस्ट इन्हीं रिकॉर्ड का उपयोग अलग संवाद या
समेकित बहु-एजेंट समीक्षा के लिए कर सकते हैं। स्पष्ट सहमति के साथ समीक्षा की गई सटीक योजना लागू करें:

```bash
openclaw claws update incident-triage \
  --yes \
  --plan-integrity <SHA256_FROM_DRY_RUN>
```

OpenClaw योजना को दोबारा बनाता है और प्रत्येक परिवर्तन से पहले स्वामित्व वाली स्थिति पर
तुलना-और-अदला-बदली करता है। हटाई गई पैकेज घोषणाएँ आर्टिफ़ैक्ट अनइंस्टॉल किए बिना
निर्भरता किनारों को मुक्त करती हैं। Cron परिवर्तन लाइव शेड्यूलर परिभाषा को दोबारा पढ़ते हैं और
ऑपरेटर विचलन पर रुक जाते हैं। पैकेज इंस्टॉलर, स्रोत-कॉन्फ़िगरेशन लेखक और Gateway शेड्यूलर
एक ही ट्रांज़ैक्शन नहीं हैं। यदि किसी बाहरी परिवर्तन के बाद प्रतिपूर्ति प्रमाणित नहीं की जा सकती,
तो OpenClaw संरचित `status: partial` के साथ त्रुटि कोड `update_partial` रिपोर्ट करता है,
अनिश्चित उद्गम को सुरक्षित रखता है और रुक जाता है। `claws status`, प्रभावित संसाधन और
`openclaw doctor` का निरीक्षण करें; फिर पुनः प्रयास करने या कुछ भी हटाने से पहले दोबारा पूर्वावलोकन करें।

## इंस्टॉल किए गए Claw को हटाएँ

सफ़ाई चुनने से पहले निष्कासन का पूर्वावलोकन करें:

```bash
openclaw claws remove incident-triage --dry-run --json
openclaw claws remove incident-triage \
  --yes \
  --plan-integrity <SHA256_FROM_DRY_RUN>
```

डिफ़ॉल्ट पात्र प्रबंधित स्थिति को हटाता है और संदर्भित स्थिति को मुक्त करता है।
संशोधित फ़ाइलें और किसी अन्य वर्तमान स्वामी वाले संसाधन बनाए रखे जाते हैं या
अवरुद्ध होते हैं। सफ़ाई विकल्प योजना डाइजेस्ट का भाग हैं; `--yes` उन्हें कभी विस्तृत
नहीं करता। वैश्विक रूप से इंस्टॉल किए गए plugins बनाए रखे जाते हैं, जबकि इस Claw का संदर्भ
मुक्त किया जाता है; जब पूरी प्रक्रिया में उपलब्ध किसी plugin को अनइंस्टॉल करना हो, तो सामान्य plugin जीवनचक्र का अलग से उपयोग करें।

अपरिवर्तित Claw-प्रस्तुत संदर्भों को हटाने के लिए, जिनका कोई अन्य वर्तमान
स्वामी नहीं है, पूर्वावलोकन और लागू करने, दोनों में `--remove-unused` शामिल करें। इसके बजाय सटीक
संदर्भित संसाधन चुनने के लिए `--remove-referenced` दोहराएँ:

```bash
openclaw claws remove incident-triage \
  --dry-run \
  --remove-referenced 'plugin:@acme/audit-plugin@2.0.0'
```

`--force-referenced` का उपयोग प्रदर्शित आश्रितों,
स्वतंत्र स्वामियों और पहले से मौजूद उद्गम की समीक्षा करने के बाद ही करें। यह उन टकरावों के बावजूद चयनित सफ़ाई की अनुमति देता है;
यह योजना-अखंडता सहमति को नहीं छोड़ता।

## इंस्टॉल किए गए एजेंट को निर्यात करें

Export एक नई पैकेज डायरेक्टरी बनाता है और यदि गंतव्य पहले से मौजूद हो या
प्रबंधित स्थिति में विचलन आ गया हो, तो विफल हो जाता है:

```bash
openclaw claws export incident-triage --out ./incident-triage-export --json
```

परिणाम में `package.json`, कैनोनिकल `CLAW.md`, और प्रबंधित कार्यक्षेत्र
साइडकार होते हैं। यह एक पोर्टेबल Claw पैकेज है, पूरे इंस्टेंस का बैकअप नहीं: असंबंधित
एजेंट, क्रेडेंशियल, सत्र और स्वामित्व-रहित स्थानीय स्थिति शामिल नहीं की जाती।

## कमांड संदर्भ

| कमांड                             | उद्देश्य                                             |
| ----------------------------------- | --------------------------------------------------- |
| `claws inspect <source>`            | पैकेज डायरेक्टरी या समूहीकृत मैनिफ़ेस्ट को सत्यापित करें।   |
| `claws add <source>`                | एक नए एजेंट और कार्यक्षेत्र का पूर्वावलोकन करें या उन्हें बनाएँ।      |
| `claws status [claw-or-agent]`      | इंस्टॉल की गई स्थिति, स्वामित्व और विचलन की रिपोर्ट दें।       |
| `claws update <claw-or-agent>`      | चयनित स्रोत से परिवर्तनों का पूर्वावलोकन करें या उन्हें लागू करें।  |
| `claws remove <claw-or-agent>`      | एजेंट और योग्य संसाधनों को हटाने का पूर्वावलोकन करें या उन्हें हटाएँ। |
| `claws export <agent> --out <path>` | इंस्टॉल किए गए एजेंट से पोर्टेबल पैकेज बनाएँ।  |

प्रयोगात्मक मशीन-पठनीय आउटपुट के लिए `--json` का उपयोग करें।
