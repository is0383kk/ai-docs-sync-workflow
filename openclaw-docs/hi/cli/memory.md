# `openclaw memory`

सिमेंटिक मेमोरी इंडेक्सिंग, खोज और `MEMORY.md` में प्रोमोशन प्रबंधित करें।
बंडल किए गए `memory-core` Plugin द्वारा प्रदान किया गया, और तब उपलब्ध होता है जब
`plugins.slots.memory`, `memory-core` (डिफ़ॉल्ट) चुनता है। अन्य मेमोरी
Plugin अपने स्वयं के CLI नेमस्पेस उपलब्ध कराते हैं।

संबंधित: [मेमोरी](/hi/concepts/memory) अवधारणा, [Dreaming](/hi/concepts/dreaming),
[मेमोरी कॉन्फ़िगरेशन संदर्भ](/hi/reference/memory-config), [मेमोरी विकी](/hi/plugins/memory-wiki),
[विकी](/hi/cli/wiki), [Plugins](/hi/tools/plugin)।

## `memory status`

```bash
openclaw memory status [--agent <id>] [--deep] [--index] [--fix] [--json] [--verbose]
```

`--agent` के बिना, `agents.entries` में प्रत्येक एजेंट के लिए चलता है; यदि कोई एजेंट सूची
कॉन्फ़िगर नहीं है, तो डिफ़ॉल्ट एजेंट का उपयोग करता है।

| फ़्लैग        | प्रभाव                                                                                                                                                                                                                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--deep`    | वेक्टर स्टोर, एम्बेडिंग प्रदाता और सिमेंटिक खोज की तैयारी की जाँच करें (इसके कारण अतिरिक्त प्रदाता कॉल होती हैं)। सामान्य `memory status` तेज़ रहता है और इसे छोड़ देता है; अज्ञात वेक्टर/सिमेंटिक स्थिति का अर्थ है कि इसकी जाँच नहीं हुई। QMD लेक्सिकल `searchMode: "search"`, `--deep` के साथ भी हमेशा सिमेंटिक वेक्टर जाँच छोड़ देता है। |
| `--index`   | स्टोर के डर्टी होने पर दोबारा इंडेक्स करें। इसमें `--deep` निहित है।                                                                                                                                                                                                                                                          |
| `--fix`     | पुराने रिकॉल लॉक की मरम्मत करें और प्रोमोशन मेटाडेटा को सामान्यीकृत करें।                                                                                                                                                                                                                                               |
| `--json`    | JSON प्रिंट करें।                                                                                                                                                                                                                                                                                               |
| `--verbose` | प्रत्येक चरण के विस्तृत लॉग उत्सर्जित करें।                                                                                                                                                                                                                                                                             |

यदि `Dreaming` पंक्ति `dreaming.enabled: true` के साथ भी `off` बनी रहती है, या
निर्धारित स्वीप कभी चलते हुए नहीं लगते, तो प्रबंधित Dreaming Cron समन्वय को
ट्रिगर करने के लिए डिफ़ॉल्ट एजेंट के Heartbeat के सक्रिय होने पर निर्भर करता है। शेड्यूलिंग विवरण के लिए
[Dreaming](/hi/concepts/dreaming) देखें।

स्थिति में `memory.search.extraPaths` से प्राप्त सभी अतिरिक्त खोज पथ भी सूचीबद्ध होते हैं।

## `memory index`

```bash
openclaw memory index [--agent <id>] [--force] [--verbose]
```

प्रति-एजेंट दायरा `status` के समान है। `--force` इंक्रीमेंटल के बजाय
पूर्ण रीइंडेक्स चलाता है। `--verbose` इंडेक्सिंग प्रगति दिखाने से पहले प्रति-एजेंट प्रदाता, मॉडल, स्रोत और
अतिरिक्त पथ का विवरण प्रिंट करता है।

## `memory search`

```bash
openclaw memory search [query] [--query <text>] [--agent <id>] [--max-results <n>] [--min-score <n>] [--json]
```

- क्वेरी: स्थितीय `[query]` या `--query <text>`। यदि दोनों सेट हैं, तो `--query`
  प्रभावी होता है। यदि कोई भी सेट नहीं है, तो कमांड त्रुटि देता है।
- `--agent <id>`: डिफ़ॉल्ट रूप से डिफ़ॉल्ट एजेंट का उपयोग करता है (पूरी एजेंट सूची का नहीं)।
- `--max-results <n>`: परिणामों की संख्या सीमित करें (धनात्मक पूर्णांक)।
- `--min-score <n>`: इस स्कोर से कम मिलानों को फ़िल्टर करें।

## `memory promote`

`memory/YYYY-MM-DD.md` से अल्पकालिक उम्मीदवारों को रैंक करें और वैकल्पिक रूप से
शीर्ष प्रविष्टियों को `MEMORY.md` में जोड़ें।

```bash
openclaw memory promote [--agent <id>] [--limit <n>] [--min-score <n>] \
  [--min-recall-count <n>] [--min-unique-queries <n>] [--apply] [--include-promoted] [--json]
```

| फ़्लैग                       | डिफ़ॉल्ट      | प्रभाव                                                            |
| -------------------------- | ------------ | ----------------------------------------------------------------- |
| `--limit <n>`              |              | लौटाए/लागू किए जाने वाले उम्मीदवारों की अधिकतम संख्या।                                   |
| `--min-score <n>`          | `0.75`       | न्यूनतम भारित प्रोमोशन स्कोर।                                 |
| `--min-recall-count <n>`   | `3`          | आवश्यक न्यूनतम रिकॉल संख्या।                                    |
| `--min-unique-queries <n>` | `2`          | आवश्यक अलग-अलग क्वेरी की न्यूनतम संख्या।                            |
| `--apply`                  | केवल पूर्वावलोकन | चयनित उम्मीदवारों को `MEMORY.md` में जोड़ें और उन्हें प्रोमोटेड चिह्नित करें। |
| `--include-promoted`       |              | पिछले चक्रों में पहले ही प्रोमोट किए गए उम्मीदवारों को शामिल करें।           |
| `--json`                   |              | JSON प्रिंट करें।                                                       |

ये CLI डिफ़ॉल्ट निर्धारित Dreaming स्वीप की डीप-फ़ेज़
थ्रेशोल्ड से अलग हैं (नीचे [Dreaming](#dreaming) देखें); एकबारगी मैन्युअल रन में
स्वीप व्यवहार से मिलान करने के लिए स्पष्ट फ़्लैग पास करें।

रैंकिंग संकेत: रिकॉल आवृत्ति, पुनर्प्राप्ति प्रासंगिकता, क्वेरी विविधता,
समयगत नवीनता, विभिन्न दिनों में समेकन और व्युत्पन्न अवधारणाओं की समृद्धि, जिन्हें
मेमोरी रिकॉल और दैनिक अंतर्ग्रहण पास दोनों से लिया जाता है, साथ ही बार-बार Dreaming में पुनः देखे जाने पर हल्का/REM चरण
सुदृढ़ीकरण बूस्ट मिलता है। लिखने से पहले, प्रोमोशन
लाइव दैनिक नोट को दोबारा पढ़ता है, इसलिए रैंकिंग के बाद अल्पकालिक स्निपेट में हुए संपादन या विलोपन का
सम्मान किया जाता है और पुराने स्नैपशॉट से प्रोमोशन नहीं किया जाता।

## `memory promote-explain`

एक प्रोमोशन उम्मीदवार के स्कोर विभाजन की व्याख्या करें।

```bash
openclaw memory promote-explain <selector> [--agent <id>] [--include-promoted] [--json]
```

`<selector>` उम्मीदवार की कुंजी (सटीक या सबस्ट्रिंग), पथ या स्निपेट
टेक्स्ट से मेल खाता है।

## `memory rem-harness`

कुछ भी लिखे बिना REM चिंतन, उम्मीदवार सत्य और डीप-फ़ेज़ प्रोमोशन आउटपुट का
पूर्वावलोकन करें।

```bash
openclaw memory rem-harness [--agent <id>] [--path <file-or-dir>] [--grounded] [--include-promoted] [--json]
```

- `--path <file-or-dir>`: लाइव कार्यक्षेत्र के बजाय ऐतिहासिक `YYYY-MM-DD.md`
  दैनिक फ़ाइलों से हार्नेस को सीड करें।
- `--grounded`: ऐतिहासिक नोट से एक आधारयुक्त `What Happened` / `Reflections` /
  `Possible Lasting Updates` पूर्वावलोकन भी रेंडर करें।

## `memory rem-backfill`

UI समीक्षा के लिए आधारयुक्त ऐतिहासिक REM सारांश `DREAMS.md` में लिखें।
इसे वापस किया जा सकता है।

```bash
openclaw memory rem-backfill --path <file-or-dir> [--agent <id>] [--stage-short-term] [--json]
openclaw memory rem-backfill --rollback [--rollback-short-term] [--json]
```

- `--path <file-or-dir>`: जब तक `--rollback`/`--rollback-short-term`
  सेट न हो, आवश्यक है। बैकफ़िल के स्रोत के रूप में ऐतिहासिक दैनिक मेमोरी फ़ाइल या फ़ाइलें अथवा डायरेक्टरी।
- `--stage-short-term`: लाइव अल्पकालिक प्रोमोशन स्टोर में आधारयुक्त टिकाऊ उम्मीदवारों को भी
  सीड करें, ताकि सामान्य डीप फ़ेज़ उन्हें रैंक कर सके।
- `--rollback`: पहले लिखी गई आधारयुक्त डायरी प्रविष्टियों को
  `DREAMS.md` से हटाएँ।
- `--rollback-short-term`: पहले स्टेज किए गए आधारयुक्त अल्पकालिक
  उम्मीदवारों को हटाएँ।

## Dreaming

Dreaming पृष्ठभूमि मेमोरी समेकन प्रणाली है, जिसमें तीन सहयोगी
चरण एक ही शेड्यूल पर क्रम से चलते हैं: **लाइट** (अल्पकालिक
सामग्री को क्रमबद्ध/स्टेज करना), **REM** (चिंतन करना और विषयों को सामने लाना), **डीप** (टिकाऊ
तथ्यों को `MEMORY.md` में प्रोमोट करना)। केवल डीप चरण `MEMORY.md` में लिखता है।

- `plugins.entries.memory-core.config.dreaming.enabled: true` से सक्षम करें
  (डिफ़ॉल्ट `false`); `memory-core` स्वीप Cron जॉब को स्वतः प्रबंधित करता है, मैन्युअल
  `openclaw cron add` आवश्यक नहीं है।
- चैट से `/dreaming on|off` द्वारा टॉगल करें; `/dreaming status`
  (या `/dreaming`/`/dreaming help`) द्वारा निरीक्षण करें। `on`/`off` के लिए चैनल स्वामी की स्थिति
  या Gateway `operator.admin` आवश्यक है; `status` और सहायता उस प्रत्येक व्यक्ति के लिए उपलब्ध रहती है जो
  कमांड चला सकता है।
- मानव-पठनीय चरण आउटपुट `DREAMS.md` (या किसी मौजूदा `dreams.md`) में जाता है।
  डिफ़ॉल्ट रूप से (`dreaming.storage.mode: "separate"`) प्रत्येक चरण
  `memory/dreaming/<phase>/YYYY-MM-DD.md` में एक स्वतंत्र रिपोर्ट भी लिखता है; रिपोर्ट को इसके बजाय दैनिक मेमोरी फ़ाइल में समाहित करने के लिए `mode:
"inline"`, या दोनों के लिए `"both"`
  सेट करें।
- निर्धारित और मैन्युअल `memory promote` रन समान डीप-फ़ेज़
  रैंकिंग संकेत साझा करते हैं; केवल डिफ़ॉल्ट थ्रेशोल्ड अलग हैं (ऊपर की तालिका बनाम
  नीचे के निर्धारित डिफ़ॉल्ट देखें)।
- निर्धारित रन प्रत्येक कॉन्फ़िगर किए गए एजेंट के मेमोरी कार्यक्षेत्र में वितरित होते हैं।

निर्धारित डिफ़ॉल्ट (`plugins.entries.memory-core.config.dreaming`):

| कुंजी                                    | डिफ़ॉल्ट     |
| -------------------------------------- | ----------- |
| `frequency`                            | `0 3 * * *` |
| `phases.deep.minScore`                 | `0.8`       |
| `phases.deep.minRecallCount`           | `3`         |
| `phases.deep.minUniqueQueries`         | `3`         |
| `phases.deep.recencyHalfLifeDays`      | `14`        |
| `phases.deep.maxAgeDays`               | `30`        |
| `phases.deep.maxPromotedSnippetTokens` | `160`       |

```json
{
  "plugins": {
    "entries": {
      "memory-core": {
        "config": {
          "dreaming": {
            "enabled": true
          }
        }
      }
    }
  }
}
```

कुंजियों की पूरी सूची और चरण विवरण: [Dreaming](/hi/concepts/dreaming),
[मेमोरी कॉन्फ़िगरेशन संदर्भ](/hi/reference/memory-config#dreaming)।

## SecretRef Gateway निर्भरता

यदि Active Memory के रिमोट API कुंजी फ़ील्ड SecretRefs के रूप में कॉन्फ़िगर किए गए हैं, तो `memory`
कमांड उन्हें सक्रिय Gateway स्नैपशॉट से रिज़ॉल्व करते हैं; यदि Gateway
अनुपलब्ध है, तो कमांड तुरंत विफल हो जाता है। इसके लिए `secrets.resolve`
विधि का समर्थन करने वाला Gateway आवश्यक है; पुराने Gateway अज्ञात-विधि त्रुटि लौटाते हैं।
