OpenClaw चार अपडेट चैनलों के साथ आता है:

- **stable**: npm dist-tag `latest`. अधिकांश उपयोगकर्ताओं के लिए अनुशंसित।
- **extended-stable**: npm dist-tag `extended-stable`. नवीनतम रिलीज़ से पीछे रहने वाला,
  समर्थित-माह का एक नया पैकेज चैनल। यह केवल पैकेज के लिए है, और इसकी स्थापना
  केवल फ़ोरग्राउंड में होती है। संग्रहीत चयन को केवल-पढ़ने योग्य अपडेट संकेत मिलते हैं जब
  `update.checkOnStart` सक्षम हो, लेकिन वे कभी स्वचालित रूप से लागू नहीं होते।
- **beta**: npm dist-tag `beta`. जब `beta` अनुपलब्ध हो
  या वर्तमान stable रिलीज़ से पुराना हो, तो `latest` पर फ़ॉलबैक करता है।
- **dev**: `main` (git) का गतिशील हेड। प्रकाशित होने पर npm dist-tag `dev`। `main`
  प्रयोग और सक्रिय विकास के लिए है; इसमें अधूरी
  सुविधाएँ या ब्रेकिंग बदलाव हो सकते हैं। इसे प्रोडक्शन gateways के लिए न चलाएँ।

Stable बिल्ड आम तौर पर पहले **beta** पर जारी किए जाते हैं, वहाँ उनकी जाँच होती है, फिर उन्हें
संस्करण बढ़ाए बिना **latest** पर पदोन्नत किया जाता है। अनुरक्षक सीधे
`latest` पर भी प्रकाशित कर सकते हैं। npm इंस्टॉलेशन के लिए dist-tags ही प्रामाणिक स्रोत हैं।

## चैनल बदलना

```bash
openclaw update --channel stable
openclaw update --channel extended-stable
openclaw update --channel beta
openclaw update --channel dev
```

`--channel` चयन को कॉन्फ़िगरेशन में `update.channel` के रूप में सहेजता है और दोनों
इंस्टॉलेशन पथों को नियंत्रित करता है:

| चैनल             | npm/package इंस्टॉलेशन                                                                                                                                                                 | git इंस्टॉलेशन                                                                                                                                                     |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `stable`          | dist-tag `latest`                                                                                                                                                                      | नवीनतम stable git टैग (`-alpha.N`, `-beta.N`, `-rc.N`, `-dev.N`, `-next.N`, `-preview.N`, `-canary.N`, `-nightly.N`, और अन्य नामित प्रीरिलीज़ प्रत्ययों को छोड़कर) |
| `extended-stable` | सार्वजनिक npm `extended-stable` चयनकर्ता को रिज़ॉल्व करता है, चुने गए सटीक पैकेज को सत्यापित करता है, और वही सटीक संस्करण इंस्टॉल करता है। `latest`, `beta`, या `dev` पर किसी फ़ॉलबैक के बिना विफलता पर बंद हो जाता है। | असमर्थित: OpenClaw चेकआउट को अपरिवर्तित छोड़ता है और आपको पैकेज इंस्टॉलेशन का उपयोग करने के लिए कहता है                                                              |
| `beta`            | dist-tag `beta`, जब `beta` अनुपलब्ध या पुराना हो तो `latest` पर फ़ॉलबैक                                                                                                              | नवीनतम beta git टैग; beta अनुपलब्ध या पुराना होने पर नवीनतम stable git टैग पर फ़ॉलबैक                                                                              |
| `dev`             | dist-tag `dev` (दुर्लभ; अधिकांश dev उपयोगकर्ता git इंस्टॉलेशन चलाते हैं)                                                                                                                               | फ़ेच करता है, चेकआउट को अपस्ट्रीम `main` ब्रांच पर रीबेस करता है, बिल्ड करता है, और वैश्विक CLI को फिर से इंस्टॉल करता है                                           |

`dev` git इंस्टॉलेशन के लिए, डिफ़ॉल्ट चेकआउट `~/openclaw` है (या
`OPENCLAW_HOME` सेट होने पर `$OPENCLAW_HOME/openclaw`); इसे
`OPENCLAW_GIT_DIR` से ओवरराइड करें।

<Tip>
stable और dev को समानांतर रखने के लिए, दो अलग-अलग चेकआउट का उपयोग करें और प्रत्येक gateway को उसके अपने चेकआउट पर निर्देशित करें।
</Tip>

## किसी एक संस्करण या टैग को लक्षित करना

सहेजे गए चैनल को बदले **बिना** किसी एक अपडेट के लिए विशिष्ट dist-tag, संस्करण, या पैकेज स्पेक
को लक्षित करने हेतु `--tag` का उपयोग करें:

```bash
# कोई विशिष्ट संस्करण इंस्टॉल करें
openclaw update --tag 2026.4.1-beta.1

# beta dist-tag से इंस्टॉल करें (केवल एक बार, सहेजा नहीं जाता)
openclaw update --tag beta

# गतिशील GitHub main चेकआउट पर जाएँ (स्थायी)
openclaw update --channel dev

# कोई विशिष्ट npm पैकेज स्पेक इंस्टॉल करें
openclaw update --tag openclaw@2026.4.1-beta.1

# चैनल सहेजे बिना GitHub main से एक बार इंस्टॉल करें
openclaw update --tag main
```

टिप्पणियाँ:

- `--tag` केवल **पैकेज (npm) इंस्टॉलेशन** पर लागू होता है; git इंस्टॉलेशन इसे अनदेखा करते हैं।
- टैग सहेजा नहीं जाता; अगला `openclaw update` कॉन्फ़िगर किए गए
  चैनल का उपयोग करता है।
- `--tag main` उस एक रन के लिए npm-संगत स्पेक `github:openclaw/openclaw#main`
  पर मैप होता है। स्थायी गतिशील `main` इंस्टॉलेशन के लिए,
  `openclaw update --channel dev` का उपयोग करें (पैकेज इंस्टॉलेशन git चेकआउट पर स्विच होते हैं)
  या इंस्टॉलर की git विधि से फिर से इंस्टॉल करें:
  `curl -fsSL https://openclaw.ai/install.sh | bash -s -- --install-method git --version main`।
  npm इंस्टॉलेशन पथ GitHub/git स्रोत लक्ष्यों को सीधे अस्वीकार करता है और
  इसके बजाय आपको git विधि की ओर निर्देशित करता है।
- डाउनग्रेड सुरक्षा: यदि लक्ष्य संस्करण वर्तमान संस्करण से पुराना है,
  तो OpenClaw पुष्टि माँगता है (`--yes` से इसे छोड़ें)।
- Extended-stable हमेशा अपने सत्यापित सटीक पैकेज लक्ष्य का उपयोग करता है। यह
  `--tag extended-stable` का एक-बार उपयोग वाला उपनाम नहीं है, और `--tag` को
  प्रभावी extended-stable चैनल के साथ संयोजित नहीं किया जा सकता।
- `--channel beta`, `--tag beta` से अलग है: beta अनुपलब्ध या
  पुराना होने पर चैनल प्रवाह stable/latest पर फ़ॉलबैक कर सकता है, जबकि `--tag beta`
  उस एक रन के लिए हमेशा मूल `beta` dist-tag को लक्षित करता है।

## ड्राई रन

बिना कोई बदलाव किए देखें कि `openclaw update` क्या करेगा:

```bash
openclaw update --dry-run
openclaw update --channel beta --dry-run
openclaw update --tag 2026.4.1-beta.1 --dry-run
openclaw update --dry-run --json
```

ड्राई रन प्रभावी चैनल, लक्ष्य संस्करण, नियोजित कार्रवाइयों,
और डाउनग्रेड की पुष्टि आवश्यक होगी या नहीं, इसकी जानकारी देता है।

## Plugins और चैनल

`openclaw update` से चैनल बदलने पर Plugin स्रोत भी सिंक होते हैं:

- `dev` ऐसे इंस्टॉल किए गए Plugins को, जिनका बंडल किया हुआ समकक्ष उपलब्ध है, वापस
  उनके बंडल किए हुए (git चेकआउट) स्रोत पर स्विच करता है।
- `stable` और `beta` npm या ClawHub से इंस्टॉल किए गए Plugin
  पैकेज पुनर्स्थापित करते हैं।
- `extended-stable` bare/default या `latest` अभिप्राय वाले योग्य आधिकारिक npm Plugins
  को इंस्टॉल किए गए core के सटीक संस्करण पर रिज़ॉल्व करता है। यह रनटाइम पर
  Plugin `@extended-stable` टैग के लिए क्वेरी नहीं करता।
- npm से इंस्टॉल किए गए Plugins, core अपडेट पूरा होने के बाद अपडेट किए जाते हैं।

## वर्तमान स्थिति जाँचना

```bash
openclaw update status
```

सक्रिय चैनल (साथ में वह स्रोत जिसने इसे निर्धारित किया: कॉन्फ़िगरेशन, git टैग,
git ब्रांच, इंस्टॉल किया गया संस्करण, या डिफ़ॉल्ट), इंस्टॉलेशन प्रकार (git या पैकेज),
वर्तमान संस्करण, और अपडेट उपलब्धता दिखाता है।

## टैगिंग की सर्वोत्तम प्रथाएँ

- उन रिलीज़ को टैग करें जिन पर आप git चेकआउट को पहुँचाना चाहते हैं: stable के लिए `vYYYY.M.PATCH`,
  beta के लिए `vYYYY.M.PATCH-beta.N`। नामित प्रीरिलीज़ प्रत्यय, जैसे
  `-alpha.N`, `-rc.N`, और `-next.N`, stable या beta लक्ष्य नहीं हैं।
- `vYYYY.M.PATCH-1` और `v1.0.1-1` जैसे पुराने संख्यात्मक stable टैग अब भी
  संगतता के लिए stable git टैग के रूप में पहचाने जाते हैं।
- `vYYYY.M.PATCH.beta.N` (बिंदु से अलग किया हुआ) भी संगतता के लिए पहचाना जाता है;
  `-beta.N` को प्राथमिकता दें।
- टैग को अपरिवर्तनीय रखें: किसी टैग को कभी स्थानांतरित या पुनः उपयोग न करें।
- npm इंस्टॉलेशन के लिए npm dist-tags ही प्रामाणिक स्रोत बने रहते हैं:
  - `latest` -> stable
  - `extended-stable` -> पीछे रहने वाली समर्थित-माह पैकेज रिलीज़
  - `beta` -> उम्मीदवार बिल्ड या beta-first stable बिल्ड
  - `dev` -> main स्नैपशॉट (वैकल्पिक)

## macOS ऐप की उपलब्धता

Beta और dev बिल्ड में macOS ऐप रिलीज़ **शामिल नहीं** हो सकती। यह स्वीकार्य है:

- git टैग और npm dist-tag फिर भी स्वतंत्र रूप से प्रकाशित किए जा सकते हैं।
- रिलीज़ नोट्स या changelog में "इस beta के लिए कोई macOS बिल्ड नहीं है" स्पष्ट रूप से लिखें।
