Codex पर्यवेक्षण आधिकारिक `codex` Plugin की एक वैकल्पिक क्षमता है। यह
Gateway कंप्यूटर और विकल्प चुने गए युग्मित कंप्यूटरों से गैर-संग्रहीत Codex CLI,
VS Code, Atlas और ChatGPT स्रोत सत्रों को सामान्य सत्र
साइडबार और Chat फलक में दिखाता है।

प्रारंभिक रिलीज़ जानबूझकर स्वामित्व को सीमित रखती है:

- संग्रहीत या निष्क्रिय स्थानीय सत्र अपने सीमित स्थायी उपयोगकर्ता और सहायक
  इतिहास से मॉडल-लॉक किया हुआ OpenClaw Chat बना सकता है। पहला संदेश एक
  मूल स्नैपशॉट फ़ोर्क बनाता है, फिर पूर्ण Codex हार्नेस थ्रेड को ठीक उसी
  मॉडल और प्रदाता के साथ शुरू करता है जिसे Codex App Server ने उस फ़ोर्क के लिए चुना था। बाद के
  टर्न कैनोनिकल मूल थ्रेड की स्थायी जोड़ी को पुनर्स्थापित करते हैं, जबकि
  पर्यवेक्षित बाइंडिंग OpenClaw को किसी अन्य रनटाइम,
  मॉडल या फ़ॉलबैक से बदलने से रोकती है। एक अलग मूल Codex नियंत्रण फिर भी उस
  स्थायी जोड़ी को बदल सकता है। पहले से बनाई गई शाखा अपना मौजूदा Chat खोलती है।
- किसी अन्य Codex प्रक्रिया से मिला संग्रहीत सत्र अज्ञात लाइव
  गतिविधि वाला होता है। इसकी शाखा बनाई जा सकती है, या इसे तभी संग्रहीत किया जा सकता है जब ऑपरेटर
  पुष्टि करे कि कोई अन्य Codex क्लाइंट इसका उपयोग नहीं कर रहा है।
- सक्रिय स्रोत दृश्यमान रहता है, लेकिन उसका वर्तमान टर्न पूरा होने तक
  उसकी शाखा नहीं बनाई जा सकती और न ही उसे संग्रहीत किया जा सकता है। यदि उसमें पहले से पर्यवेक्षित Chat है, तो **Chat खोलें**
  उपलब्ध रहता है।
- युग्मित Node पर सत्र अपने स्थायी ट्रांसक्रिप्ट को सीमित,
  कर्सर-पृष्ठांकित App Server रीड के माध्यम से उपलब्ध कराता है। दूरस्थ निरंतरता
  के लिए भविष्य के स्ट्रीमिंग Node ब्रिज की आवश्यकता है; दूरस्थ संग्रहण के लिए इसके अतिरिक्त
  रनर-स्वामित्व लीज़ या समतुल्य फ़ेंसिंग की आवश्यकता है।
- संग्रहीत सत्र सूचीबद्ध नहीं होते। संग्रहीत या निष्क्रिय स्थानीय सत्र को
  तभी संग्रहीत किया जा सकता है जब ऑपरेटर पुष्टि करे कि कोई अन्य Codex क्लाइंट इसका उपयोग नहीं कर
  रहा है।

## शुरू करने से पहले

- Gateway पर आधिकारिक `@openclaw/codex` Plugin इंस्टॉल करें। OpenClaw
  macOS ऐप Codex सुविधाएँ सक्षम करने पर इसे इंस्टॉल कर सकता है; CLI इंस्टॉलेशन
  `openclaw plugins install @openclaw/codex` चला सकते हैं।
- उन सभी कंप्यूटरों पर Codex Desktop या Codex CLI इंस्टॉल करें और साइन इन करें, जिनके
  सत्र आप सूचीबद्ध करना चाहते हैं।
- दूरस्थ कंप्यूटरों को OpenClaw Node के रूप में युग्मित करें। प्रत्येक कंप्यूटर को स्थानीय रूप से विकल्प चुनना होगा;
  केवल Gateway पर पर्यवेक्षण सक्षम करने से किसी अन्य Node को प्राधिकरण नहीं मिलता।
- स्वामी-नियंत्रित Gateway का उपयोग करें। सत्र शीर्षक, कार्यशील डायरेक्टरी और Git
  शाखाएँ संवेदनशील परियोजना जानकारी प्रकट कर सकती हैं।

## पर्यवेक्षण सक्षम करें

निर्देशित `openclaw onboard` और macOS प्रथम-रन सेटअप, मूल Codex इंस्टॉलेशन का पता लगाने और
चयनित अनुमान बैकएंड को सफलतापूर्वक सक्रिय करने के बाद Codex पर्यवेक्षण इंस्टॉल और
सक्षम करने का प्रयास करते हैं। Codex का प्राथमिक बैकएंड होना आवश्यक नहीं है।
उस अवसरानुकूल Plugin सक्रियण के सफल होने पर पर्यवेक्षण उपलब्ध हो जाता है। पर्यवेक्षण के
पहली बार कनेक्ट होने पर App Server की उपलब्धता जाँची जाती है। Codex Plugin को स्पष्ट रूप से अक्षम करना या नीति द्वारा अवरुद्ध करना
अवसरानुकूल सक्रियण को रोकता है, और मौजूदा स्पष्ट
`supervision.enabled: false` एजेंट-सामना करने वाले पर्यवेक्षण टूल अक्षम करता है;
जब भी Codex Plugin सक्रिय हो, ऑपरेटर कैटलॉग पंजीकृत रहता है, जब तक कि
`sessionCatalog.enabled: false` उसे अक्षम न करे। यह अलग स्विच
Codex प्रदाता, हार्नेस और एजेंट-सामना करने वाली पर्यवेक्षण नीति को अपरिवर्तित रखता है, साथ ही
इस होस्ट से युग्मित-Node कैटलॉग सूची/रीड कमांड भी हटा देता है।
मौजूदा इंस्टॉलेशन यही क्षमता मैन्युअल रूप से सक्षम कर सकते हैं:

`openclaw.json` में `codex` Plugin और उसकी पर्यवेक्षण क्षमता सक्षम करें:

```json5
{
  plugins: {
    entries: {
      codex: {
        enabled: true,
        config: {
          supervision: {
            enabled: true,
          },
        },
      },
    },
  },
}
```

यदि `plugins.allow` मौजूद है, तो `codex` शामिल करें। Plugin सक्रियण बदलने के बाद
Gateway पुनः आरंभ करें।

किसी स्पष्ट `appServer` कनेक्शन सेटिंग के बिना, पर्यवेक्षण मूल उपयोगकर्ता Codex होम के विरुद्ध
एक अलग प्रबंधित stdio पर्यवेक्षण कनेक्शन का उपयोग करता है। सामान्य
Codex हार्नेस डिफ़ॉल्ट रूप से एजेंट-स्कोप्ड रहता है। इससे सामान्य OpenClaw टर्न द्वारा
मूल Codex स्थिति साझा किए बिना, मूल सत्र दोनों ऐप में दृश्यमान होते हैं।
यदि हार्नेस को भी वह स्थिति साझा करनी चाहिए, तो `appServer.homeScope: "user"` स्पष्ट रूप से सेट करें।
पर्यवेक्षण स्पष्ट `appServer` कनेक्शन सेटिंग को अपने स्थानीय उपयोगकर्ता-होम डिफ़ॉल्ट से बदलने के बजाय
उनका पालन करता है।

**Codex** साइडबार समूह से अपनाया गया Chat कोई सामान्य हार्नेस सत्र नहीं है।
उसकी निजी पर्यवेक्षण बाइंडिंग स्रोत
रीड, कैनोनिकल शाखा निर्माण, इतिहास इंजेक्शन और प्रत्येक बाद के टर्न के लिए पर्यवेक्षण कनेक्शन का उपयोग करती है।
डिफ़ॉल्ट स्थानीय कनेक्शन के साथ, यह अन्य सत्रों का डिफ़ॉल्ट बदले बिना
मूल उपयोगकर्ता Codex होम, प्रमाणीकरण और प्रदाता कॉन्फ़िगरेशन को सुरक्षित रखता है।
देखे जा रहे अपनाए गए Chat [सत्र स्थिति जागरूकता](/hi/concepts/session-state) में भी भाग लेते हैं।

डिफ़ॉल्ट स्थानीय पर्यवेक्षण कनेक्शन के लिए, स्टोर मूल
Codex क्लाइंट के साथ साझा किया जाता है। OpenClaw यह नहीं मानता कि कोई अन्य क्लाइंट वही लाइव
App Server प्रक्रिया साझा करता है, और मूल स्थिति स्वामित्व प्रक्रिया-स्थानीय होता है। इसलिए यह
उस थ्रेड को, जिसे उसका पर्यवेक्षण App Server `notLoaded` के रूप में रिपोर्ट करता है,
निष्क्रिय नहीं बल्कि **संग्रहीत / गतिविधि अज्ञात** मानता है।

हर उस हेडलेस Node होस्ट पर वही विकल्प लागू करें जिसके सत्र दिखने चाहिए।
मूल OpenClaw macOS ऐप अपने Codex कैटलॉग को युग्मित Gateway पर विज्ञापित करते समय
वही स्थानीय सेटिंग पढ़ता है। वह युग्मित मूल Mac कैटलॉग केवल डिफ़ॉल्ट या स्पष्ट
`appServer.transport: "stdio"` का समर्थन करता है, जिसमें `appServer.homeScope: "user"` अनसेट या
स्पष्ट हो। उस stdio प्रक्रिया के लिए `command`, `args` और `clearEnv` का
पालन किया जाता है। यदि Mac कॉन्फ़िगरेशन `"unix"`,
`"websocket"` या `homeScope: "agent"` चुनता है, तो ऐप कैटलॉग
क्षमता या कमांड विज्ञापित नहीं करता, और पुराना प्रत्यक्ष आह्वान उपयोगकर्ता Codex होम को उजागर करने या
कोई अलग स्थानीय stdio App Server शुरू करने के बजाय विफल हो जाता है।

नई विज्ञापित Node कमांड, Node की स्वीकृत कमांड सतह बदलती है।
Gateway होस्ट से अपडेट स्वीकृत करें:

```bash
openclaw nodes pending
openclaw nodes approve <requestId>
```

गैर-संग्रहीत Codex सत्र मुख्य Control UI साइडबार में भी होस्ट के अनुसार समूहबद्ध होकर
दिखाई देते हैं। उसका स्थायी ट्रांसक्रिप्ट पढ़ने के लिए किसी एक को चुनें। व्यूअर नवीनतम
Codex `thread/turns/list` API को `itemsView: "full"` के साथ उपयोग करता है और प्रत्येक अनुरोध में अधिकतम 20 टर्न
लोड करता है; **पुराने ट्रांसक्रिप्ट आइटम लोड करें** नवीनतम पृष्ठ से अपारदर्शी App Server कर्सर का अनुसरण करता है।
लोड किए गए पृष्ठ कालानुक्रमिक क्रम में रेंडर होते हैं। व्यूअर कभी भी असीमित
`thread/read` इतिहास लोड नहीं करता। 20 MiB परिवहन सुरक्षा सीमा से बड़ा पृष्ठ
Node या Gateway कनेक्शन को जोखिम में डालने के बजाय सुरक्षित रूप से विफल होता है।

सामान्य सत्र साइडबार में **Codex** समूह खोलें। यह उन्हीं सत्रों को
होस्ट के अनुसार समूहबद्ध करके सूचीबद्ध करता है। **और सत्र लोड करें** पुराने रिकॉर्ड वाले प्रत्येक होस्ट का अगला पृष्ठ
जोड़ता है, और जोड़े गए वे रिकॉर्ड साइडबार के आवधिक रीफ़्रेश के बाद भी बने रहते हैं।
प्रत्येक होस्ट अपनी मूल सूची तैयार होते ही दिखाई देता है। दृश्यमान पृष्ठ
Node कनेक्टिविटी बदलने के बाद, दोबारा फ़ोकस मिलने पर और अधिकतम
हर 30 सेकंड में समन्वय करता है; बदले हुए परिणाम पर तेज़ अनुवर्ती चरण चलता है। इसलिए Codex Desktop,
CLI या किसी अन्य मूल क्लाइंट में बनाए गए सत्र पूर्ण
पृष्ठ रीलोड के बिना दिखाई देते हैं। पहला पृष्ठ Codex के अपने सबसे-हाल में अपडेट किए गए क्रम का अनुसरण करता है,
इसलिए नया बनाया गया मूल सत्र तुरंत पात्र होता है।
प्रत्येक लौटाया गया खोज पृष्ठ क्वेरी को App Server को भेजने के बजाय प्रति होस्ट
मूल पृष्ठों की सीमित संख्या स्कैन करता है, क्योंकि मूल खोज ट्रांसक्रिप्ट पूर्वावलोकनों से भी
मेल खा सकती है।

होस्ट उपलब्धता और थ्रेड स्थिति अलग हैं। **ऑफ़लाइन** या **अनुपलब्ध**
होस्ट रीफ़्रेश का वर्णन करता है; अनुपलब्ध होस्ट कोई नया सत्र रिकॉर्ड नहीं लौटाता और
किसी थ्रेड की मूल स्थिति को `offline` में नहीं बदलता। सत्र रिकॉर्ड `idle`,
`active`, `notLoaded` या त्रुटि जैसी Codex स्थितियों का उपयोग करते हैं। विफल होस्ट
स्वस्थ होस्ट के परिणाम नहीं छिपाता।

साइडबार चेतावनी में कैटलॉग त्रुटि कोड और सुरक्षित अंतर्निहित
Gateway त्रुटि शामिल होती है। Codex को अक्षम किए बिना खोज अक्षम करने के लिए
**Settings > Automation > Plugins > Codex > Native Session
Discovery** खोलें।
`NODE_LIST_FAILED` के लिए, `openclaw nodes list` और **Settings > Devices** की तुलना करें;
विस्तृत कारण उस pairing-store, node-registry, अनुमति या
Gateway जीवनचक्र विफलता की पहचान करता है जिसकी मरम्मत आवश्यक है।

## ऑपरेटर CLI का उपयोग करें

टर्मिनल CLI वही गैर-संग्रहीत कैटलॉग और Gateway-स्थानीय शाखा
तथा संग्रह क्रियाएँ उपलब्ध कराता है:

```bash
openclaw codex sessions [--search <text>] [--host <id>] [--limit <count>] [--cursor <cursor>] [--json] [--url <url>] [--token <token>] [--timeout <ms>] [--expect-final]
openclaw codex continue <thread-id> [--json] [--url <url>] [--token <token>] [--timeout <ms>] [--expect-final]
openclaw codex archive <thread-id> --confirm-no-other-runner [--json] [--url <url>] [--token <token>] [--timeout <ms>] [--expect-final]
```

`openclaw codex sessions` विकल्प:

- `--search <text>` सत्र शीर्षकों में अक्षर-स्थिति की परवाह किए बिना खोज करता है।
- `--host <id>` प्रतिक्रिया को एक स्थिर कैटलॉग होस्ट, जैसे
  `gateway:local` या `node:<node-id>`, तक सीमित करता है।
- `--limit <count>` प्रति होस्ट 1 से 100 रिकॉर्ड सेट करता है; डिफ़ॉल्ट 50 है।
- `--cursor <cursor>` एक होस्ट पृष्ठ जारी रखता है और इसलिए `--host` आवश्यक है।
- `--json` संरचित Gateway प्रतिक्रिया प्रिंट करता है।

तीनों कमांड Gateway क्लाइंट से `--url`, `--token` और `--timeout <ms>`
प्राप्त करते हैं। सत्र सूचीकरण का डिफ़ॉल्ट 75,000 ms है, ताकि कोल्ड युग्मित-Node
कैटलॉग पूरे हो सकें; जारी रखने और संग्रह करने का डिफ़ॉल्ट 30,000 ms है। वे साझा
`--expect-final` स्विच भी उपलब्ध कराते हैं, जो इन यूनरी पर्यवेक्षण RPC को नहीं बदलता।
प्रत्येक कमांड के लिए `operator.write` Gateway स्कोप आवश्यक है।
प्रत्येक उपकमांड पर मानक `-h, --help` आउटपुट उपलब्ध है।
कोई संग्रहीत या संग्रहीत-शामिल करने का विकल्प नहीं है। `sessions` युग्मित
होस्ट सूचीबद्ध कर सकता है, लेकिन `continue` और `archive` हमेशा `gateway:local` को लक्षित करते हैं;
युग्मित रिकॉर्ड केवल सूचीकरण के लिए हैं। संग्रह के लिए हमेशा `--confirm-no-other-runner` आवश्यक है।

ये शेल कमांड इन-Chat `/codex` रनटाइम कमांड से अलग हैं।
`/codex threads [filter]` वर्तमान
वार्तालाप कनेक्शन के लिए उपलब्ध App Server थ्रेड सूचीबद्ध करता है। `/codex sessions --host <node>` पर्यवेक्षण फ़्लीट कैटलॉग नहीं, बल्कि एक Node पर
फिर से शुरू किए जा सकने वाले Codex CLI सत्र फ़ाइलें सूचीबद्ध करता है। `/codex
resume` और `/codex bind` सुरक्षित पर्यवेक्षित शाखा बनाने के बजाय
वर्तमान वार्तालाप संलग्न करते हैं, और मॉडल-लॉक किया हुआ पर्यवेक्षित Chat उन
बाइंडिंग परिवर्तनों को अस्वीकार करता है। कोई `/codex continue` या `/codex archive` रनटाइम
कमांड नहीं है।

## स्थानीय सत्र से शाखा बनाएँ

Gateway कंप्यूटर के किसी संग्रहीत या निष्क्रिय रिकॉर्ड पर **शाखा के रूप में जारी रखें** चुनें।
OpenClaw एक सामान्य Chat प्रविष्टि बनाता है, अंतिम टर्मिनल स्थायी टर्न
(पूर्ण, बाधित या विफल) तक स्रोत के सीमित उपयोगकर्ता और सहायक इतिहास को मिरर करता है,
लंबित हार्नेस शाखा रिकॉर्ड करता है और Chat खोलता है। सामान्य मॉडल
पिकर लॉक रहता है, लेकिन अभी तक कोई ठोस मॉडल या प्रदाता नहीं चुना गया है।
स्रोत फिर से शुरू नहीं होता और कैनोनिकल हार्नेस थ्रेड भी अभी शुरू नहीं होता।
क्रिया दोहराने पर दूसरी शाखा बनाने के बजाय मौजूदा Chat खुलता है।

मिरर उस नवीनतम दृश्यमान अंतिम भाग को रखता है जो तीनों सीमाओं में समाता है: अधिकतम 200
उपयोगकर्ता या सहायक संदेश, कुल 512 KiB UTF-8 टेक्स्ट और प्रति
संदेश 64 KiB। अत्यधिक बड़े संदेश मार्कर के साथ काटे जाते हैं और सीमा पूरी होने पर
पुराने संदेश छोड़ दिए जाते हैं। छवि या स्थानीय-छवि इनपुट शाब्दिक
`[Image attachment]` प्लेसहोल्डर बन जाता है; छवि डेटा और स्थानीय पथ कॉपी नहीं किए जाते।

काम शुरू करने के लिए पहला सामान्य चैट संदेश भेजें। Codex हार्नेस वास्तविक
अनुमोदन, जानकारी माँगने, इवेंट और डिलीवरी हैंडलर इंस्टॉल करता है। यह स्रोत
स्नैपशॉट को पिन करने के लिए पर्यवेक्षण कनेक्शन पर एक अस्थायी नेटिव फ़ोर्क का
उपयोग करता है, बिना कोई मॉडल या प्रदाता ओवरराइड दिए। Codex App Server अपने
वर्तमान नेटिव कॉन्फ़िगरेशन से दोनों का चयन करता है और वास्तविक चयन लौटाता है।
उसी कनेक्शन पर, OpenClaw अपने cwd और रनटाइम नीति के अंतर्गत ठीक उसी लौटाई गई
जोड़ी के साथ विहित `appServer`-स्रोत पूर्ण हार्नेस थ्रेड शुरू करता है, सीमित
दृश्यमान इतिहास इंजेक्ट करता है और अस्थायी फ़ोर्क को आर्काइव करता है। विहित थ्रेड
के पास OpenClaw हार्नेस की पूरी टूल सतह होती है। यह दृश्यमान-इतिहास शाखा है,
पूर्ण नेटिव रोलआउट क्लोन नहीं: स्रोत रीजनिंग, टूल कॉल और टूल परिणाम छोड़ दिए
जाते हैं। यह और इसके बाद का प्रत्येक टर्न किसी अन्य OpenClaw मॉडल रनटाइम या
सामान्य एजेंट-होम हार्नेस के बजाय पर्यवेक्षित Codex कनेक्शन पर बना रहता है।

लौटाया गया चयन स्रोत के ऐतिहासिक मॉडल का प्रमाण नहीं है। यदि वर्तमान नेटिव
कॉन्फ़िगरेशन स्रोत के अंतिम टर्न के लिए दर्ज मॉडल से अलग है, तो Codex अपनी
सामान्य मॉडल-अंतर चेतावनी देता है। OpenClaw विहित थ्रेड शुरू करने के लिए लौटाई
गई जोड़ी का उपयोग करता है। Codex उस विहित थ्रेड के नेटिव मॉडल और प्रदाता को
स्थायी रूप से सहेजता है, और बाद में फिर से शुरू करने पर वे सुरक्षित रहते हैं
क्योंकि OpenClaw मॉडल और प्रदाता ओवरराइड नहीं देता। यदि विहित थ्रेड को किसी
अलग नेटिव Codex नियंत्रण से बदला जाता है, तो OpenClaw Codex के स्थायी रूप से
सहेजे गए चयन को स्वीकार करता है। OpenClaw कभी भी उसके स्थान पर अपना बाहरी
मॉडल या फ़ॉलबैक श्रृंखला नहीं लगाता।

पर्यवेक्षित मॉडल-लॉक चैट को हटाया नहीं जा सकता, उसमें मॉडल नहीं बदले जा सकते,
`/new` या `/reset` का उपयोग नहीं किया जा सकता, Gateway सत्र-रीसेट
कार्रवाई लागू नहीं की जा सकती और सामान्य **Fork session** कार्रवाई का उपयोग
नहीं किया जा सकता। `/codex model <model>`, `/codex
bind`, `/codex resume` (जिसमें `--bind here` वाला Node सत्र शामिल है) और
`/codex detach` या `/codex unbind` को बदलना भी अस्वीकार किया जाता है, क्योंकि इससे
लॉक की गई नेटिव बाइंडिंग बदल या साफ़ हो जाएगी। `/codex model` क्वेरी तथा
`/codex fast`, `/codex permissions` और `/codex threads` उपलब्ध रहते हैं। जब अलग मॉडल
या नया थ्रेड चाहिए, तब एक अन्य सामान्य सत्र शुरू करें।

इस चैट के लिए पर्यवेक्षण सक्षम रखें। यदि पर्यवेक्षण अक्षम कर दिया जाता है या
उसकी संग्रहीत कनेक्शन बाइंडिंग अनुपलब्ध या असंगत हो जाती है, तो सामान्य
एजेंट-होम सत्र पर जाने के बजाय टर्न सुरक्षित रूप से विफल हो जाता है।

`codex` Plugin को अक्षम या अनइंस्टॉल करने से वह स्वामित्व मुक्त नहीं होता और
चैट किसी अन्य मॉडल के लिए पात्र नहीं बनता। लॉक किया गया चैट सुरक्षित रहता है,
लेकिन अनुपलब्ध हो जाता है; इसे फिर से शुरू करने के लिए वही Plugin पुनः इंस्टॉल
या सक्षम करें और Gateway रीस्टार्ट करें। जानबूझकर किया गया यह सुरक्षित-विफल
व्यवहार रिटेंशन क्लीनअप या Plugin की अस्थायी अनुपलब्धता के कारण नेटिव बाइंडिंग
के बिना सूचना अनाथ हो जाने से रोकता है।

`codex_threads` एजेंट टूल भी इसी सीमा का पालन करता है। यह कोई अलग फ़ोर्क संलग्न
नहीं कर सकता और न ही चैट के बाउंड नेटिव थ्रेड को आर्काइव कर सकता है। सूची और
केवल-मेटाडेटा रीड उपलब्ध रहते हैं। रॉ ट्रांसक्रिप्ट रीड के लिए `allowRawTranscripts`
आवश्यक है। रॉ एक्सेस अक्षम होने पर `codex_threads` सूची खोज को भी अस्वीकार
करता है, क्योंकि नेटिव खोज में ट्रांसक्रिप्ट पूर्वावलोकन शामिल होते हैं;
Control UI और ऑपरेटर CLI अब भी सीमित केवल-शीर्षक खोज प्रदान करते हैं। किसी
असंबंधित और अस्वामित्व वाले थ्रेड का नाम बदलने, अनआर्काइव करने, अलग फ़ोर्क
बनाने और आर्काइव करने के लिए
`allowWriteControls` आवश्यक है। कोई भी विकल्प लॉक की गई बाइंडिंग को बायपास नहीं करता।

OpenClaw केवल स्रोत थ्रेड सूचीबद्ध करते या लंबित चैट दिखाते समय अनुमोदन अनुरोधों
की सदस्यता नहीं लेता और न उनका उत्तर देता है। पहले टर्न पर एक अलग विहित हार्नेस
थ्रेड शुरू करने से कोई अन्य Codex प्रक्रिया प्रतिस्पर्धी रोलआउट राइटर बनाए बिना
स्रोत का स्वामित्व बनाए रख सकती है।

मूल CLI, VS Code, Atlas या ChatGPT स्रोत नेटिव क्लाइंट और OpenClaw कैटलॉग में
दृश्यमान रहता है। विहित शाखा नेटिव Codex थ्रेड के रूप में संग्रहीत होती है,
लेकिन उसका स्रोत प्रकार `appServer` है; Codex Desktop या कोई अन्य नेटिव
क्लाइंट उस स्रोत प्रकार को फ़िल्टर कर सकता है, इसलिए स्वयं शाखा का प्रत्येक
नेटिव इतिहास दृश्य में दिखाई देना सुनिश्चित नहीं है।

OpenClaw के App Server द्वारा सक्रिय बताई गई पंक्ति नई शाखा शुरू नहीं कर सकती।
वर्तमान टर्न समाप्त होने की प्रतीक्षा करें और कैटलॉग रीफ़्रेश करें। Codex App
Server एक प्रक्रिया के भीतर बदलावों को क्रमबद्ध करता है, लेकिन यह कोई विशिष्ट
क्रॉस-प्रोसेस रनर या अनुमोदन-स्वामी लीज़ प्रदान नहीं करता।

**Stored / activity unknown** पंक्ति के लिए, चैट मिरर और पहले-टर्न का स्नैपशॉट
पिन अंतिम टर्मिनल स्थायी रूप से सहेजे गए टर्न तक Codex की स्थिति का उपयोग करते
हैं। स्रोत थ्रेड को फिर से शुरू, बाधित या आर्काइव नहीं किया जाता। यदि किसी अन्य
प्रक्रिया में कोई टर्न प्रगति पर है, तो उसका नवीनतम प्रक्रियाधीन कार्य शाखा में
मौजूद नहीं हो सकता।

## स्थानीय सत्र आर्काइव करें

संग्रहीत या निष्क्रिय Gateway-स्थानीय पंक्ति पर **Archive** चुनें, फिर पुष्टि
करें कि कोई अन्य Codex क्लाइंट या OpenClaw रनर उस थ्रेड या उससे उत्पन्न वंशजों
का उपयोग नहीं कर रहा है। OpenClaw प्रक्रिया-स्थानीय स्थिति को नए सिरे से पढ़ता
है, केवल `idle` या `notLoaded` के लिए आगे बढ़ता है, नेटिव Codex
आर्काइव कार्रवाई को कॉल करता है और सत्र को गैर-आर्काइव सूची से हटा देता है।
नेटिव Codex थ्रेड से उत्पन्न वंशजों को भी आर्काइव करने का प्रयास करता है।

जब नए रीड में सत्र सक्रिय या त्रुटि स्थिति में बताया जाए, वह किसी युग्मित Node
का हो, या किसी नए बनाए गए पर्यवेक्षित चैट में अब भी उस स्रोत से लंबित शाखा हो,
तब आर्काइव उपलब्ध नहीं होता। स्रोत को आर्काइव करने से पहले चैट की विहित शाखा
साकार करने के लिए उसका पहला संदेश भेजें। आर्काइव तब भी अवरुद्ध होता है जब
OpenClaw को पता हो कि कोई सक्रिय बाइंडिंग ठीक लक्षित थ्रेड या किसी गैर-आर्काइव
उत्पन्न वंशज की स्वामी है। OpenClaw प्रत्येक पृष्ठ पर प्रयोगात्मक Codex वंशज
क्वेरी का अनुसरण करता है; अमान्य प्रतिक्रिया, अनुरोध विफलता, दोहराया गया कर्सर
या थ्रेड, अथवा सुरक्षा-सीमा समाप्त होने पर आर्काइव अस्वीकार कर दिया जाता है।

रीड, वंशजों की गणना और आर्काइव अनुरोध एक सशर्त कार्रवाई नहीं हैं, इसलिए इनके
बीच भी कोई टर्न शुरू हो सकता है। App Server की स्थिति स्वतंत्र प्रक्रियाओं के
बीच साझा भी नहीं होती। इसलिए पुष्टि अज्ञात क्लाइंट और उस रेस के लिए सुरक्षा
सीमा है: पुष्टि करने से पहले हर अन्य क्लाइंट को बंद करें या किसी अन्य तरीके से
सत्यापित करें। आर्काइव किए गए थ्रेड को Codex Desktop, Codex CLI या
स्वामी-अधिकृत नेटिव थ्रेड-प्रबंधन प्रवाह से पुनर्स्थापित करें; अनआर्काइव होने के
बाद वह फिर दिखाई देता है।

```bash
codex unarchive <thread-id>
```

## युग्मित-Node सीमाएँ समझें

युग्मित Node संस्करणित केवल-पढ़ने योग्य
`codex.appServer.threads.list.v1` और
`codex.appServer.thread.turns.list.v1` कमांड उपलब्ध कराते हैं। जिन नेटिव Node होस्ट पर
Codex CLI उपलब्ध है, वे अनुमत-सूची वाला `codex.terminal.resume.v1`
कमांड भी उपलब्ध कराते हैं। Gateway को सामान्यीकृत
मेटाडेटा और स्पष्ट रूप से अनुरोधित सीमित ट्रांसक्रिप्ट पृष्ठ मिलते हैं, रॉ App
Server एंडपॉइंट कभी नहीं। ऑपरेटर टर्मिनल में कोई पंक्ति खोलने पर स्वामी होस्ट
पर `codex resume <thread-id>` चलता है और उस कमांड का PTY रिले होता है; इससे सामान्य
शेल या Gateway द्वारा दिया गया argv उजागर नहीं होता।

टर्मिनल रिले हार्नेस निरंतरता या आर्काइव स्वामित्व अनुबंध प्रदान नहीं करता।
इसलिए दूरस्थ पंक्तियाँ दृश्यमान रहती हैं, लेकिन दूरस्थ थ्रेड निष्क्रिय होने पर
भी **Continue** या **Archive** उपलब्ध नहीं करातीं। उस कंप्यूटर पर **Open in
terminal** के माध्यम से Codex का उपयोग करें, या सुरक्षित रनर-स्वामित्व सीमा
वाले भावी निरंतरता प्रवाह का उपयोग करें।

## मेटाडेटा और अनुमतियाँ

कैटलॉग पंक्तियों में ये शामिल हो सकते हैं:

- थ्रेड और सत्र पहचानकर्ता
- शीर्षक और कार्यशील डायरेक्टरी
- वर्तमान स्थिति और सक्रिय प्रतीक्षा फ़्लैग
- निर्माण, अपडेट और गतिविधि टाइमस्टैम्प
- स्रोत, मॉडल प्रदाता, Codex CLI संस्करण और Git शाखा

कैटलॉग प्रोजेक्शन में ट्रांसक्रिप्ट पूर्वावलोकन, टर्न, रोलआउट पथ,
Codex होम पथ, Git रिमोट, कमिट SHA और रॉ App Server त्रुटियाँ शामिल नहीं होतीं।
कैटलॉग एक्सेस और Control UI ट्रांसक्रिप्ट रीड के लिए `operator.write` Gateway
स्कोप आवश्यक है, क्योंकि फ़्लीट एकत्रीकरण मानक `node.invoke` पथ का उपयोग
करता है, भले ही दोनों Node कमांड केवल-पढ़ने योग्य हों।

`supervision.allowRawTranscripts` और `supervision.allowWriteControls`
स्वायत्त एजेंट और स्टैंडअलोन MCP टूल नियंत्रित करते हैं। दोनों का डिफ़ॉल्ट
`false` है। पर्यवेक्षण सक्षम होने पर, जब तक रॉ ट्रांसक्रिप्ट की अनुमति
न हो, `codex_threads` सूची और केवल-मेटाडेटा रीड परिणामों से ट्रांसक्रिप्ट
पूर्वावलोकन और टर्न हटा देता है; टर्न-सहित रीड सुरक्षित रूप से विफल हो जाता है।
प्रत्येक फ़ोर्क, नाम परिवर्तन, आर्काइव और अनआर्काइव के लिए राइट नियंत्रण आवश्यक
हैं। ये विकल्प प्रमाणित Control UI ट्रांसक्रिप्ट दृश्य को नियंत्रित नहीं करते
और बाइंडिंग, होस्ट, स्थिति या पुष्टि जाँच को बायपास नहीं करते।

### संगतता टूल

आधिकारिक `codex` Plugin मौजूदा एजेंट और स्टैंडअलोन MCP क्लाइंट के लिए
रिलीज़ किए गए पाँच Supervisor टूल नाम बनाए रखता है:

- `codex_endpoint_probe`
- `codex_sessions_list`
- `codex_session_read`
- `codex_session_send`
- `codex_session_interrupt`

`codex_sessions_list` डिफ़ॉल्ट रूप से केवल-लोडेड है; कोई `loaded_only`
पैरामीटर नहीं है। Codex के स्थिति डेटाबेस से गैर-आर्काइव संग्रहीत पंक्तियाँ भी
पढ़ने के लिए `include_stored: true` सेट करें। वैकल्पिक `max_stored_sessions` सीमा का
डिफ़ॉल्ट 200 है और यह प्रति एंडपॉइंट 1 से 1,000 पंक्तियाँ स्वीकार करती है। यह
लोड की गई पंक्तियों को सीमित नहीं करती। रॉ-ट्रांसक्रिप्ट अनुमति के बिना, सूची
परिणामों में ट्रांसक्रिप्ट से प्राप्त नाम, पूर्वावलोकन और विस्तृत एंडपॉइंट
त्रुटियाँ शामिल नहीं होतीं।
`codex_session_read` के लिए `allowRawTranscripts` आवश्यक है; `include_turns: true`
इसके अतिरिक्त Codex से टर्न माँगता है।

`codex_session_send` और `codex_session_interrupt` के लिए
`allowWriteControls` आवश्यक है। Send `mode: "auto" | "start" | "steer"` स्वीकार करता है, लेकिन
`"start"` हमेशा अस्वीकार किया जाता है और `"auto"` तथा `"steer"` दोनों केवल
पढ़े जा सकने वाले सक्रिय टर्न को दिशा दे सकते हैं। निष्क्रिय थ्रेड को **Codex
Sessions** का उपयोग करने के निर्देश के साथ अस्वीकार किया जाता है, जहाँ पूर्ण
हार्नेस निरंतरता से पहले अनुमोदन और टूल हैंडलर इंस्टॉल करता है। इसी तरह
इंटरप्ट के लिए भी सक्रिय और पढ़ा जा सकने वाला टर्न आवश्यक है। ये टूल निष्क्रिय
स्रोत थ्रेड को फिर से शुरू या आरंभ नहीं करते।

`openclaw doctor --fix` किसी सेवानिवृत्त `codex-supervisor` प्रविष्टि, उसके एंडपॉइंट
और अनुमति फ़ील्ड तथा Plugin अनुमति/अस्वीकृति नीति संदर्भों को स्पष्ट विहित
सेटिंग्स ओवरराइट किए बिना आधिकारिक `codex` Plugin में ले जाता है।
स्टैंडअलोन संगतता MCP एडाप्टर उसी Plugin से वही पाँच टूल लोड करना जारी रखता है;
लेगेसी नीति पर्यावरण चर केवल उस विश्वसनीय एडाप्टर के भीतर लागू होते हैं।

प्रत्येक पर्यवेक्षण कॉन्फ़िगरेशन फ़ील्ड के लिए
[Codex हार्नेस संदर्भ](/hi/plugins/codex-harness-reference#supervision) देखें।

## समस्या निवारण

**कोई सत्र दिखाई नहीं देता:** सत्यापित करें कि `@openclaw/codex` इंस्टॉल है, Plugin
और `supervision.enabled` दोनों true हैं, वर्तमान Plugin अनुमत-सूची
`codex` को अनुमति देती है और सत्र आर्काइव नहीं हैं। सक्रियण बदलने के बाद
Gateway या Node रीस्टार्ट करें।

**Continue अक्षम है:** कोई अनमैप की गई पंक्ति सक्रिय है, किसी युग्मित Node की
है, उसका होस्ट ऑफ़लाइन है या कोई अन्य कार्रवाई लंबित है। Gateway-स्थानीय
संग्रहीत और निष्क्रिय पंक्तियाँ असुरक्षित सटीक-थ्रेड अधिग्रहण के बजाय
**Continue as branch** उपलब्ध कराती हैं। जिस पंक्ति में पहले से पर्यवेक्षित चैट
है, वह **Open Chat** उपलब्ध कराती है।

**Archive अक्षम है:** किसी अन्य रनर के न होने की पुष्टि के बाद
संग्रहीत/गतिविधि-अज्ञात और निष्क्रिय Gateway-स्थानीय पंक्तियों के लिए आर्काइव
उपलब्ध होता है। सक्रिय, त्रुटिपूर्ण, ऑफ़लाइन, युग्मित-Node, लंबित-शाखा और ज्ञात
सटीक-बाइंडिंग-स्वामी पंक्तियाँ आर्काइव के लिए केवल-पढ़ने योग्य रहती हैं।

**आर्काइव किया गया सत्र गायब हो गया:** यह अपेक्षित है। पर्यवेक्षण पृष्ठ में
आर्काइव दृश्य नहीं है। इसे फिर दिखाने के लिए `codex unarchive <thread-id>` चलाएँ या Codex
Desktop का उपयोग करें।

**पुराना `codex-supervisor` कॉन्फ़िगरेशन शेष है:** `openclaw doctor --fix` चलाएँ। Doctor
स्पष्ट Codex सेटिंग्स ओवरराइट किए बिना सेवानिवृत्त Plugin प्रविष्टि और संबंधित
Plugin-नीति संदर्भों को `plugins.entries.codex.config.supervision` में ले जाता है।
