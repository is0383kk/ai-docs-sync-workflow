macOS ऐप OpenClaw का **मेन्यू बार सहायक** है: नेटिव ट्रे UI, macOS
अनुमति संकेत, सूचनाएँ, WebChat, वॉइस इनपुट, Canvas, और
Mac पर होस्ट किए गए Node टूल, जैसे `system.run`।

पूरी विंडो खोले बिना Spotlight-शैली के मुख्य-सत्र कंपोज़र के लिए **Quick Chat** का उपयोग करें। डिफ़ॉल्ट रूप से Option-Space (⌥Space) दबाएँ, इसे मेन्यू बार मेन्यू से चुनें, या **Settings → General** में कोई दूसरा शॉर्टकट रिकॉर्ड करें।

केवल CLI और Gateway चाहिए? [आरंभ करना](/hi/start/getting-started) से शुरू करें।

## डाउनलोड

macOS ऐप बिल्ड [OpenClaw GitHub रिलीज़](https://github.com/openclaw/openclaw/releases) से प्राप्त करें।
जब किसी रिलीज़ में macOS ऐप एसेट शामिल हों, तो इन्हें खोजें:

- `OpenClaw-<version>.dmg` (अनुशंसित)
- `OpenClaw-<version>.zip`

कुछ रिलीज़ में केवल CLI, प्रमाण या Windows एसेट शामिल होते हैं। यदि नवीनतम रिलीज़
में macOS ऐप एसेट नहीं है, तो ऐसे सबसे नए रिलीज़ का उपयोग करें जिसमें यह उपलब्ध हो, या
[macOS डेवलपमेंट सेटअप](/hi/platforms/mac/dev-setup) के साथ स्रोत से बिल्ड करें।

## पहली बार चलाना

1. **OpenClaw.app** इंस्टॉल करके लॉन्च करें।
2. स्थानीय Gateway के लिए **This Mac** चुनें या किसी रिमोट Gateway से कनेक्ट करें।
3. ऐप द्वारा मेल खाता CLI रनटाइम इंस्टॉल किए जाने तक प्रतीक्षा करें। स्थानीय मोड में यह
   Gateway को भी इंस्टॉल और शुरू करता है।
4. लाइव मॉडल जाँच के साथ इन्फ़रेंस स्थापित करें। इसके सफल होने के बाद OpenClaw
   शेष सेटअप संभालता है।
5. macOS अनुमति चेकलिस्ट पूरी करें और ऑनबोर्डिंग परीक्षण संदेश भेजें।

यदि ऐप किसी मौजूदा Gateway तक पहुँचता है, जिसके डिफ़ॉल्ट एजेंट में मॉडल कॉन्फ़िगर
है, तो वह उस Gateway को पहले से सेट अप मानता है, प्रदाता ऑनबोर्डिंग और
OpenClaw को छोड़ देता है और डैशबोर्ड खोलता है। यदि Gateway कनेक्ट नहीं हो सकता या उसके
डिफ़ॉल्ट एजेंट में कोई मॉडल नहीं है, तो पुनर्प्राप्ति के लिए इन्फ़रेंस ऑनबोर्डिंग उपलब्ध
रहती है।

CLI/Gateway सेटअप पथ के लिए [आरंभ करना](/hi/start/getting-started) का उपयोग करें।
अनुमति पुनर्प्राप्ति के लिए [macOS अनुमतियाँ](/hi/platforms/mac/permissions) का उपयोग करें।

## अपडेट

डैशबोर्ड अपडेट कार्ड बताता है कि ऐप क्या अपडेट करेगा:

- **Update Mac app + Gateway** का अर्थ है कि साइन किया गया ऐप स्थानीय launchd
  Gateway का स्वामी है। Sparkle पहले ऐप को अपडेट करता है; दोबारा लॉन्च होने के बाद ऐप अपने आप
  अपने Gateway को मेल खाते संस्करण पर अपडेट करके पुनः आरंभ करता है और फिर
  कनेक्शन सत्यापित करता है।
- **Update Gateway** का अर्थ है कि ऐप किसी रिमोट Gateway, मैन्युअल रूप से
  प्रबंधित स्थानीय Gateway या किसी अन्य इंस्टॉलेशन से कनेक्ट है, जिसका स्वामी ऐप नहीं है। बटन
  Mac ऐप को बदलने के बजाय उस Gateway का सामान्य अपडेट प्रवाह चलाता है।

समन्वित अपडेट विफल होने पर वह पुनः प्रयास,
[अपडेट गाइड](/hi/install/updating) और Discord क्रियाओं वाली अपनी सेटअप-शैली विंडो में बना रहता है। स्वचालित मरम्मत कभी भी
किसी नए Gateway को डाउनग्रेड नहीं करती या `extended-stable` चैनल पिन को ओवरराइड नहीं करती।

सफल अपडेट के बाद ऐप सबसे हाल में किसी व्यक्ति द्वारा उपयोग किया गया,
शीर्ष-स्तरीय प्रत्यक्ष सत्र खोजता है और उस एजेंट को एक बार का अपडेट इवेंट देता है। Heartbeat
और Cron गतिविधि इस चयन को प्रभावित नहीं करती। इसके बाद एजेंट उस वार्तालाप से आपका फिर स्वागत कर सकता है,
जिसका उपयोग करने की संभावना सबसे अधिक थी। रिमोट मोड में ऐप
केवल स्थानीय Mac Node रनटाइम को अपडेट करता है और रिमोट Gateway के ऐप से पुराना होने पर
सूचना छोड़ देता है।

Sparkle, Gateway की `update.channel` सेटिंग का पालन करता है। `beta` और `dev`
बीटा ऐप बिल्ड चुनते हैं; `stable`, `extended-stable`, और अनुपस्थित या अज्ञात मान
स्थिर ऐप बिल्ड पर बने रहते हैं।

## डैशबोर्ड लिंक खोलें

macOS ऐप के एम्बेडेड डैशबोर्ड में, किसी बाहरी वेब लिंक पर क्लिक करने से वह डैशबोर्ड नेविगेशन को दृश्यमान रखते हुए विंडो की आधी चौड़ाई वाले आकार-बदलने योग्य ब्राउज़र साइडबार में खुलता है। दूसरी चौड़ाई चुनने के लिए विभाजक को खींचें; ऐप इसे याद रखता है। प्रत्येक लिंक अपने अलग टैब में खुलता है, कई पृष्ठ खुले होने पर टैब पट्टी दिखाई देती है, और उसी लिंक पर दोबारा क्लिक करने से उसके मौजूदा टैब का पुनः उपयोग होता है। टैब का क्रम बदलने के लिए उन्हें खींचें, टैब बंद करें बटन या मध्य-क्लिक से उन्हें बंद करें, और **Open in Default Browser**, **Copy Link**, **Reload**, **Close Tab**, तथा **Close Other Tabs** के लिए किसी टैब पर दायाँ-क्लिक करें। विंडो के शीर्षक-पट्टी के पीछे/आगे नियंत्रण और ट्रैकपैड स्वाइप डैशबोर्ड इतिहास में नेविगेट करते हैं; साइडबार के अपने पीछे/आगे नियंत्रण सक्रिय टैब के इतिहास में नेविगेट करते हैं। साइडबार में पुनः लोड करने, डिफ़ॉल्ट ब्राउज़र में खोलने और बंद करने के नियंत्रण भी हैं।

शीर्षक-पट्टी के नियंत्रण ऐप साइडबार के अनुसार बदलते हैं: इसके विस्तृत होने पर पीछे/आगे नियंत्रण साइडबार टॉगल के पास उसके दाएँ किनारे पर रहते हैं; इसके संकुचित होने पर वे खोज बटन (जो कमांड पैलेट खोलता है) और नया-सत्र बटन के लिए जगह बनाते हैं।

**Open in Sidebar**, **Open in Default Browser**, या **Copy Link** चुनने के लिए किसी बाहरी लिंक पर दायाँ-क्लिक करें। डैशबोर्ड से संशोधक कुंजी वाले क्लिक और उपयोगकर्ता द्वारा सक्रिय किए गए नई-विंडो लिंक डिफ़ॉल्ट ब्राउज़र में ही खुलते रहते हैं; साइडबार के भीतर नई-विंडो लिंक नए साइडबार टैब के रूप में खुलते हैं। सामान्य ब्राउज़र-होस्टेड Control UI पृष्ठ ब्राउज़र के सामान्य लिंक और संदर्भ-मेन्यू व्यवहार को बनाए रखते हैं।

## ब्राउज़र लॉगिन आयात करें

जब ऐप किसी स्थानीय Gateway के साथ चल रहा हो और ब्राउज़र साइडबार पहली बार खुले, तो Mac पर कुकीज़ वाली Chrome-परिवार की प्रोफ़ाइल मौजूद होने पर डैशबोर्ड एक हटाया जा सकने वाला बैनर दिखाता है। बैनर उन कुकीज़ को एक पृथक प्रबंधित प्रोफ़ाइल में कॉपी करने की सुविधा देता है, जिसका उपयोग एजेंट ब्राउज़िंग के लिए करते हैं। इसके **Import** नियंत्रण से कोई प्रोफ़ाइल चुनें (Touch ID की आवश्यकता हो सकती है); प्रगति और आयातित कुकी की संख्या उसी स्थान पर दिखाई देती है, और केवल कुकीज़ कॉपी की जाती हैं — पासवर्ड स्रोत ब्राउज़र से कभी बाहर नहीं जाते। बैनर हटाने पर यह चुनाव दर्ज हो जाता है; **Settings → General → Browser login → Import…** इसे किसी भी समय फिर उपलब्ध कराता है। अंतर्निहित आयात प्रवाह और `browser.allowSystemProfileImport` गेट के लिए [ब्राउज़र](/hi/cli/browser) देखें।

## Gateway मोड चुनें

| मोड   | इसका उपयोग तब करें जब                                                                    | विवरण पृष्ठ                                        |
| ------ | ------------------------------------------------------------------------------ | -------------------------------------------------- |
| स्थानीय  | इस Mac को Gateway चलाना चाहिए और launchd से उसे सक्रिय रखना चाहिए।                | [macOS पर Gateway](/hi/platforms/mac/bundled-gateway) |
| रिमोट | कोई अन्य होस्ट Gateway चलाता है; यह Mac उसे SSH, LAN, या Tailnet पर नियंत्रित करता है। | [रिमोट नियंत्रण](/hi/platforms/mac/remote)            |

दोनों मोड के लिए स्थापित `openclaw` CLI आवश्यक है, क्योंकि ऐप उसके node-host
रनटाइम का पुनः उपयोग करता है। नए Mac पर ऐप मेल खाता CLI स्वतः इंस्टॉल करता है; इसके बाद स्थानीय
मोड Gateway विज़ार्ड शुरू करता है, जबकि रिमोट मोड दूसरा स्थानीय Gateway शुरू किए बिना चयनित
Gateway से कनेक्ट होता है।
मैन्युअल पुनर्प्राप्ति के लिए [macOS पर Gateway](/hi/platforms/mac/bundled-gateway) देखें।

## ऐप किन चीज़ों का स्वामी है

- मेन्यू बार स्थिति, सूचनाएँ, स्वास्थ्य, WebChat और फ़्लोटिंग Quick Chat बार।
- स्क्रीन, माइक्रोफ़ोन, वाक्, ऑटोमेशन और अभिगम्यता के लिए macOS अनुमति संकेत।
- एक Mac node, जो नेटिव Canvas, कैमरा/स्क्रीन कैप्चर, सूचनाओं,
  स्थान और कंप्यूटर नियंत्रण को CLI node होस्ट के सिस्टम, ब्राउज़र,
  plugin, skill और MCP कमांड के साथ संयोजित करता है।
- Mac पर होस्ट किए गए कमांड के लिए Exec अनुमोदन संकेत।
- अनुमोदित शेल कमांड के लिए ऐप-संदर्भ निष्पादन, जो ऐप की macOS
  अनुमति विशेषता को बनाए रखता है, जबकि CLI रनटाइम साझा node नीति का स्वामी होता है।
- रिमोट-मोड SSH टनल या सीधे Gateway कनेक्शन।

एम्बेडेड Control UI में, **Settings → Notifications** ब्राउज़र पुश के बजाय ऐप की नेटिव
सूचना अनुमति दिखाता है, क्योंकि ऐप सूचनाएँ नेटिव रूप से वितरित करता है।

ऐप Gateway या सामान्य CLI दस्तावेज़ों का स्थान **नहीं** लेता। Gateway
कॉन्फ़िगरेशन, प्रदाता, plugins, चैनल, टूल और सुरक्षा के अपने
अलग दस्तावेज़ हैं।
