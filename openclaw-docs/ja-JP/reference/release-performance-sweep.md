このページでは、2026年5月に実施したOpenClawのパフォーマンス、
パッケージサイズ、依存関係、shrinkwrapのクリーンアップを裏付ける証拠をまとめています。公開ブログ記事の
技術的な補足資料です。

ここでは、2つの監査を組み合わせています。

- **リリースパフォーマンス調査:** `v2026.5.28`から
  安定版`v2026.4.23`まで遡ったGitHub Releasesを、`OpenClaw Performance`ワークフローの
  `profile=smoke`、モックプロバイダーレーンを使用して調査しました。ほとんどのタグ行は1サンプルです。
  `v2026.5.27`と`v2026.5.28`の行では、最新の3回反復リリースブランチ
  アーティファクトを使用しています。
- **4月前半のコンテキスト:** `v2026.4.1`から`v2026.5.2`までの
  公開済み`clawgrit-reports`モックプロバイダー
  ベースラインです。壊れていた4月後半のリリースを公開パフォーマンスのベースラインとして扱わないためにのみ使用します。
- **インストールフットプリント調査:** 一時パッケージへ
  `npm install --ignore-scripts`を新規インストールし、サイズには`du -sk node_modules`、
  パッケージインスタンス数には`node_modules`による走査を使用しました。
- **npmパッケージサイズ調査:** 公開済みリリースに対して
  `npm pack openclaw@<version> --dry-run --json`を実行し、圧縮tarballサイズ、展開後サイズ、
  ファイル数を記録しました。

<Warning>
メインのパフォーマンス調査ではタグごとに1つのスモークサンプルを使用していますが、
`v2026.5.27`と`v2026.5.28`の行では、最新の3回反復
リリースブランチアーティファクトを使用しています。4月前半のコンテキストでは、
`clawgrit-reports`の公開済み3回反復中央値を使用しています。これらの数値はリリースゲートの統計値ではなく、
傾向を示す証拠およびリグレッション調査のシグナルとして扱ってください。
</Warning>

### Shrinkwrap の境界

`2026.5.20` は、ルート shrinkwrap も大規模なネストされた OpenClaw
依存関係ツリーもない状態でリリースされました。`2026.5.22` ではルート shrinkwrap が導入され、ネストされた
`openclaw/node_modules` 配下に911.8MBがインストールされました。`2026.5.28` は shrinkwrap を維持し、
ネストされた `openclaw/node_modules` 配下に引き続き259.7MiBをインストールしますが、ローカルの新規インストール監査では
`@napi-rs/canvas` パッケージがインストールされなくなりました。

公開された tarball の検査により、この境界が確認されています。

| バージョン     | 安定版として公開済みか | ルート `npm-shrinkwrap.json` | 備考                                 |
| ----------- | ----------------- | -------------------------- | ------------------------------------- |
| `2026.5.20` | はい               | いいえ                         | shrinkwrap 導入前の最後の安定版リリース |
| `2026.5.21` | いいえ                | 該当なし                        | npm の安定版リリースなし                 |
| `2026.5.22` | はい               | はい                        | shrinkwrap を導入                 |
| `2026.5.23` | いいえ                | 該当なし                        | npm の安定版リリースなし                 |
| `2026.5.24` | いいえ                | 該当なし                        | npm の安定版リリースなし                 |
| `2026.5.25` | いいえ                | 該当なし                        | npm の安定版リリースなし                 |
| `2026.5.26` | はい               | はい                        | ネストされた依存関係ツリーが引き続き存在  |
| `2026.5.27` | はい               | はい                        | ネストされた依存関係ツリーが引き続き存在  |
| `2026.5.28` | はい               | はい                        | ネストされた依存関係ツリーが大幅に縮小   |

重要な違いは、**shrinkwrap 自体が問題なのではない**という点です。
`v2026.5.28` も引き続きルート shrinkwrap を同梱しています。問題だったのは、npm に大規模なネストされた OpenClaw
依存関係ツリーと全12個の `@napi-rs/canvas` プラットフォームパッケージを実体化させるパッケージ構成でした。
`v2026.5.28` ではネストされたツリーが縮小し、Canvas プラットフォームのファンアウトもローカル監査には
現れなくなりました。

shrinkwrap の平易な説明とメンテナーレベルのパッケージチェックについては、[npm shrinkwrap](/ja-JP/gateway/security/shrinkwrap)を参照してください。

## サプライチェーン上の解釈

依存関係数は、インストールサイズの指標であるだけでなく、運用上のセキュリティ指標でもあります。
パッケージが増えるたびに、運用者が信頼しなければならないメンテナー、tarball、推移的更新、
オプションのネイティブバイナリ、インストール時の動作の範囲が広がります。

クリーンアップの方針は次のとおりです。

- 重量級およびオプションの機能をデフォルトのコアインストールから除外する
- Plugin パッケージが自身のランタイム依存関係グラフを所有するようにする
- Gateway 起動時にランタイムパッケージマネージャーによる修復を行わない
- 全プラットフォーム向けネイティブパッケージの実体化を引き起こすことなく、
  決定論的なインストールを維持する
- パッケージの受け入れおよび測定パスではインストールスクリプトを無効のままにする
- 公開前に、ネストされた依存関係ツリーとネイティブのオプション依存関係の急増を
  検出する
