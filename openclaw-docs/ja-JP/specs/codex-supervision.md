# Codex の監督

## 目的

Codex の監督により、OpenClaw オペレーターはネイティブ Codex セッションを検出し、
安全な場合は通常の OpenClaw Chat 画面からローカルブランチを作成できます。
Codex App Server は引き続きスレッドとモデルループを所有します。OpenClaw は
フリートカタログ、認証済みオペレーター UI、セッションのバインド、チャンネル配信を提供します。

この機能は公式 `codex` Plugin に属します。独立した
Supervisor Plugin や、2 つ目の Codex プロトコル実装はありません。

## 製品境界

ネイティブセッションの検出が次の設定で明示的に無効化されていない限り、
Codex Plugin が有効になるとカタログが登録されます。

```text
plugins.entries.codex.config.sessionCatalog.enabled = false
```

エージェント向け監督ツールを有効にするには、次を設定します。

```text
plugins.entries.codex.config.supervision.enabled = true
```

現在有効な初期製品の範囲は、長期的なフリート計画よりも意図的に限定されています。

- アーカイブされていない Codex スレッドのみを一覧表示します。
- ローカルおよびオプトイン済みのペアリング Node の行を、安定したホスト ID ごとにグループ化します。
- 保存済みまたはアイドル状態の Gateway ローカルスレッドから、通常のモデルロック済み Chat ブランチを
  作成し、最初のターンで完全な Codex ハーネススレッドを開始するか、以前のブランチ用に
  作成された Chat を開きます。
- 他のランナーが存在しないことを明示的に確認した後にのみ、
  保存済みまたはアイドル状態の Gateway ローカルスレッドをアーカイブします。
- アクティブなローカルソースには新規ブランチまたはアーカイブのコントロールを表示せず、
  既存の監督対象 Chat は引き続き開けるようにします。
- メインサイドバーにはホストごとの最新行を表示し、セッションページには完全なカタログを保持し、
  ローカル行およびペアリング Node の行に対して、上限付きのカーソルページネーションによるトランスクリプト読み取りを提供します。
- カタログ障害をホスト単位で分離します。

カタログは、アーカイブされていない項目の集合です。その中の行は、
アイドル、アクティブ、`notLoaded`、またはエラーのターン状態である場合があります。

エージェント向け監督は引き続きオプトインです。ガイド付きオンボーディングでは、
ネイティブ Codex のインストール検出に成功し、選択した推論バックエンドがライブチェックに合格すると、
ユーザーが選択するプライマリバックエンドに関係なく、監督機能のインストールと有効化を試みます。
監督機能は、その日和見的な Plugin セットアップが成功した場合にのみ有効になります。
明示的に無効化された Plugin、ポリシーによるブロック、または
`supervision.enabled: false` は監督ツールに対して引き続き優先されますが、
オペレーターのセッションカタログは無効化しません。`sessionCatalog.enabled: false` は
オペレーターによる検出とペアリング Node のカタログコマンドを無効化しますが、Codex
プロバイダーとハーネスは引き続き有効です。

## 所有権

`codex` Plugin は Codex App Server のすべての動作を所有します。

- エンドポイントの検出と接続ライフサイクル
- プロトコルの初期化とバージョンチェック
- スレッドの一覧表示、読み取り、再開、アーカイブ、イベント処理
- 承認およびユーザー入力のブリッジ
- ネイティブスレッドと OpenClaw セッションのバインド
- 継続後の Codex 専用モデルとハーネスの強制

Control UI と Gateway は、その Plugin が所有するサービスを利用します。Codex の
ロールアウトファイルを直接読み取ることも、別の App Server クライアントを実装することもありません。

デフォルトのローカルトポロジーは次のとおりです。

```text
Codex Desktop -> プライベート stdio App Server -> ユーザーの Codex ホーム
                                             ^
OpenClaw Codex Plugin -> 監督用 App Server 接続
  （デフォルトは管理対象のユーザーホーム stdio。明示的な appServer 設定が優先される）
  -> パッシブなソースカタログと読み取り
  -> スナップショット固定 -> 正規 appServer ソースブランチ
  -> 表示履歴の注入と、それ以降の監督対象 Chat のすべてのターン

通常の OpenClaw Codex セッション -> デフォルトでは管理対象のエージェントホーム stdio
  -> 通常の完全なハーネススレッド -> OpenClaw Chat とチャンネル配信
```

監督を有効化しても、通常の Codex ハーネスは変更されず、デフォルトでは
エージェントスコープのままです。独立した監督接続は、デフォルトで
管理対象のユーザーホーム stdio を使用するため、そのカタログとスナップショット操作では
ネイティブの保存済みスレッドが表示されます。明示的な `appServer` 接続設定は優先されます。
`homeScope` が未設定の場合、監督接続では stdio または Unix に対して
`"user"`、WebSocket に対して `"agent"` に解決されます。
通常のハーネスでもネイティブ Codex ホームを共有する必要がある場合にのみ、
`appServer.homeScope: "user"` を明示的に設定してください。Codex サイドバーグループから引き継がれた Chat は例外です。
そのプライベートな監督バインドにより、ソースの読み取り、正規ブランチの作成、および後続のターンは
監督接続上に維持されます。ライブ状態と所有権はプロセスローカルのままです。
OpenClaw の監督プロセスが認識していないスレッドは、Codex Desktop がアクティブに実行している場合でも
`notLoaded` です。

Codex には、インストーラーが管理する独立したブートストラップ契約を持つ、
実験的な正規ローカルデーモンがあります。この機能は、そのデーモンを暗黙に
ブートストラップ、要求、または前提としてはなりません。

## カタログフロー

汎用 Gateway メソッド `sessions.catalog.list` は `codex`
カタログプロバイダーにディスパッチします。このプロバイダーは常に `archived: false` を要求し、
App Server に対話型ソースのデフォルトである `cli`、`vscode`、Atlas、ChatGPT を
適用させます。次の結果を統合します。

1. 監督用 App Server から取得した Gateway ローカルの `thread/list` 結果。
   デフォルトでは管理対象のユーザーホーム stdio を使用します。
2. 接続済みでオプトインしている各 Node からの `codex.appServer.threads.list.v1` 結果。

トランスクリプトの選択では、ローカルでは `itemsView: "full"` を指定した
`thread/turns/list` を使用し、選択した Node ではバージョン付きの
`codex.appServer.thread.turns.list.v1` コマンドを使用します。各レスポンスには最大 20 件の
永続化済みターンと、不透明な前方／後方カーソルが含まれます。Control UI は
新しい順のページを要求し、各ページを時系列順にレンダリングして、古いページを先頭に追加します。
上限のない `thread/read` にフォールバックすることはありません。また OpenClaw は、
シリアライズされた項目ページが 20 MiB を超える場合、Node または Gateway の
トランスポートを通過する前に拒否します。

ネイティブ macOS のペアリング Node 実装では、未設定／デフォルトまたは明示的な
`appServer.transport: "stdio"` のみがサポートされ、監督スコープは未設定／デフォルトまたは
明示的な `appServer.homeScope: "user"` のみがサポートされます。設定済みの `command`、
`args`、正規化済みの `clearEnv` を子プロセスに引き渡します。
`"unix"`、`"websocket"`、または明示的な `homeScope: "agent"` を使用する場合、
カタログ機能もコマンドも公開せず、直接呼び出してもフェイルクローズします。
エージェントスコープの設定でユーザーの Codex ホームを公開したり、明示的なエンドポイントの代わりに
ローカル stdio を使用したりしてはなりません。

カタログのプロジェクションでは、識別子、タイトル、cwd、状態、アクティブ待機フラグ、
タイムスタンプ、ソース、モデルプロバイダー、Codex バージョン、Git ブランチを正規化します。
トランスクリプトのプレビュー、ターン、ロールアウトパス、Codex ホームパス、
Git リモート、コミット SHA、生のエンドポイント、生の App Server エラーは返しません。
トランスクリプトのレスポンスには、明示的に要求された App Server の項目ページと、
その不透明なカーソルのみが含まれます。

ホスト障害は各ホストの結果内に限定されます。オフラインの Node や利用できない
ローカル App Server があっても、正常なホストはページから削除されません。接続状態は
スレッド状態ではなくホストのプロパティです。失敗したホスト結果には新しいセッション行が含まれず、
ネイティブスレッドに `offline` を投影することもありません。

Control UI は段階的なカタログ更新を要求します。各ローカルホストまたはペアリングホストは、
自身の App Server の一覧取得が完了した時点で表示されます。集約レスポンスは、
互換性および復旧用のスナップショットとして残ります。表示中のページは、接続状態の変更後、
フォーカス時、および最大 30 秒ごとに整合され、変更後にはより高速な処理が実行されます。
そのため、別のクライアントで作成されたネイティブ Codex セッションは、
OpenClaw ストレージにインポートしなくても最終的に検出されます。

カタログ検出はパッシブです。メタデータの一覧表示または読み取り時に、
`thread/resume` を呼び出したり、OpenClaw クライアントをライブスレッド要求に
サブスクライブしたり、承認に応答したりしてはなりません。

検索対象はタイトルのみで、大文字と小文字は区別されません。返される各カタログページについて、
Gateway とペアリング済み Mac はクエリを App Server に渡さず、上限付きの数のネイティブページを
走査します。これは、ネイティブ検索ではトランスクリプトのプレビューも一致する可能性があるためです。
返されたネイティブカーソルを使用して、呼び出し元は走査を継続できます。

## オペレーター CLI の境界

Plugin は、Gateway を利用する 3 つのシェルコマンドを登録します。

```text
openclaw codex sessions [--search <text>] [--host <id>] [--limit <count>] [--cursor <cursor>] [--json] [gateway-options]
openclaw codex continue <thread-id> [--json] [gateway-options]
openclaw codex archive <thread-id> --confirm-no-other-runner [--json] [gateway-options]
```

`[gateway-options]` は `--url <url>`、`--token <token>`、`--timeout <ms>`、
および継承された `--expect-final` スイッチです。セッション一覧のデフォルトは 75,000 ms、
continue と archive のデフォルトは 30,000 ms です。
`--expect-final` は、これらの単項 RPC に追加の効果を与えません。セッション検索は
タイトルのみを対象とし、大文字と小文字を区別しません。各レスポンスは上限付きのネイティブページチェーンを
走査し、`--cursor` でより古い結果に進みます。上限のデフォルトはホストごとに 50 で、
1 から 100 まで指定できます。また、カーソルには安定した 1 つの `--host`
宛先が必要です。どのコマンドも、アーカイブ済み項目を含めるオプションを受け付けません。
ペアリングホストを対象にできるのは `sessions` のみです。
`continue` と `archive` は常に `hostId: "gateway:local"` を送信し、
archive には明示的な確認フラグが必要です。

シェル名前空間は、Chat 内の `/codex` ランタイム名前空間とは異なります。
具体的には、`/codex sessions --host <node>` は 1 つの Node 上の Codex CLI セッションファイルを一覧表示し、
`/codex threads` は現在の会話接続の App Server スレッドを一覧表示し、
`/codex resume` または `/codex bind` はその会話のバインドを変更します。
これらのコマンドは `sessions.catalog.continue` の代わりにはならず、
`/codex continue` または `/codex archive` というランタイムコマンドもありません。

## ローカルでの継続

保存済みまたはアイドル状態の Gateway ローカル行について、UI はホスト ID とスレッド ID に加えて
`catalogId: "codex"` を指定し、`sessions.catalog.continue` を呼び出します。Plugin は次を行います。

1. ソースに監督対象 Chat がすでに存在する場合、それを再利用します。
2. 存在しない場合は、ソースの最後の終端済み永続化ターン
   （完了、中断、または失敗）までの上限付きユーザー／アシスタント履歴を新しい
   OpenClaw Chat に投影し、保留中のハーネスブランチを記録します。
3. 具体的なモデルやプロバイダーの選択ではなく、保留中の Codex 専用モデルロックポリシーと、
   プライベートな監督接続スコープを保存し、OpenClaw `sessionKey` を返します。

履歴プロジェクションでは、表示可能なユーザーおよびアシスタントメッセージの最新末尾部分を選択し、
メッセージ数は最大 200 件、UTF-8 テキストの合計は 512 KiB、1 メッセージあたりは
64 KiB という厳格な上限を適用します。画像およびローカル画像の入力を
`[Image attachment]` に置き換え、画像ペイロードやパスは決してコピーせず、
推論、ツール呼び出し、ツール結果は省略します。

UI は、そのセッションキーを使用して通常の Chat に移動します。この時点では、
正規ハーネススレッドはまだ存在しません。最初の通常 Chat ターンで、ハーネスは実際の
Codex の承認、引き出し、イベント、配信ハンドラーをインストールし、次を実行します。

1. 監督接続を使用し、モデルまたはプロバイダーを上書きせずにネイティブ
   `thread/fork` を呼び出して、永続化されたソーススナップショットを固定します。
   Codex の現在の `ConfigManager` 状態がモデルとプロバイダーを選択し、
   フォークレスポンスが実際の組み合わせを報告します。モデルがソースに最後に記録されたモデルと異なる場合、
   Codex は通常のモデル差異警告を出力します。
2. 同じ接続上で、`threadSource: "appServer"`、OpenClaw の cwd、ポリシー、設定、環境、
   OpenClaw ハーネスの完全なツールサーフェス、およびこの初回起動用にフォークから返された
   モデルとプロバイダーを正確に使用して、正規の完全な Codex ハーネススレッドを開始します。
3. その接続を通じて上限付きの表示可能なユーザー／アシスタント履歴を注入し、
   監督スコープを削除せずに正規バインドをコミットし、ターンを実行して、一時フォークをアーカイブします。

最初のターンの前では、Chat は履歴ミラーが表示されたロック済みの保留ブランチです。その後は、すべてのモデルターンが監督接続上の正規 Codex ハーネススレッドを通じて実行されます。このブランチは完全なネイティブロールアウトのクローンではありません。ソースの推論、ツール呼び出し、ツール結果は意図的に省略されます。スナップショットの固定または正規スレッドの作成に失敗した場合、保留ブランチは再試行可能な状態を維持します。バインドの競合、無効化された監督、または利用不能もしくは不一致の監督接続がある場合、通常のエージェントホームハーネスへフォールバックせず、ターンの実行前にフェイルクローズします。

これにより保証されるのは Codex が所有する選択であり、ソースの過去のモデルの保持ではありません。フォークから返されたペアが正規スレッドの開始に使用され、Codex はそのスレッドのネイティブモデルとプロバイダーを永続化します。以降の再開では OpenClaw のモデルとプロバイダーのオーバーライドが省略されるため、Codex は永続化されたペアを復元します。別のネイティブ Codex コントロールが正規スレッドを変更した場合、OpenClaw はそのネイティブに永続化された選択を受け入れます。外側の OpenClaw モデルとフォールバックチェーンがそれを代替することはありません。

監督対象のモデルロック済み Chat では、モデル変更、セッション削除、セッションのリセット／新規操作はフェイルクローズします。`/codex model <model>`、`/codex
bind`、`/codex resume`（Node `--bind here` を含む）、および `/codex detach` または
`/codex unbind` の変更も、バインドを置換またはクリアするためフェイルクローズします。
`/codex model` クエリと `/codex fast`、`/codex permissions`、`/codex
threads` は引き続き利用できます。`codex_threads` エージェントツールは、新しいフォークをアタッチしたり、バインドされたネイティブスレッドをアーカイブしたりできません。リストとメタデータのみの読み取りは引き続き利用できます。トランスクリプトフィールドには `supervision.allowRawTranscripts` が必要であり、名前変更、アーカイブ解除、デタッチされたフォーク、および無関係なスレッドのアーカイブには `supervision.allowWriteControls` が必要です。どちらのオプションもロックされたバインドを置換できません。
OpenClaw エントリを削除またはリセットすると、本来はネイティブバインドが破棄され、Codex に見えるセッションの背後で汎用スレッドが作成または許可されることになります。そのため、保持メンテナンスでは、通常の経過時間、件数、またはディスク予算の上限を超えていても、モデルロック済みエントリを保持します。所有 Plugin を無効化またはアンインストールしても、ロックと Plugin 所有権マーカーは保持されます。同じ Plugin が再び有効化されるまで Chat は利用不能なままフェイルクローズし、クリーンアップによって通常のモデルセッションへ変換されることはありません。

この操作によってソースが再開または変更されることはありません。一時フォークはスナップショットを固定しますが、永続的な継続スレッドではありません。最初のターンで別個の正規ハーネススレッドを開始することで、プロセスローカルなステータスが Desktop 所有のターンを検出できなかったという理由だけで、OpenClaw が競合するソースライターになることを防ぎます。表示される履歴ミラーと固定されたスナップショットでは、アクティブなソースでまだ完了していない作業が省略される場合があります。元の CLI、VS Code、Atlas、または ChatGPT ソースは、ネイティブカタログと OpenClaw カタログの両方で引き続き対象となります。正規ブランチは監督ストア内でネイティブ Codex スレッドのままですが、ネイティブクライアントがその `appServer` ソース種別をフィルタリングする場合があるため、Codex Desktop での可視性は契約ではありません。

## アーカイブの動作

保存済みまたはアイドル状態の Gateway ローカル行では、`catalogId: "codex"` を指定した `sessions.catalog.archive` に明示的な `confirmNoOtherRunner: true` が必要です。現在のプロセスローカルステータスを新たに読み取り、`idle` または `notLoaded` の場合にのみ続行し、ネイティブ `thread/archive` を呼び出して、Codex が操作を受け入れた後にのみ成功を返します。その後、その行は未アーカイブカタログから除外されます。

新たな読み取りでアクティブまたはエラーのステータスが返された場合、アーカイブは拒否されます。ソースからの初期化中または保留中の監督対象ブランチも同様です。ソースをアーカイブする前に、最初の Chat ターンで正規ブランチを実体化する必要があります。正確な対象について既知のアクティブな OpenClaw バインド所有者が存在する場合、またはアーカイブされていない生成済み子孫が存在する場合も、アーカイブは拒否されます。OpenClaw は Codex の実験的な `thread/list ancestorThreadId` 関係をページネーションし、リクエストまたはレスポンスのエラー、カーソルまたはスレッドの循環、安全上限の枯渇が発生した場合はフェイルクローズします。ネイティブアーカイブは読み込み済みの親および子孫の作業を停止できるため、アーカイブは割り込みの代替手段ではありません。読み取り、子孫の列挙、アーカイブの呼び出しはアトミックではありません。独立したクライアントが、ローカルではアイドルまたは `notLoaded` に見える行を引き続き所有したり、その行で作業を開始したりする可能性があります。Codex に条件付きアーカイブまたはプロセス間リースが実装されるまでは、他のランナーが存在しないことの確認によって、不明なクライアントとその競合をカバーします。ペアリングされた Node のアーカイブは禁止されています。

Codex カタログにはアーカイブ済みビューがありません。別の所有者認可済み Codex サーフェスで `thread/unarchive` によって復元されたスレッドは、再び未アーカイブカタログの対象になります。

## アクティブスレッドの安全性

Codex は、1 つの App Server のクライアント間でスレッドに対する変更を直列化しますが、排他的なプロセス間ランナーまたは承認所有者リースは公開しません。独立した stdio App Server は同じロールアウトに追記でき、それぞれが自身のインメモリステータスのみを認識します。また、承認リクエストは 1 つのサーバーのすべてのサブスクライバーに届く可能性があり、最初の有効なレスポンスによってリクエストが完了します。

したがって、次のようになります。

- 受動的なカタログクライアントは、承認をサブスクライブしたり自動拒否したりしません
- 現在アクティブと報告されている行では、新しいブランチもアーカイブも公開されません
- マッピングされていないソースは、正規ハーネススレッドがソースを決して再開しない、表示履歴付きブランチになります
- `notLoaded` はアクティビティ不明として表示され、他のランナーが存在しないことを十分に理解したうえで確認した後にのみアーカイブできます
- ローカルアーカイブには、その確認に加えて新たな `idle` または `notLoaded` の読み取りが必要であり、読み取りとアーカイブの間にあるプロトコル上の競合も考慮する必要があります

割り込みとマルチクライアント間の引き継ぎは、将来の製品判断事項です。アクティブな行を表示することによって暗黙に提供されるものではありません。

## ペアリングされた Node の境界

Node invoke は現在、リクエスト／レスポンス方式のみです。境界のあるカタログメタデータとトランスクリプトのターンページは安全に返せますが、Codex ハーネスの実行に必要な長時間存続するイベントストリーム、承認リクエスト、ツール呼び出し、キャンセル、アシスタントの差分を伝送できません。

そのため、Node 契約はリストとトランスクリプトのターンページをサポートします。リモート行は引き続き読み取り可能ですが、アイドル状態に関係なく **続行** と **アーカイブ** は利用できません。実際のリモート継続には、ローカルハーネスと同じ承認およびバインドの不変条件を維持する Node 側ランナーとストリーミングブリッジが必要です。

## 権限

各コンピューターはローカルでオプトインします。Gateway を有効化しても、別の Node に Codex メタデータの読み取りを許可することにはなりません。Node ケイパビリティは、通常のペアリングおよびコマンドポリシーの承認を通過する必要があります。

フリートの一覧表示とトランスクリプトの表示では、ペアリングされた Node を呼び出すため `operator.write` Gateway スコープを使用します。ローカルの継続とアーカイブは認証済みオペレーターの操作であり、引き続きホストとステータスのチェック対象です。

自律エージェントおよびスタンドアロン MCP のアクセスは別です。出荷済みの `codex_endpoint_probe`、`codex_sessions_list`、`codex_session_read`、`codex_session_send`、`codex_session_interrupt` ツール契約は、引き続き `codex` Plugin が所有します。監督が有効な場合、生の `codex_threads` トランスクリプト読み取りとトランスクリプトから派生するリストフィールドにも `supervision.allowRawTranscripts` が必要です。すべての `codex_threads` のフォーク、名前変更、アーカイブ、アーカイブ解除には `supervision.allowWriteControls` が必要です。どちらのポリシーもデフォルトでは無効です。

## 互換性

`openclaw doctor --fix` は、エンドポイントとトランスクリプト／書き込みポリシー、および Plugin の許可／拒否参照を含む、出荷済みの `plugins.entries.codex-supervisor` 設定を `plugins.entries.codex.config.supervision` に移行します。競合する場合は、明示された正規の移行先値が優先されます。移行後、ランタイムコードは正規の `codex` Plugin 形式のみを使用します。

公式 Plugin は、Supervisor 互換ツールを正確に 5 つ保持します。`codex_endpoint_probe`、`codex_sessions_list`、`codex_session_read`、`codex_session_send`、`codex_session_interrupt` です。セッションリストはデフォルトで読み込み済みのもののみを対象とし、`loaded_only` パラメーターはありません。`include_stored: true` は、エンドポイントごとに `max_stored_sessions`（デフォルト 200、許容範囲 1～1,000）で制限された未アーカイブの状態データベース行を追加します。読み込み済みの行はこの設定による上限の対象外です。トランスクリプトから派生するフィールドと読み取りには引き続き `allowRawTranscripts` による制限が適用され、送信と割り込みには引き続き `allowWriteControls` による制限が適用されます。

互換送信によってアイドルスレッドが開始または再開されることはありません。`mode: "start"` は常に拒否されます。`"auto"` と `"steer"` は、読み取り可能なアクティブターンのみを制御します。割り込みにも、読み取り可能なアクティブターンが必要です。アイドル状態からの継続はネイティブ Codex カタログへルーティングされ、完全なハーネスが承認、ツール、バインドを所有します。スタンドアロンのレガシー MCP アダプターは、公式 Plugin からこれらと同じツールを解決し、保持されたレガシーポリシー環境変数に従う唯一の経路です。

7 月のカタログ UI、Gateway メソッド、Node ケイパビリティ、CLI 登録は、旧 Plugin ID では出荷されていませんでした。これらは 2 つ目のランタイムファサードを介さず、直接 `codex` の所有へ移行します。

## 受け入れテスト

- 監督を有効にすると、アーカイブされていないローカルセッションが一覧表示されます。
- アーカイブ済みセッションは、カタログレスポンスにも UI にも表示されません。
- 別のホストで障害が発生しても、正常なホストは引き続き表示されます。利用できないホストは、
  オフラインのセッションステータスを捏造するのではなく、新しい行を返しません。
- 保存済みまたはアイドル状態のローカル行から、Codex 専用の
  モデル／ランタイムロックを持つ Chat ミラーが作成されます。最初のターンで一時スナップショットが固定され、
  正規の完全なハーネススレッドが開始されます。Continue を再度実行すると、既存の Chat が開きます。
- 最初のターンでは、スナップショットのフォーク時にモデル／プロバイダーのオーバーライドが省略され、
  Codex が現在のモデルとソースに最後に記録されたモデルが異なると警告した場合でも、
  正規の開始時点には Codex が返した正確なペアが固定されます。
- 保留中およびコミット済みの監督対象バインディングでは、ソースへのアクセス、
  正規ブランチの作成、および以降のすべてのターンに監督接続が使用されます。通常の
  Codex セッションは引き続きエージェント単位です。
- 以降の再開では、OpenClaw のモデル／プロバイダーのオーバーライドを省略し、Codex が
  正規に永続化した選択を維持し、そのスレッドに対する個別のネイティブ変更を受け入れます。
  外側の OpenClaw モデルやフォールバックチェーンに置き換えることはありません。
- 監督を無効にした場合、またはバインディング／接続のライフサイクルが失われた場合、
  Chat を通常のエージェントホームのハーネスへ移動せず、フェイルクローズします。
- 監督対象でモデルがロックされた Chat は、ネイティブバインディングを保護している間は
  削除できません。
- Chat がミラーリングするユーザーおよびアシスタントのメッセージは最大 200 件、合計 512 KiB、
  メッセージごとに 64 KiB です。画像はプレースホルダーになります。ソースの推論、ツール呼び出し、
  ツール結果、画像ペイロード、ローカルパスは複製されません。
- ブランチフローがソーススレッドを再開することはありません。
- 元のソースは、両方のカタログの対象であり続けます。正規のネイティブ
  ブランチは `appServer` ソース種別を使用し、Codex Desktop に表示される保証はありません。
- アクティブなローカルソースからはブランチを作成できず、アーカイブもできません。既存の
  監督対象 Chat は引き続き開くことができます。
- アクティビティ不明の行は確認なしでブランチを作成できます。アーカイブには、
  他のランナーが存在しないことの明示的な確認が必要です。
- 初期化中または保留中の監督対象ブランチを持つソースは、最初の Chat ターンで
  正規ブランチが実体化されるまでアーカイブできません。
- 対象と完全に一致する既知のアクティブなバインディング所有者、またはアーカイブされていない生成済みの
  子孫が存在する場合、アーカイブはブロックされます。子孫の列挙に失敗した場合はフェイルクローズし、
  不明なクライアントおよびステータス確認からアーカイブまでの競合については、
  引き続き明示的な確認が責任を持ちます。
- 確認済みの保存済みまたはアイドル状態のローカルアーカイブでは、ネイティブ側で成功した後に行が削除されます。
- ペアリング済み Node の行は、Continue または Archive なしでも引き続き表示されます。
- 受動的な一覧表示では、スレッドの承認を購読したり応答したりすることはありません。
- 従来の Supervisor 設定は、正規の Codex 設定形式に移行されます。
- 従来の一覧はデフォルトで読み込み専用です。保存済み項目の列挙はエンドポイントごとの
  上限に従い、互換送信によってアイドル状態のスレッドが開始または再開されることはありません。
