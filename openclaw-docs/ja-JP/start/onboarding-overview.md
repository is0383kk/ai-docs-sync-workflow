OpenClaw には、ターミナルと macOS アプリのオンボーディングがあります。どちらも最初に推論を確立します。
既存の AI アクセスを検出し、実際の補完を必須としたうえで、その後にのみ
OpenClaw を起動して残りのセットアップを構成します。到達可能で構成済みの Gateway で、
デフォルトエージェントにモデルがすでに構成されている場合は、オンボーディングをスキップして
通常のエージェント UI を開きます。ターミナルのフローでは、詳細なセットアップ向けに
完全な従来型ウィザードも利用できます。

## どの方法を使用すべきですか？

|                    | CLI オンボーディング                         | macOS アプリのオンボーディング       |
| ------------------ | -------------------------------------------- | ------------------------------------ |
| **プラットフォーム** | macOS、Linux、Windows（ネイティブまたは WSL2） | macOS のみ                           |
| **インターフェース** | 推論のセットアップ後、OpenClaw                | 推論のセットアップ後、OpenClaw       |
| **最適な用途**       | サーバー、ヘッドレス環境、完全な制御           | デスクトップ Mac、視覚的なセットアップ |
| **自動化**           | スクリプト用の `--non-interactive`             | 手動のみ                             |
| **コマンド**         | `openclaw onboard`                            | アプリを起動                         |

ほとんどのユーザーには、**CLI オンボーディング**から始めることを推奨します。あらゆる環境で動作し、
最も柔軟に制御できます。

## オンボーディングで構成される内容

ガイド付き推論フェーズで確立されるのは、次の項目のみです。

1. **モデルプロバイダーと認証** — 検出されたアクセス、または検証済みのプロバイダーへのサインイン、
   API キー、トークン
2. **検証済みの推論** — デフォルトエージェントの実効モデルによる
   実際の補完

この補完に成功すると、OpenClaw でワークスペース、Gateway、
Gateway サービス、チャンネル、エージェント、プラグイン、その他のオプション機能を構成できます。

従来型 CLI ウィザードでは、さらに次の項目を構成できます。

1. **チャンネル**（任意）— Discord、Feishu、Google Chat、iMessage、Mattermost、Microsoft Teams、
   Telegram、WhatsApp などの組み込みおよび同梱チャットチャンネル
2. **高度な Gateway 制御** — リモートモード、ネットワーク設定、デーモンの選択

## CLI オンボーディング

任意のターミナルで実行します。

```bash
openclaw onboard
```

ガイド付きフローでは、既存の AI アクセスを検出し、候補を順番に実際にテストして、
失敗した場合は次の候補に進みます。検出候補をすべて試しても見つからない場合、まず OpenAI、
Anthropic、xAI（Grok）、Google、OpenRouter が表示されます。**More…** には、
残りのプロバイダーがプロバイダーグループ別にまとめられており、2 番目のメニューで地域、プラン、対応する
ブラウザ、デバイス、API キー、トークンの各方式を選択できます。補完に成功した後にのみモデル
と認証情報を保存し、その後 OpenClaw を起動して
ワークスペース、Gateway、チャンネル、エージェント、プラグイン、その他のオプション機能を
構成します。**Skip for now** を選択すると、OpenClaw を起動せずに終了します。
フロー内で従来型ウィザードに切り替えることはできません。代わりに従来型ウィザードを使用する場合は、終了して
`openclaw onboard --classic` を実行してください。

推論に成功すると、OpenClaw はチャンネルのセットアップを入力がマスクされたターミナル
ウィザードに引き継げます。ガイド付きまたは従来型のプロバイダーセットアップは開きません。モデルプロバイダーや
その認証を変更するには、OpenClaw を終了して
`openclaw onboard` を実行してください。

モデルと認証、チャンネル、Skills、
リモート Gateway、インポートを詳細にセットアップするには、`openclaw onboard --classic` を使用します。`--install-daemon` を追加すると、
従来型フローも選択され、バックグラウンドサービスが 1 ステップでインストールされます。対話形式で推論以外のセットアップと修復を行うには、`openclaw
openclaw` を使用します。`openclaw
onboard --modern` は、同じ実推論
ゲートを使用する互換性エイリアスです。

完全なリファレンス：[オンボーディング（CLI）](/ja-JP/start/wizard)
CLI コマンドのドキュメント：[`openclaw onboard`](/ja-JP/cli/onboard)

## macOS アプリのオンボーディング

OpenClaw アプリを開きます。構成済みのローカルまたはリモート Gateway に到達可能で、
デフォルトエージェントにモデルがすでに構成されている場合、アプリはオンボーディング
と OpenClaw をスキップし、通常のエージェント UI をすぐに開きます。

新規または設定が不完全な Gateway では、初回起動フローが既存の AI
アクセス（Claude Code、Codex、API キー）を検出し、最適な
選択肢を実際にテストして、実際の応答を確認した後にのみ保存します。失敗した場合は自動的に次の候補へ進み、
何も見つからない場合は検証付きの手動 API キー入力ステップを提示します。機密性の高い
認証情報にはマスク入力を使用します。推論に成功すると、OpenClaw が起動し、
残りの構成を支援します。

Gemini CLI はセットアップ後も通常のエージェントで使用できますが、
ツールを使用しないプローブを強制できないため、この推論ゲートでは提示されません。

完全なリファレンス：[オンボーディング（macOS アプリ）](/ja-JP/start/onboarding)

## カスタムまたは一覧にないプロバイダー

プロバイダーが一覧にない場合は、`openclaw onboard --classic` を実行して
**Custom Provider** を選択し、次の情報を入力します。

- エンドポイントの互換性：OpenAI 互換（`/chat/completions`）、OpenAI Responses 互換（`/responses`）、Anthropic 互換（`/messages`）、または不明（3 つすべてをプローブして自動検出）
- ベース URL と API キー（エンドポイントで不要な場合、API キーは任意）
- モデル ID と任意のモデルエイリアス

複数のカスタムエンドポイントを共存させることができ、それぞれに固有のエンドポイント ID が割り当てられます。
