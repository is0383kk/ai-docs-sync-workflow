`/steer` は、まずすでにアクティブな実行へガイダンスを送信しようとします。これは、
「この実行がまだ動作している間に調整する」場合に使用します。現在のランタイムが
ステアリングを受け付けられない場合、OpenClaw はメッセージを破棄せず、
代わりに通常のプロンプトとして送信します。

## 現在のセッション

現在のセッションでアクティブな実行を対象にするには、トップレベルの `/steer` を使用します。

```text
/steer より小さいパッチを優先し、テストの焦点を絞ってください
/tell 次のツール呼び出しを行う前に要約してください
```

動作:

- 現在のセッションでアクティブな実行のみを対象にします。
- セッションの `/queue` モードとは独立して動作します。
- セッションがアイドル状態の場合、またはアクティブな実行がステアリングを受け付けられない場合は、
  同じメッセージで通常のターンを開始します。
- アクティブなランタイムのステアリング経路を使用するため、モデルは
  次にサポートされるランタイム境界でガイダンスを確認します。

## ステアリングとキューの比較

`/queue steer` を使用すると、実行がアクティブな間に到着した通常の受信メッセージは、
アクティブな実行をステアリングしようとします。`/steer <message>` は、保存されている
`/queue` 設定に関係なく、次にサポートされるランタイム境界で、そのコマンドの
メッセージをアクティブな実行へ注入しようとする明示的なコマンドです。この注入を利用できない場合は、
コマンドのプレフィックスが取り除かれ、`<message>` が通常のプロンプトとして続行されます。

明示的な `/steer`（および `/tell`）コマンドは Gateway を基盤としています。
`openclaw chat` または `openclaw tui --local` では、`/queue steer` を選択し、
ガイダンスを通常のメッセージとして送信してください。組み込みランタイムは、Gateway コマンドを
転送せずに同じステアリングポリシーを適用します。

用途:

- `/steer <message>` は、アクティブな実行を今すぐ誘導する場合に使用します。
- `/queue steer` は、今後の通常のメッセージで、デフォルトでアクティブな実行を
  ステアリングする場合に使用します。
- `/queue collect` または `/queue followup` は、今後の通常のメッセージを、
  アクティブな実行のステアリングに使用せず、後続のターンまで待機させる場合に使用します。
- `/queue interrupt` は、最新のメッセージでアクティブな実行をステアリングするのではなく、
  置き換える場合に使用します。

キューモードとステアリング境界については、[コマンドキュー](/ja-JP/concepts/queue)および
[ステアリングキュー](/ja-JP/concepts/queue-steering)を参照してください。

## サブエージェント

トップレベルの `/steer` は、現在のセッションでアクティブな実行を対象にします。サブエージェントは
親または依頼元のセッションへ報告します。`/subagents` は表示のみを目的としています。

## ACP セッション

対象が ACP ハーネスセッションの場合は、`/acp steer` を使用します。

```text
/acp steer --session agent:main:acp:codex 再現手順を絞り込んでください
```

ACP セッションの選択とランタイムの動作については、[ACP エージェント](/ja-JP/tools/acp-agents)を
参照してください。
